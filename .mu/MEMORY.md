# Development notes

## 2026-09-07 — First demo and scaffold

User confirmed that spatial objects are relative to anchors, and that the draft should be cached in browser-local datastores. The proposed stack was React + TypeScript + Vite with Tiptap/ProseMirror for rich text; implemented as a single-document browser application, without a backend.

The initial demo combines semantic paragraphs/phrases, a central theme, explicit vertical spacers, and anchored rich-text boxes. Main and floating text share the same semantic schema and theme. Native rich-text paste is constrained by the schema; no arbitrary inline CSS is retained.

V0 uses stable main-block UUIDs and floating-object anchor IDs plus document-pixel offsets and width. Anchor geometry is derived after layout and never persisted. If an anchor is deleted, retain its boxes and reanchor to the nearest surviving predecessor (or first remaining block). User confirmed this deletion behavior on 2026-09-07.

IndexedDB holds one current draft, including theme and spatial data. Writes are local document persistence, intentionally distinct from HTTP caching, which is disabled. Browser storage is not guaranteed durable and is not a backup. No cloud, import/export, document library, or migrations. Multi-tab editing is not coordinated yet.

Mobile means a viewport below 768px in this demo and forces reading mode. Reading scales the fixed-width page as a unit to retain the spatial composition. Desktop defaults to editing; document width starts at 800px. Width changes preserve offsets and do not automatically rearrange boxes. These responsive/width policies are implementation defaults to discuss further.

Undo/redo is per text editor (including main-text spacers); a unified document-wide history for theme/spatial changes is deferred. Reset and floating-box deletion ask for confirmation. Dependencies are locked with npm; no Git repository has been initialized.

## 2026-09-08 — A zoom detent at actual size

Incremental zoom (wheel/trackpad, pinch, header +/−, keyboard +/−) snaps to exactly 100% when its target is 95–105%. Wheel gestures accumulate their unsnapped scale, restarting after a 250ms pause, so continued small deltas can move past the detent rather than getting trapped at 100%. Pinch keeps its existing gesture-start reference for the same reason. Explicit presets, reading-mode Fit, and Ctrl/⌘ 0 remain exact and bypass snapping so a near-100% fitted page never becomes too wide.

## 2026-09-08 — Border-only floating controls and resizable main-text segments

User requested removal of floating delete buttons and corner resize handles: top/left/bottom borders now move each object, while the entire right border resizes its width. Images no longer move when dragged through their interior; clicking inside only selects them. Direct text/table editing remains unchanged. Keyboard movement and confirmed Delete/Backspace on a focused object remain available; the right border itself is focusable for keyboard width adjustment. No discrete resize glyph or delete control is rendered. This supersedes the prior image-content dragging and selected-object button behavior.

A main-text segment is a continuous paragraph run between spaces, not an individual paragraph. One horizontal border is shared by each pair of adjacent sections. Dragging it resizes the section above and moves all subsequent content in the normal flow, rather than redistributing a fixed total height between neighbors. Spaces keep their existing 24px floor. Text starts automatic; a dragged height larger than natural content becomes a saved minimum. Content can shrink without losing that reserved room. Once natural content meets/exceeds the minimum (within 0.1 document pixels), or the user drags back to content height, clear the minimum so later shrinking is automatic again. Theme/page-width reflow also counts as natural content growth. Border Up/Down and Home provide keyboard resizing/reset, and reading/mobile views have no interaction overlays.

Keep the flat main editor schema and existing anchor UUIDs. The leading segment's `minSegmentHeight` belongs to the editor document node; later segment minimums belong to their preceding spacer, alongside that spacer's separate `height`. This ownership avoids losing a minimum when a segment's first paragraph is deleted or replaced. Inserting a space starts a new automatic trailing segment; deleting a space joins runs under the earlier minimum, releasing it if combined content already reaches it. Nonexistent/empty runs clear unused minimums. The minimum includes normal paragraph spacing. Extra room is rendered as measured padding on the run's last paragraph, not as a fixed content height.

Drag previews are ProseMirror decorations and never persist intermediate document mutations. Commit once on release as an isolated editor-history step; Escape, pointer cancellation, mode changes, and zoom changes cancel previews. Automatic minimum release is saved without adding a separate undo event. Spacer previews use a distinct CSS variable from stored spacer height: smoke testing caught that overriding/removing the same inline height property could otherwise erase the rendered height on commit. Main-anchor measurement observes individual blocks as well as the whole text; minimap snapshots retain layout padding but omit all border controls.

Smoke checks passed for each floating object's four borders, image-interior selection, keyboard width/deletion controls, text and space dragging at 75%/150%, clamp-to-content, rounding tolerance, growth/release/subsequent shrink, paragraph insertion/deletion, same-size paragraph replacement, consecutive spaces and segment joins, Escape cancellation, undo/redo, no-op clicks, reload persistence, width reflow, minimap cleanup, and reading/mobile layouts. Layout decoration state is invalidated on document changes because replacing a paragraph can discard its decoration even if positions and desired padding remain identical. Settled layouts were checked for zero repeating transactions. Empty paragraphs still count as a text run and retain minimums; only runs with no paragraphs discard their unused minimum.

Built and deployed. Live desktop has seven shared section boundaries, five floating objects without buttons, persisted text minimums/spacer heights, and working right-border keyboard resizing. ## 2026-09-08 — Floating repulsion design discussion (not implemented)

User wants per-object Overlap / Repel behavior. Repellers affect only main-text lines; floating text, images, and tables are opaque rectangular obstacles and never repel one another. Each main-text line retains only its leftmost usable interval: wrap before the leftmost intersecting repeller and never continue in free space to its right. Front-to-back stacking is independent of this text-flow behavior.

User chose absolute document-space x and nonnegative anchor-relative y, superseding the current text-margin-relative x and unrestricted y design. Before the first main block, use a document-top origin, represented either by a null anchor or a virtual top anchor; representation remains to be finalized. User favors automatic reanchoring when moving objects. Proposed interaction: derive attachment from placement on explicit movement, preserve visual position when changing anchors, and retain attachment during ordinary text/theme reflow. Preserve the anchor block's logical top while repulsion changes its internal line layout and height. Forward-only exclusions avoid backward layout dependencies; any above-object gap must also respect the anchor boundary. Implementation and remaining defaults are still under discussion.

Future work requested by user: snapping during floating-object placement, especially alignment/snapping between floating objects. Record for later design; do not include snapping in the initial repulsion implementation.

Implemented the initial repulsion slice. Floating geometry now uses absolute document-space x, nonnegative anchor-relative y, and nullable document-top anchors. New and example objects explicitly default to Overlap; the inspector can switch any selected object to Repel. Repellers use transient paragraph-local CSS exclusion proxies and native line breaking; they affect the anchored block and following main text, never floating objects, and preserve the anchored block's top. Dragging keeps the object under the pointer and automatically commits a new anchor plus offset based on final document placement. Repulsion previews remain transient and do not release saved segment minimums. Production build and live deployment completed with no-store responses; native wrapping, document-top reanchoring, inspector control, existing draft loading, and no idle transaction loop were browser-checked.


## 2026-09-08 — Live document configuration and shared undo

User chose a fixed semantic vocabulary for now (Title, Heading, Body, Caption; Emphasis and Term), a right-side configuration panel, and immediate undoable edits rather than an Apply/Cancel preview. The Document header button opens Layout/Theme tabs in place of the selection inspector; selecting content does not close or retarget it. Edit class style opens the current paragraph/phrase class. View preferences have their own header entry, remain browser-local, and never enter document history. Mobile stays reading-only.

Layout has continuous page width (800px default, 320–2400px) and left/right main-text margins (55px default). Linking is a panel convenience, initially enabled for equal margins; enabling it aligns the right margin to the left, bounded to retain 120px of main text. At least 120px remains usable at every width. Top/bottom padding remains fixed. Margins and width reflow main text but do not rewrite floating objects’ absolute x or saved attachments.

Theme Defaults provide a single inheritance baseline rather than class-to-class inheritance. Paragraph classes store partial overrides for typeface, size, weight, color, line height, letter spacing, and before/after spacing. Defaults also own page background. Phrase overrides cover text color, transparent-or-colored background, weight, italic, and decoration; absent phrase typography follows the surrounding paragraph, not Body or Defaults directly. Tables continue to use Body exclusively. Each override can reset to inheritance; resetting a class clears all its overrides in one undo step. Existing browser drafts retain their content and explicit styles when the new baseline/margins are filled in.

A single chronological, session-local history replaces editor-local ProseMirror history. It covers text/class application, table structure, segment/spacer sizes, theme/layout, and floating-object content/geometry/creation/deletion/image changes. Up to 100 document snapshots share unchanged data; images are not cloned or serialized for each history comparison. Continuous typing groups within 750ms and breaks on selection/focus changes. Numeric input focus sessions and color-adjustment sessions group until the control is left; released border drags commit once. Native undo remains available inside text/numeric settings fields; toolbar Undo/Redo or shortcuts outside those inputs operate on the document. View changes are excluded. Reload and confirmed Reset to example clear history.

Layout normalization (especially automatic minimum-height release) folds into the triggering document change and does not clear redo. Undo restores both the configuration and affected segment minimums. Snapshot synchronization must restore root document attributes as well as child content: Tiptap setContent alone does not restore the leading segment’s minimum. Editor selections are restored without stealing focus; removing a selected object through undo returns the inspector to main text. There is no transient configuration preview and no separate commit operation.
