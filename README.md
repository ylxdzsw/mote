# Mote

[![CI](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml/badge.svg)](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml)

A local-first demo exploring semantic text and anchor-relative spatial placement.

## Run

Use Node.js 22.12+ (or a current release) and npm.

```sh
npm install
npm run dev
```

Open the URL printed by Vite, normally `http://localhost:5173` (it selects the next port if occupied). The development server listens on all interfaces for previews; do not expose it as a production server. Keep the same origin between sessions to access the same local draft.

```sh
npm run check   # TypeScript
npm run build   # TypeScript + production bundle in dist/
npm run preview
```

## First working slice

- One V0 document, initially an example with text-and-space sections, text notes, an image, a table, connected shapes, attached labels, a KaTeX sampler, and two ECharts widgets. The small **Reset to example** button in the editing top bar loads the current demo after confirmation; existing browser drafts are not replaced automatically.
- **File** exports PNG, standalone HTML, or a compressed **.mote** document. The HTML reader works offline except for online resources referenced by HTML widgets. Exports use the current in-memory document, even when saving locally fails. Desktop writers can import `.mote` files after confirming replacement; readers and mobile can export without writing the draft. See [Document files](#document-files).
- Selectable semantic paragraph classes (`title`, `heading`, `body`, `caption`, `code`, `list`), an automatic table-only `table` class, and phrase classes (`primary`, `secondary`, `bold`, `term`). Primary and Secondary use distinct green and blue emphasis colors; Bold only overrides weight by default. Ctrl/⌘B toggles Bold in main text, floating text, and tables, but not Code. Bold HTML paste maps to this same semantic class. No direct selection styling.
- The editing toolbar has three persistent menus: current paragraph class, current inline class, and **+** for all insertable elements. Wider screens add Heading/List/Code, Bold/Primary/Secondary/Term, and Text box/Image/Rectangle/Line shortcuts. Paragraph shortcuts toggle back to Body; inline shortcuts toggle back to Plain. A mixed selection receives the chosen class throughout; menu choices always apply explicitly. Menus show icons or theme samples, support arrow keys/Home/End/type-ahead, and close with Escape or an outside click. List indentation commands are in the paragraph menu as well as on Tab/Shift+Tab. Shortcuts disappear in fixed width tiers, with Bold retained longest; 768–849px shows just the three menus and Undo/Redo. Table and Label have fixed paragraph indicators and disabled paragraph shortcuts; Code disables inline controls. Armed drawing tools highlight both **+** and their shortcut.
- A **Document** button opens a live right-side panel with Layout and Theme tabs, replacing the selection inspector while open. The inspector heading names the selected item type (Main text or the selected floating-object kind), rather than repeating it in the toolbar. Its bottom **Edit style** section has separate paragraph and inline style buttons labeled for their target class (for example, **Heading style…** or **Bold style…**); they open the current paragraph class (Table in tables) or inline class (Primary for plain text) without changing the selection. There is no style-edit button in the toolbar. Selecting text does not switch or close the theme panel. **View** keeps browser-local preferences separate.
- Theme Defaults define base typography, text color, spacing, and page background. The fixed Title/Heading/Body/Caption/Code/List/Table and Primary/Secondary/Bold/Term classes can override their applicable properties, with inherited indicators, per-property resets, a class reset, and a small sample. Paragraphs support typeface, size, weight, color, line height, letter spacing, and spacing before/after. Font size and lengths offer **em** and **px**; line height also offers **×** the paragraph's font size. Every em is relative to the **Defaults font size**, not the local paragraph size. That baseline remains in pixels (initially 16px, with a default line height of 1.5em); preset class sizes, line heights, letter spacing, and paragraph spacing use em. Switching units preserves the current rendered length. Phrases support color, optional highlight, weight, italic, and decoration; unspecified properties follow surrounding text. Styles are shared by main text, floating text, Table-class cell text, and the minimap. No direct selection styling or custom classes.
- **Code** is a plain-text paragraph/block with a monospace default and preserved whitespace. Enter and Shift+Enter insert a newline within the block, Tab inserts two spaces, and Ctrl/⌘Enter inserts a Body paragraph after it. Backspace at the block start returns it to Body. Code strips phrase marks and pastes plain text; line breaks survive changing the class back to Body. Code typography is controlled centrally by its theme class.
- **List** is an independent unordered-list item, not a child of a list container. Enter splits it into a new same-level item, including when the item is empty. Shift+Enter adds a line aligned with the item's text start. Tab / Shift+Tab or the toolbar arrows indent/outdent selected items independently, without changing neighboring items. Backspace at the start reduces one level; at the top level it returns the item to Body without deleting its text. Each level adds 24px indentation, never a font-size change. Top-level markers are solid dots; all sublevels use hollow dots. Pasted unordered lists flatten into independent paragraphs; ordered-list paste becomes Body text. Code and List work in main and floating text, while tables always use Table.
- Borderless, unselectable vertical spaces live at paragraph breaks. Hold **Alt** near a break and drag down to open a gap. Alt-drag anywhere in an unoccupied space, or on the first text line immediately below it, to resize it: down adds room, up removes it. The top stays fixed and following content moves. Gaps below **12 document pixels** are removed on release; normal theme paragraph spacing remains. Adjacent spaces merge, including after intervening text is deleted, preserving total height and floating-object offsets. Text always sizes naturally; there are no reserved/minimum text-segment heights. A small Alt-only margin cue identifies insertion points, and a transient size/removal hint appears during dragging. There are no segment borders, spacer selection states, or spacer inspector controls.
- Rich-text floating boxes anchored to main-text blocks. Drag the **top, left, or bottom border to move**, and the **right border to resize**; click inside to edit text. There are no delete buttons, corner resize handles, or anchor markers. Focused objects move with arrow keys (Shift for 1px); their right borders support left/right arrows for width. Press Delete/Backspace with the outer object focused to remove it after confirmation.
- Floating images share the same anchor, drag, resize, and delete behavior. Choose a local PNG, JPEG, WebP, GIF, or AVIF (up to 10 MB); images are embedded in the browser-local draft, never uploaded. Resizing preserves proportions. Select an image to edit its accessible description or replace its file in the sidebar.
- Floating tables are directly editable: click a cell, use Tab / Shift+Tab to navigate, and add/remove rows or columns through the sidebar. Every cell uses the global **Table** paragraph class, independent of Body but with the same preset. Table is available in the theme editor and through **Table style…**, never in the normal paragraph-class dropdown; the toolbar shows a fixed Table label inside cells. **Primary**, **Secondary**, **Bold**, and **Term** phrase classes remain available. Each cell contains exactly one paragraph: Enter, Shift+Enter, and Ctrl/⌘Enter insert soft newlines, not paragraph spacing. Pasted paragraphs/headings flatten to newlines while preserving text and inline classes. Pasted table/spreadsheet ranges still fill separate cells. Tables support cell selection, rich-text paste, and document-wide undo/redo for text and row/column changes. The last row and column cannot be removed through the sidebar; delete the floating object to remove the entire table.
- Rectangles, ellipses, lines, and labels are regular floating-object kinds, sharing anchoring, movement, selection, marquee selection, grid snapping, ordering, persistence, undo, zoom, and minimap behavior with text, images, and tables. Rectangles can be square or rounded; ellipses can be circles; both have per-object fill/stroke colors, width, and Solid/Dashed outlines. Lines can be straight or simple elbow routes, have per-object stroke settings, arrows at either end, draggable endpoints, and optional connections to floating objects. Default strokes follow the Defaults font color; shape fill defaults to None. Labels are single-paragraph rich text using the fixed Label class, never wrap automatically, and can attach to object center/top/bottom or to line center/left/right/above/below positions. Double-clicking an attachable object selects or creates its label; labels can be detached and remain independently movable. Enter finishes label editing and Shift+Enter inserts a soft break.
- A **page-wide 16px dot grid**, with one origin at the document’s top-left, appears only while dragging or resizing floating objects, including creation and table-column resizing. Objects snap to that same grid in both text and space areas; Alt bypasses snapping but not page bounds. Resizing or merging spaces never moves the grid origin. Selection, text editing, hover, marquee selection, reading mode, and the minimap do not show it. Dragging unoccupied space or either side gutter between the page and the surrounding chrome starts rectangular marquee selection for any floating kind; Shift adds. Transparent shape interiors are click-through, while filled shapes and images can be moved from their interiors. Marquee and group movement preserve relative positions, and attached line endpoints/labels follow their targets.
- **Table columns** resize by dragging internal dividers, adjusting only the two adjacent columns while preserving total table width. The outer right border resizes the whole table proportionally. Dividers support Left/Right arrows (Shift for 1px), a 40px minimum where space permits, and Escape cancellation; zoom/mode changes cancel an active drag. Drag previews are transient and each release is one undo step. **Left / Center / Right** in the inspector aligns the entire column containing the caret, or all columns intersecting a rectangular selection. Mixed alignment leaves all three buttons inactive. New columns start left-aligned with an equal-share weight; adding/removing columns preserves the relative widths of surviving columns. New rows follow existing column alignment.
- Configurable document width (320–2400px, initially 800px) and left/right main-text margins (initially 48px). Margins can be linked or edited independently and always leave at least 120px for text. The page remains continuous with fixed top padding and no automatic bottom padding, minimum page height, or branding footer. Its bottom follows the last main-text block or lowest floating object; explicit spaces are retained. Changes are immediate and locally saved, with no Apply/Cancel stage.
- One chronological undo/redo history covers text across editors, semantic-class application, table structure, layout/theme changes, space insertion/resizing/removal, and floating-object creation/deletion/geometry/image changes. Numeric-field focus sessions, color adjustments, and continuous typing are grouped; each released layout drag is one step. Toolbar Undo/Redo and Ctrl/⌘Z / Ctrl/⌘Shift+Z (also Ctrl/⌘Y) work across editor focus and panel closing. Text/numeric settings inputs keep native input undo. History keeps up to 100 steps in memory and is cleared on reload or confirmed Reset to example; saved documents do not contain history.
- A live minimap on the left of the canvas shows text, semantic colors, whitespace, and floating boxes. Click a region to navigate or drag the shaded viewport to scrub vertically; horizontal position and editor selection are preserved. Wheel scrolling and keyboard arrows, Page Up/Down, Home/End work over the minimap. There is no hover popup. Native canvas scrollbars are hidden; wheel, touch, and trackpad scrolling remain available.
- Small main-text heading bookmarks sit to the right of the minimap in a 64px overlay (44px on mobile when explicitly shown), with 9px text. Labels take no horizontal layout space and can overlap the centered document; gaps between labels let clicks through. Floating notes remain visible in the miniature but do not contribute bookmarks. The current heading changes at a focus line 15% down the canvas viewport, capped at 120px; clicking a label aligns its heading to that line without changing horizontal position or text selection. Labels follow live edits and the miniature's scroll position; nearby labels spread out to stay readable. A very dense bookmark overlay can scroll independently over its labels. Full heading text is available in each label's tooltip and accessible name.
- Global settings under **View** offer faithful-proportion (default) and fit-whole-document minimap sizing, plus automatic/show/hide visibility. Automatic hides at viewport widths of 1050px and below, including mobile. Reading mode exposes these settings through **View**. Preferences live in browser-local storage, separately from the V0 document.
- Fixed app frame with independently scrolling document canvas and settings. Zoom controls live in the top bar between save status and the mode selector. Click the current percentage to select 25%, 50%, 75%, 100%, 125%, 150%, 200%, or 300% (plus Fit in reading mode). Zoom only the document using these controls, Ctrl/⌘ + wheel, pinch, or Ctrl/⌘ +/−; Ctrl/⌘ 0 resets the view. Incremental zoom snaps to 100% around actual size; continued zooming moves past it. Fit and explicit presets stay exact. Zoom is view state, not saved document geometry.
- Desktop editing/reading modes; viewports under 768px are reading-only. Entering reading mode fits the entire page width to preserve spatial relationships; document zoom remains available.
- A single browser-local draft in IndexedDB, written after each document update by the editing tab. With Web Locks available, other tabs read without saving and offer **Try editing**; acquiring ownership reloads the latest saved draft with fresh undo history. Without Web Locks, concurrent editing is silently allowed. Save errors are visible and retryable. Ctrl/⌘S is a no-op throughout editing and reading modes, including settings fields; it does not open the browser Save dialog or change the document.

Click a main-text block before inserting Space, Text box, Image, or Table through **+** or an available shortcut. **+ → Space** remains a keyboard-accessible alternative to Alt-dragging and adds to an existing gap at that paragraph break. Spaces span the page, including its text margins. Clicking one preserves the text caret rather than selecting the space. Ordinary dragging inside text still selects text; ordinary dragging inside a space or either side gutter selects floating objects. Object interactions take precedence over gap manipulation, and an object drag keeps its original meaning when Alt is pressed to bypass snapping. Floating text and tables share the main text’s inline semantic toolbar and theme.

## Model and boundaries

### Formulas and HTML widgets

**+ → KaTeX** inserts a floating display-mode formula. The inspector edits its LaTeX source live, without `$$` or `\[...\]` delimiters; syntax errors retain the source and appear on the object. Width is user-controlled and height follows content. Formulas are centered, never automatically wrapped or shrunk, and can use explicit constructs such as `aligned`. Oversized content follows the existing page-edge cropping policy. **Math style…** opens a global size/color style inherited from Defaults, with px/em units and normal history/reset behavior; math typefaces remain KaTeX's. KaTeX's unsafe HTML commands are disabled (`trust: false`). The renderer and WOFF2 math fonts are bundled for offline HTML and PNG. This is not a full LaTeX document engine, and inline mathematics is not included.

**+ → HTML widget** first asks for a screenshot, using the same embedded-image formats and 10MB limit as image objects. The new widget starts with an editable button-counter demo. **Edit code…** opens one HTML/CSS/JavaScript source field; source edits save immediately, while **Run / Restart** recreates the iframe and executes the current source. Each widget has its own DOM, CSS, globals, and libraries. Moving, resizing, selecting, changing mode, and front/back ordering retain its running state. Runtime interaction state is not saved or included in document undo; reopening starts from saved source.

HTML widgets have independent width/height controls and corner resizing. Their iframe viewport follows the saved dimensions, while page zoom scales the entire widget. In editing mode, click/drag the noninteractive interior to select/move it; **Interact** enables its controls and **Exit interaction** returns to object manipulation. Reading/mobile interiors are directly interactive. Each iframe uses `sandbox="allow-scripts"`, without access to Mote's DOM/storage or top-level navigation. This prevents namespace collisions and limits access, but is not a CPU/memory quota or a promise that arbitrary code cannot affect responsiveness.

Resource references, including CDN scripts and external data, are used as written. Mote does not inspect widget source, bundle or rewrite external resources, or guarantee offline operation for network-dependent demos. Normal browser resource restrictions still apply. There is no separate ECharts object or bundled chart library: authors can embed ECharts with their own script reference.

The example formula exercises aligned equations, fractions/roots, scripts, Greek letters, sums/binomial coefficients, integrals/derivatives, matrices, underbraces, cases, and vector notation. The two example widgets load pinned ECharts 6.0.0 from jsDelivr: **A week of attention** uses an `<attention-chart>` custom element with shadow DOM, a measure selector, legend filtering, tooltips, and bar-click details (also emitting `attention-select`); **Ideas in motion** animates a repeating six-pass bar ranking with value interpolation, Pause/Play, and Next pass. Reduced-motion preferences disable transitions and start the ranking paused. Their HTML sources and manually captured PNG previews live in `src/document/examples/`; no chart dependency is bundled. To refresh a preview, open its HTML at 690 × 400 and capture that viewport (the ranking preview shows paused pass 4).

The author-supplied screenshot is required and used for the minimap and PNG export, stretched to the object's saved rectangle. **Replace screenshot** updates it explicitly; authors should supply a matching aspect ratio and refresh it when needed. Mote does not capture widget HTML or verify that a screenshot matches the source/current state. Minimap snapshots remove live iframe content before insertion; PNG mounts a screenshot-only reader and never starts widget code. HTML exports keep live widgets, not screenshot substitutes. Both kinds share ordinary floating selection, anchoring, movement, grid, overlap/repel, labels, line connections, ordering, duplication/deletion, and document history.

### V0 representation

KaTeX objects store `kind: 'katex'` and `latex` alongside shared floating geometry. HTML widgets store `kind: 'html'`, `html`, embedded `screenshot`, accessible `alt`, and explicit `height`. Math overrides live in `theme.blocks.math`; omission means inherited size/color, without rewriting the draft. Native import checks these fields and screenshot safety, but intentionally does not sanitize executable widget source. The `.mote` file contains source and screenshots, never live iframe state or run counters.

`MoteDocument` contains a `version: 'V0'`, width, left/right margins, theme defaults and class overrides, main-text editor JSON, and floating objects. Each main-text block has a stable UUID. Each floating object stores an anchor UUID (or a document-top null anchor), absolute document-space x, nonnegative anchor-relative y, width, and Overlap/Repel text-flow behavior where applicable. Text/table objects store constrained rich-text content; images store an embedded source and accessible description; rectangles and ellipses store height, fill, stroke, stroke width, dash style, and rectangle corner style; lines store two anchor-relative endpoints, optional object connections, route, bend, arrowhead settings, and stroke settings; labels store constrained rich-text content and an optional attachment. A label is a single paragraph with fixed `label` semantics. Attached geometry is derived from current target layout, not saved as an absolute page position. An omitted kind denotes a text box. Tables have their own constrained schema: one table, exactly one paragraph per cell, no editable paragraph semantic attribute, and the shared inline semantic mark. The table node stores a `columns` array of `{ width, align }`, with normalized proportional widths and left/center/right alignment. An absent array means equal-width, left-aligned columns. Column commands update structure and metadata in one transaction; rectangular paste extends metadata when it grows the table. Rendering uses a colgroup and column-wide cell decorations, with noneditable divider controls excluded from the minimap. Images use their intrinsic aspect ratio; tables grow vertically with their cell content.

Code and List retain the flat `paragraph` node and stable block UUIDs. A list paragraph stores `semantic: 'list'` and a zero-based `listLevel`; there are no list containers, ownership relationships, or nested item nodes. Code stores `semantic: 'code'` and unmarked text/soft breaks, rendered as `pre > code`. These blocks participate in the existing anchor, repulsion, space-flow, minimap, persistence, and shared undo systems.

Each spacer stores a stable block UUID and a `height` in document pixels. Consecutive spacer nodes normalize to one, summing heights and transferring objects and line endpoints to the retained anchor with their offsets preserved. Text has no saved height or capacity reservation. The 12px removal threshold applies at gesture completion, not as a side effect of changing typography. Old V0 text-height reservations are no longer interpreted; V0 makes no layout-migration promise.

Gap previews use transient editor decorations; creation previews do not insert saved document nodes. Resizing an existing gap adds or removes room at the drag's starting position: floating objects and free line endpoints at or below that position move by the height change, while those above stay put. Later main-text anchors move normally, and attached labels/connected endpoints follow their targets without moving twice. Upward dragging can produce overlap, but anchor-relative offsets remain nonnegative. Mouse release commits once, even if Alt has already been released. Escape, pointer cancellation/capture loss, window blur, zoom/mode changes, and document replacement cancel a drag. Each completed gesture and any resulting merge form one document undo step. Normal paragraph margins are preserved rather than added twice when a gap separates them. Closing a space never resizes or deletes its floating objects; overlap with the following text remains possible.

When an anchor is deleted, its floating objects move to the closest surviving preceding block, or the document-top origin. Their content is retained. The shared history restores document snapshots and editor selections without stealing focus or undoing view preferences. Reset to example remains confirmed and clears history. Only the current V0 is supported: loading checks its identity and initializes content through the editor schemas, without historical upgrades or a general-purpose document validator. An editor parsing failure offers a confirmed reset to the example in the owning tab; declining leaves the saved draft untouched. Reading tabs cannot reset it.

Desktop tabs request an exclusive `mote-local-draft` Web Lock before loading for editing. The owning tab retains it through reading-mode switches and load retries, until it closes or reloads. A competing tab opens a read-only snapshot, without autosave or normalization writes. **Try editing** makes a non-waiting ownership request, then reloads from IndexedDB before enabling editing. There is no automatic takeover, live synchronization, or merging. Browsers without Web Locks retain ordinary editing and saving, including concurrent last-writer-wins writes. A fresh mobile view neither requests ownership nor writes a draft; after widening to desktop, **Try editing** can acquire ownership.

Storage-access failures show Retry, never a reset prompt. Failed database opens are retried rather than cached permanently. Save failures retain the in-memory document and offer Retry for its latest state; “Saved in this browser” appears only after the write transaction completes. Pending or failed saves retain the unload warning.

IndexedDB (`mote-local` → `drafts` → `current`) is origin-specific local storage, not a backup. Another browser, port, hostname, or device has a different draft. Clearing site data removes it, and browsers may evict it. Export `.mote` files to keep editable copies outside the browser. There is no cloud sync, multi-tab conflict resolution, or document library.

The floating layer deliberately permits overlap. Pointer and keyboard movement, duplication, and resizing stop at the document's horizontal edges; group movement preserves relative positions and accounts for attached labels. Changing document width does not rewrite saved offsets, and shrinking the page or growing unwrapped label text can still leave existing content outside its bounds. This demo does not yet have collision avoidance or a full spatial layout inspector.

## Document files

**File** opens a modal with three exports and, for desktop tabs with editing ownership, **Import .mote…**. All processing is local. Export takes a snapshot of the latest in-memory content, not the last IndexedDB save. It does not alter selection, history, mode, or zoom. Ctrl/⌘S retains its existing no-op behavior.

The **Filename** field supplies the export name, with the selected extension added automatically (an existing PNG/HTML/Mote extension is replaced, not duplicated). Where `showSaveFilePicker()` is available, export opens the browser's native Save As dialog with that suggested name and format filter. The picker is invoked directly from the click before export preparation; canceling does not generate or download a file. Bytes are written only after generation succeeds, and success is reported after the writable stream closes. Elsewhere, Mote uses an ordinary download with the chosen filename; browser preferences determine whether it prompts for a location. The filename is session-local UI state, not part of the document.

- **PNG:** one full-length image at one bitmap pixel per document CSS pixel, independent of display density, scroll position, and view zoom. It captures the shared reader at native size after images/fonts/layout settle, including the theme background, spaces, tables, labels, shapes, lines, and floating text. The page's horizontal edges crop overflowing content; the width never grows to accommodate objects. Fractional pixel extents round upward. No app chrome, page shadow, selection controls, or added bottom padding. Animated images become a still frame. The initial implementation caps height at 32,767px and area at 32 million pixels; smaller browser limits can also prevent export. It checks rasterization support and reports failures rather than silently shrinking/truncating the document. HTML and `.mote` remain alternatives. Scoped raster checks use Chromium; other engines' HTML-in-SVG raster support varies.
- **HTML:** a single file that opens directly from disk, with inline CSS/JavaScript and embedded document/images/math fonts. Mote content and self-contained widgets work offline; widgets referencing online resources still require them. It mounts the same `DocumentCanvas` through `ReadDocument`, sharing text schemas, theme styles, anchor/repulsion measurement, floating-object layout, fit/zoom, minimap, and heading navigation. The shell includes only reader controls and in-memory View preferences. The Mote reader itself does not access IndexedDB, localStorage, Web Locks, or a server; widget code runs separately in sandboxed iframes. The page and minimap crop horizontal overflow just like app reading mode; zoom still permits horizontal navigation within the page. Text stays selectable and searchable. JavaScript is required; ordinary system fonts remain system fonts, so typography can vary across devices and the shared layout recalculates accordingly. HTML is a published copy, not an import format.
- **Mote document (`.mote`):** binary gzip of UTF-8 JSON containing the existing `MoteDocument`, including `version: "V0"`, IDs, theme, geometry, rich text, and embedded assets. There is no archive manifest, custom binary header, encryption, or base64 wrapper around the file. Session history, selection, zoom, and browser preferences are excluded. Both compressed and decompressed data are capped at 128 MiB. Only the current V0 schema is supported; V0 does not promise compatibility with older builds. Ordinary gzip tools can inspect the JSON.

Import decompresses and checks the file before requesting replacement. External file checks cover its envelope, finite geometry, current field shapes, and safe embedded image/style values; rich-text content uses the same schema initialization as local drafts. No migration or repair layer is introduced. Corrupt gzip/UTF-8/JSON, unsupported versions, unsafe sources, schema failures, oversized files, and canceled replacement leave the existing draft untouched, without a reset-to-example prompt. Confirmed import remounts the editing session and clears undo history even if the document ID is unchanged, then uses ordinary local autosave and its visible retry behavior.

PDF export is deferred. PNG and HTML cannot be imported back.

## Structure

```text
src/app/        application shell, controls, responsive styles
src/document/   V0 data model, example, IndexedDB
src/editor/     constrained Tiptap schema and editor component
src/canvas/     anchor measurement, floating text interaction, zoom, minimap
src/theme/      shared semantic theme variables and controls
src/reader/     offline reader entry and single-file HTML export
```

The Vite configuration builds the offline reader as a production IIFE and stylesheet behind `virtual:mote-reader-bundle`. The HTML exporter embeds those build outputs; it has no handwritten alternate document renderer. Export codecs and the reader bundle load lazily from the main application. No export dependencies were added.

The minimap shares the rendered page through an inert, noneditable DOM snapshot, with editing controls and accessibility duplicates removed. Both sizing modes share this renderer and navigation geometry. Proportional mode keeps the page's aspect ratio and scrolls the miniature for long notes; fit mode compresses only the vertical axis as needed. Main-document zoom changes the viewport indicator, not miniature content scale. Scroll-only updates translate the existing snapshot and indicator; layout/content changes refresh the snapshot once per animation frame.

## Deployment

The current demo is live at **https://mote.ylxdzsw.com**. It is served as static files by Nginx from `/var/www/mote`, with the virtual host in `/etc/nginx/conf.d/mote.conf`. The existing wildcard Cloudflare Origin CA certificate covers the hostname. It is intentionally public and unauthenticated: there is no server API, session, account, or cloud document storage.

The deployment sets `Cache-Control: no-store` and disables Nginx ETags/expiration for HTML, JavaScript, CSS, and fallback responses. Cloudflare receives the origin directive and currently reports `DYNAMIC`/`BYPASS`, so the pre-release build is not cached at the edge. There is no service worker. Intentional IndexedDB document persistence is separate from HTTP caching. Future updates require `npm run build`, copying `dist/` to `/var/www/mote`, then `nginx -t && systemctl reload nginx`.

Vite development and preview responses also send `Cache-Control: no-store`. `public/_headers` carries the same rule for static hosts that support that format. Other hosts must explicitly set `Cache-Control: no-store` on **all** responses, including HTML and built assets.

Review the early-development decisions in `.mu/AGENTS.md` before a release.

## Verification

### Continuous integration

GitHub Actions runs on every push and pull request, and can be started manually from the **CI** workflow. On Ubuntu with Node.js 22 and 24, each job installs the lockfile with `npm ci` and runs `npm run build`, which includes TypeScript checking and production builds of both the app and offline reader. npm's download cache is reused; `node_modules` and build outputs are not cached. CI does not deploy the demo or run browser checks.

### Current document-file checks

Scoped Chromium checks cover gzip round-trips with empty image descriptions and preserved IDs, malformed/unsupported/oversized-file rejection, canceled replacement, fresh history on same-ID imports, and export of unsaved content during quota failure. Reader-tab exports do not write and cannot import. PNG checks cover byte-identical output at 100%/150% zoom, fixed-width overflow cropping, high-density displays, theme/margin changes, text repulsion, all floating kinds, cleanup, and explicit long-document limits. Offline `file://` checks compare native layout geometry against app reading mode and exercise heading navigation, zoom/horizontal scrolling, system-font layout, safe embedded text, and 390/320px mobile layouts while storage access is trapped and network access is disabled. No regression framework was added.

### Current local-draft checks

Scoped Chromium checks cover two-tab write exclusion, ownership retained in reading mode and through load retries, fresh content/history on handoff, reload persistence, transient database-open failure, aborted reads/writes, quota failure and latest-draft Retry, invalid editor-content reset acceptance/decline, and the silent no-Web-Locks fallback. Fresh mobile views remain read-only without acquiring a lock or saving. No regression framework or dependencies were added.

### Earlier implementation checks (historical)

These checks record earlier development slices, including interactions and draft formats that have since been replaced. The current behavior is described above.

The initial slice was checked with `npm run build` and scoped Chromium browser checks: paragraph/phrase classes, text undo, unique IDs on paragraph splitting, anchor-following after text reflow, spacer insertion/resizing/deletion, box insertion/dragging/keyboard resizing, shared theme updates, IndexedDB reload persistence, simulated save failure and retry, and reset.
