# Mote

[![CI](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml/badge.svg)](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml)

A private, AI-native document workspace combining semantic text with anchor-relative spatial placement. Documents live in the cloud, with independent local working copies and explicit conflict resolution. See [Cloud workspace](CLOUD.md) for saving, sharing, recovery, authentication, and operations.

## Run

Use Node.js 22.12+ (or a current release) and npm. For contributor invariants and a documentation map, see [.mu/AGENTS.md](.mu/AGENTS.md). Agent authors use [server/guide.md](server/guide.md); private-client/API changes use [server/agent-api.md](server/agent-api.md).

```sh
npm install
npm run dev -- --host 127.0.0.1
```

Run the fake backend below, then open **http://127.0.0.1:5173**. The exact origin must match `MOTED_DEV_ORIGIN`; use an isolated state/data directory. Vite proxies `/api` to port 5174. Do not expose development or fake services publicly. Browser recovery remains origin-specific.

```sh
npm run check   # TypeScript
npm run build   # TypeScript + production bundle in dist/
npm run preview -- --host 127.0.0.1
npm run test:ai # Essential Flow model, reservation, and fake-backend checks; no model calls
```

### Desktop interface

Editing uses a compact document workbench: 28px standard controls, 12px UI text with 11px secondary labels, aligned property rows, and flat sections rather than stacked cards. The 50px title bar and stable 288px / 268px Context–Assistant lane keep the document in place. Settings, Files, Share/export, creation menus, and drawing/source editors use the same control scale. Prompts and source editors retain useful writing space; page-layout and typography explanations sit in contextual disclosures.

Interface density does not change document typography, geometry, or zoom. Light/Dark appearance and the Primary hue apply throughout, including Files and Local recovery. Below 768px, Mote remains reading-only; Files and reading navigation retain larger touch targets.

On-document reservation actions and markers, selection marquees, and placement/space guides stay above the document object stack. Review actions never bring the reserved content itself to the front. Individual object review controls sit below the complete object, including its caption, and follow its measured Flow or Float placement.

## AI assistant

Select content, open **Assistant**, and choose **Reserve for Assistant**. Context contains properties, not reservation creation. Reserving locks the selected content but does not generate anything or grant external access; the request field opens next. An unsent draft offers **Cancel reservation**. A gutter segment selection generates a native composed section: an empty segment inserts at that point; a nonempty segment replaces its paragraphs, explicit spaces, Flow blocks, and owned objects. Without a segment selection, revision replaces all paragraphs touched by a text selection, or the whole paragraph at the caret (including an empty line). **Add → AI object** arms a drawing tool for a new floating area. The **Assistant** tab contains the request and review workflow; multiple reservations have their own session tabs. Describe a research, writing, formula, diagram, table, or interactive-object task and choose **Preview candidate**. **Settings → Document → Layout → Mu model** accepts an optional raw Mu model reference; blank inherits the workspace default. Explicit overrides belong to the document and round-trip through `.mote` files; credentials do not.

**Settings → Workspace** sets workspace defaults for built-in agents and indexing. Built-in generation requires a model configured in Document or Workspace settings; there is no server-wide or Mu default fallback. Blank indexing inherits the workspace built-in default, not a document override, and requires one of those workspace models. New documents inherit rather than writing a fixed model override. Existing explicit document overrides and existing agent-session models are unchanged. References may be fixed `provider/model:effort` or floating `model:effort` for Mu's configured provider fallback. Settings are revision-checked cloud metadata, outside document content/undo/export. Opening Workspace settings never probes a model; enabling auto-indexing authorizes background model work.

**Auto-index documents** is off by default. When enabled, saved documents are indexed after 100 seconds without another content save (10× the autosave interval), including after the browser closes. The indexer receives the complete native document and writes a concise discovery description, choosing important topics and useful visual/interactive material rather than inventorying every object. Private documents can be indexed for their own built-in agent. Status and explicit failed-work retry are available in Settings → Workspace. Disabling pauses work without deleting completed indexes or changing session retrieval permissions.

Each agent session separately enables **Use workspace documents** (built-in) or **Allow workspace reads** (external). The server confirms this permission; executor changes reset it. Enabled agents can download a permission-filtered `workspace-index.md`, **search the file rather than read it whole**, and fetch full relevant native documents before referring to them or reusing sections/compositions. Descriptions are discovery hints, never evidence. Current privacy applies to every index/source request, including historical reads; disabling blocks future reads but cannot recall previously fetched context. Retrieval does not expand the reserved write region or bypass candidate acceptance. A direct user-query interface is deferred.

### Availability and retry boundaries

Opening, editing, saving, exporting, sharing, and managing files/settings do not require Mu or a working provider. An agent failure retains its reservation/result for explicit Retry or Discard; unrelated content stays editable. Missing model configuration produces an actionable Settings error without starting a worker or taking the workspace offline. Configure a model and explicitly retry. Worker attempts are deadline-bound (15 minutes by default); failed or interrupted attempts require explicit retry, including after a server restart. Indexing never blocks ordinary cloud saves.

User-written requests are part of local recovery, not disposable execution output. Switching documents or adopting a newer cloud version waits for local assistant preservation; if browser saving fails, the current copy stays open for retry or task-JSON download. Files → Local recovery also includes assistant-only pending changes and carries their checkpoint when opening another tab's working copy. This does not require a model call or automatically restart generation. Candidate retention still keeps only the latest validated proposal, not a history of generated versions.

Mu handles bounded provider retries according to its installed version and configuration. Mote does not add a generation retry loop. Worker cleanup uses bounded subprocesses and six progressively spaced state checks. Unconfirmed cleanup retains the execution/artifacts and blocks subsequent built-in runs until service recovery, rather than releasing isolation or probing indefinitely.

AI and cloud HTTP requests have a 15-second deadline including response reads; explicit widget screenshot requests allow 35 seconds for bounded browser capture and cleanup. Disconnections, timeouts, service outages, redirects, HTML login pages, and invalid JSON response envelopes put the workspace into **Offline · saved locally** mode. Editing and IndexedDB saving continue; ordinary cloud requests pause. Click the sync indicator to retry. The open document also checks connectivity every ten seconds and when the browser reports that the network returned. A validated, read-only Mote request confirms reconnection before document sync, assistant-state recovery, task monitoring, and transcripts resume. A clean document's sync button also checks the server.

AI requests and candidates remain retained during an outage; uncertain submissions wait for their existing task status after reconnection. Recovery never automatically resubmits generation. Work interrupted before submission remains available to send explicitly. Healthy task checks are about two seconds during active work and ten seconds after completion. Other transient status errors back off 10/20/40 seconds, then pause after four failures; access/permanent client errors pause immediately. **Check status** resumes monitoring. Conflicts still require an explicit choice, and authentication errors require sign-in. Assistant-state refreshes remain serialized. Offline mode supports an already loaded app and its local working copies; there is no service worker to make a fresh page load available without the application assets.

Generated segments have **free height at the document width**. They may combine semantic main text, explicit spaces, first-class Flow blocks, and native Float objects with built-in captions on eligible objects. They are not flattened into one widget. The destination document mode and both theme hues apply to fixed color slots. The gutter selection's anchor-based ownership defines the replacement scope, not visual intersection. Alt-split spaces retain their unselected pieces and objects. The selection height is context, not a fixed output box; following content reflows naturally.

Each reservation shows the **Built-in / External** agent switch and workspace-read permission directly, with access descriptions in tooltips. Built-in keeps the chat workflow and creates no public grant. External replaces the composer with **Copy instructions** and **Copy link** so an agent on any machine can download the full immutable document, target, rendered snapshot, exact-version guide, and portable submission/preview helpers. Selecting External grants access; copying does not create another link. Controls stay disabled until the server confirms a switch. An uncertain response keeps them disabled with **Retry confirmation** visible. Returning to External creates a fresh link; old links and old built-in runs never regain delivery rights. Switching back to Built-in does not start generation automatically, and completed candidates survive switching. Selecting a reserved object or section updates its task in Assistant without switching away from Context. **Download task JSON** exports the full task for inspection and recovery.

The link is a secret bearer capability: anyone holding it can read the entire input snapshot and submit a replacement for the reserved region, but cannot save the document or accept changes. External results use the same validation and inline review as built-in results. Access ends on switching back, acceptance, discard, region deletion, or document deletion; closing the tab does not revoke it. Revocation blocks future reads/submissions, not downloaded copies or an external process already running. External status is **Awaiting submission**, not a claim that Mote is monitoring the agent. Handoff credentials stay outside document exports and task recovery JSON.

Tabs retain requests, streamed agent output, and follow-ups within the same session. New reservations activate their tab; **Request…** on a reserved region opens its matching tab, and **Show in document** selects and reveals that region. Arrow keys/Home/End navigate the tab strip. Draft requests and tab order survive reload. Background completion updates status without changing the active tab. **Stop** and errors retain the reservation; **Accept**, **Discard**, and explicit region deletion release it and close its tab. Switching to Context only hides the task. After the last reservation is released, Assistant stays selected and shows the current selection’s reservation invitation or its empty state. Deleting a reserved floating object with Delete/Backspace, or choosing **Delete region** in its on-document controls, abandons its task. Paragraph controls also provide **Delete region**. Undo restores deleted document content as ordinary content, never an agent session or its reservation. Ordinary cross-boundary typing/cut/history edits remain protected.

The read-only transcript uses lazy-loaded `ansi_up`, not a terminal emulator or an interactive shell. Mu's piped `-o concise` output is append-only; ANSI styling is supported, raw HTML is escaped, and terminal hyperlinks are disabled. Output follows the bottom until you scroll up; **Latest** resumes following. Only the active tab has an SSE connection, while background tasks keep their existing status polling. Switching tabs/reconnecting replays missing events; earlier requests stay visible across revisions. Transcripts have bounded retained history with omission/failure notices, and are separate from document persistence and exports. Candidate validation—not transcript text—still determines readiness. **Help & privacy** explains reservations and data sharing; with actionable authentication feedback on failures.

The assistant keeps a session strip available whenever tasks exist, including a single task, followed by one task heading and an adjacent **Show in document** button. Executor and workspace-read controls stay visible; routine access descriptions use tooltips. Before the first request, the Request composer includes a data-sharing reminder. Submitted requests use ordinary UI text; technical Mu output remains monospace. Activity opens while work is running and is initially collapsed after completion; it can be reopened without losing the transcript. Review has its own summary, **Original / Preview** view selector, and **Accept / Discard** actions, separate from the follow-up composer. The composer stays at the bottom on normal-height screens; short windows scroll the whole task to keep review actions accessible. The panel shares the Context lane’s 288px desktop / 268px compact width. It retains the document-matching surface and theme accents.

The first built-in request or external handoff uses an acknowledged immutable cloud revision of the **entire document**, including embedded assets, and a full rendered PNG snapshot. Both executors receive the selected target, the [Mote task guide](server/guide.md), and the same validated submission contract. Built-in workers additionally have read-only source and local environment guidance; external agents need no Mote checkout or Mu installation. Ordinary cloud saving uploads documents to Mote; built-in generation shares that document with the configured model, and External grants its holder download access. Manual editing does not require a successful model call. Later executor switches and follow-ups retain the original input snapshot.

Concurrent tasks reserve nonoverlapping content through generation and review. You may edit other regions and move individually reserved objects. Before the first request or external handoff, individually reserved floating areas can also be resized; preparing either freezes their dimensions with the snapshot. Once a request has been sent, body size stays locked through review, including after Stop. Caption width remains user-owned geometry for individual object tasks; caption content/removal stays reserved. Their content stays locked throughout. Segment-owned objects are locked as a composition, including placement. A partial-space segment locks its touched spacer's structure/height, but not surrounding paragraphs or unowned floating objects; two tasks cannot independently reserve pieces of that same spacer. Empty insertion bookmarks survive unrelated edits and reject losing or replacing their reserved boundary. Text selections still expand to whole consecutive paragraphs, without splitting paragraphs or crossing spaces or Flow blocks; use the gutter segment selection to include those blocks. Paragraphs, segment regions/insertion points, and floating objects share striped reservation treatment. Reserving or discarding an empty paragraph or segment does not add a saved placeholder. Cross-boundary edits and history operations that would change a reservation are blocked.

Ready candidates appear automatically **in place on the editing document**, without modifying its saved content. Selecting a reserved object or segment, placing the caret in reserved text, or clicking/tabbing into a candidate reveals **Original / Candidate**, **Accept**, and **Discard** controls. These use compact on-document buttons, with no reservation-status title; the sidebar remains available for requests and follow-ups. Paragraph and mixed-segment previews reflow the document and its anchored objects; individually reserved floating previews follow their current placement. Generated widgets execute only in sandboxed, opaque-origin frames. Reading and exports use the accepted document, not pending previews. **Accept** makes one document-history change, including an entire mixed composition, while preserving unrelated edits. **Stop** retains any previous complete candidate; **Discard** releases the reservation and removes a newly drawn floating area; existing paragraphs, segments, and objects remain. Follow-up requests reuse the task's Mu session when available. Accepted content consists of ordinary Mote blocks and objects. Drawn floating areas use ordinary draft placeholders; pending candidates and task records are separate from document exports. AI requests, snapshots, and candidates are cloud-associated and recover across devices. Local task-state copies use their own revision checks; conflicting or stale candidates remain inspectable without locking or changing incompatible content. Acceptance is a local undoable action, and the candidate is retained until that exact accepted document is acknowledged by the cloud. Switching documents does not abandon tasks.

Drawn areas are generic **New floating object** requests, not specifically figures or HTML widgets. New candidates may use Code, KaTeX, text, table, image, HTML, or drawing. The agent guide includes direct native examples for Drawing, Code, and KaTeX; these kinds need no screenshot. Existing-object revisions retain their kind except that an explicitly requested Drawing revision may convert to another supported single-object kind. The first object request captures the current document and resized area; later follow-ups reuse that immutable snapshot.

### Fake-first development

Run the app at the exact development origin below and start a fake service in another terminal:

```sh
mote_dev_dir=$(mktemp -d /tmp/mote-dev.XXXXXX)
MOTED_FAKE_RUNNER=1 MOTED_USE_SYSTEMD=0 MOTED_PORT=5174 \
  MOTED_DEV_ORIGIN=http://127.0.0.1:5173 \
  MOTED_STATE_DIR="$mote_dev_dir/ai" MOTED_DATA_DIR="$mote_dev_dir/data" \
  node --experimental-sqlite server/moted.mjs
```

Vite proxies `/api` to port 5174. The fake runner is selected only by server environment, never by a request parameter, and makes deterministic visible changes without calling Mu. Configure a model such as `fake` in Document or Workspace settings before generating; fake mode enforces the same explicit-model requirement. `npm run test:ai` exercises critical Flow atom/object, conversion, segment/clipboard, document CAS, sharing, recovery, backup, reservation, validation, and task-lifecycle invariants without a browser, systemd worker, or provider call.

### Pre-release service

The app and AI controls use same-origin APIs behind the existing `nginx_auth` cookie gate. Private navigation uses Nginx’s existing `/var/www/login.html` gate, preserving the requested URL through sign-in; there is no Mote-specific login page. `/` and `/d/:id` require login. Private mutations require the exact allowed Origin. The single key represents one trusted workspace, not separate users. Explicit `/s/:token` read-only shares, their scoped data endpoint, and reservation-scoped `/api/agent/:token` capabilities bypass login. Capability requests authenticate the token, not a workspace cookie or Origin; Nginx does not access-log that route. See [CLOUD.md](CLOUD.md).

**Settings → Document** has a **Private document** lock toggle above Layout and Theme, separate from content and undo. A highlighted closed lock means Private; an open lock means not private. Hover for the current state and action. Enabling it revokes public sharing and external-agent access, without disabling the document's own built-in agent or discarding completed candidates. Disabling it does not revive old links. Files marks private documents; owner access remains unchanged. Private controls access, not trusted indexing. The [Document Private policy](CLOUD.md#document-private-policy) governs every index and cross-document read.

`moted.service` runs the Node supervisor at `/run/moted/moted.sock`, storing cloud documents in `/var/lib/mote/documents.sqlite` and durable AI sessions in `/var/lib/mote-ai`. Each task runs Mu and Chromium as the unprivileged `mote-ai` user in a transient systemd service. Workers cannot access the document database, backups, Nginx credentials, or sibling task directories. Each receives its own explicit read-only snapshot and approved source/config resources. Workers still have outbound networking and configured provider access; this is not a hostile-user multi-tenant sandbox.

See the [service](server/moted.service.example), [Nginx deployment](deploy/mote.nginx.conf), and [manual backup command](CLOUD.md#manual-backup). Defaults are two workers, 15 minutes per run, 2 GiB memory, and 200% CPU per worker. Request bodies are capped at 128 MiB, result JSON at 8 MiB, and each widget screenshot at 10 MiB. Candidate validation never executes HTML. Explicit owner-requested widget screenshots use a separate disposable browser sandbox, not the supervisor or AI delivery path. Task workspaces/results no longer expire on a 24-hour timer; explicit task resolution controls cleanup. Inspect failures with `journalctl -u moted.service`.

`GET /api/ai/tasks/:id/events?after=N` serves the cookie-gated SSE transcript. `Last-Event-ID`, if supplied, takes precedence over the query cursor. The active transcript resumes after validated network reconnection; **Reconnect** also offers an explicit retry. `transcript` events contain `{ id, attempt, kind, text }`, where IDs increase within the task, attempts start at 1, and kind is `request`, `stdout`, or `stderr`. Requests are recorded when queued, even if stopped before a worker starts. `reset` indicates that the cursor is outside retained history; `warning` reports output limits or storage failure. Heartbeats run every 15 seconds. Nginx buffering stays disabled and stream responses send `no-store, no-transform`. Only selected Mu output is exposed, not raw session/provider journals or configuration. Task mutations are serialized so discard/delete cannot race a revision into an orphaned worker.

Server transcript defaults are 2 MiB / 2048 events, at most 128 KiB per event and 256 pending writes; slow SSE clients disconnect at 128 queued events or 512 KiB. Per-attempt stdout/stderr logs each retain at most 1 MiB, with old logs trimmed to a 4 MiB task-wide default after each attempt. Environment overrides are `MOTED_TRANSCRIPT_MAX_BYTES`, `MOTED_TRANSCRIPT_MAX_EVENTS`, `MOTED_TRANSCRIPT_MAX_EVENT_TEXT`, `MOTED_TRANSCRIPT_MAX_PENDING`, `MOTED_TRANSCRIPT_HEARTBEAT_MS`, `MOTED_LOG_MAX_BYTES`, and `MOTED_LOG_TOTAL_MAX_BYTES`. Frontend history is capped at roughly 512K text characters / 2000 chunks per tab. Task-local transcript replay survives supervisor restart and remains bounded; it is not unlimited chat storage. Missing backend sessions offer accept/discard rather than an endless retry. If server cleanup fails, local release remains final and a notice explains that unconfirmed execution artifacts remain retained.

## Editing and reading

- A cloud document library with blank/example creation, opening, filtering, renaming, importing, and deletion. Documents use the current V0 format. Incompatible saved content offers a confirmed reset to example that also replaces the cloud save; there is still no format migration promise.
- **Files**, opened from the document title, is a searchable document switcher. Click a row to open it; arrow keys navigate and Enter opens. Sort by recent modification or name, use each row’s menu for Share/Rename/Delete, and create blank documents with **New** or examples from its dropdown. **Import** accepts `.mote` or Mote-exported HTML as new files. Local recovery stays in the footer, with a count of documents that have pending changes on this device. Mobile uses a tall sheet with dates beneath names. **Share → Export** produces PNG, standalone HTML, and compressed `.mote`. The Files row’s **Share…** opens the same Link/Export dialog without opening that document, including in reading mode and on mobile. **Share → Link** controls one optional latest-version read-only link; opening the dialog never creates one.
- Semantic paragraph classes (`title`, `heading`, `subheading`, `body`, `caption`, `list`), plus fixed Table styling, retain theme-controlled typography. Inline formatting composes Bold or inherited weight, a fixed palette color or inherited color, None/Box decoration, and a separate native Link mark. Links are available in main text, floating text boxes, table cells, and captions—not Code or Drawing—and inherit text color while remaining underlined. Ctrl/⌘B changes only Bold. Code is a separate floating-object kind, not a paragraph class or rich-text editor.
- **Links:** Link replaces Underline in the Text strip. Select text and choose Link to focus its URL row below the strip; choosing Link on an existing link removes it. A caret inside a link shows the row without taking focus, and Ctrl/⌘K focuses it. Enter or blur commits; Escape cancels; an empty value removes the link. A valid URL entered at an empty caret inserts its URL as a linked label. Values are trimmed; bare domains gain `https://`, while only absolute, credential-free HTTP(S) URLs are accepted (no relative paths, `mailto:`, or `tel:`; localhost requires an explicit protocol such as `http://localhost:5173`). Unsafe protocols, control characters, and invalid URLs are rejected. Typing a URL does not create a link. Ordinary paste may detect explicit HTTP(S) URLs and preserves safe incoming rich links. Ctrl/⌘Shift+V strips incoming link marks and skips URL detection, but a paste inside an existing link inherits that destination link. Ctrl/⌘-click opens a link in a new tab while editing; ordinary reading clicks also open a new tab. Links have no popover. The Clear formatting action is removed.
- The **50px title bar** keeps a clickable document title and live save indicator on the left, with quiet history, Add, zoom, minimap, document actions, and Read controls on the right. The save indicator stays visually plain, with a pointer cursor and “Click to sync” tooltip; click to sync or retry a local save. Ctrl/⌘S remains available. Share, Settings, and Reset to example remain flat icons with hover tooltips at every editing width. Share uses a link icon and opens Link/Export tabs; Settings uses a gear and opens Document/Workspace/Browser tabs. There is no collapsing More menu. Reset retains its confirmation. The single Read button becomes Edit in reading mode without moving. Reading and mobile retain the document title for Files access; mobile has no editing controls.
- The right lane has persistent **Context / Assistant** tabs, with one stable width per breakpoint (288px desktop, 268px at 1050px and below). Eligible rich-text selections show a fixed **Text** strip above the scrolling properties: paragraph class, Bold, palette color, Box, and Link. Table/Caption keep fixed class indicators; Code/source and non-text objects do not show rich-text tools. Alt+F10 focuses the strip, arrows/Home/End navigate its controls, and Escape returns to the retained caret. Menus preserve selection; the color menu includes recent colors. Creation stays separate under **Add** or the right-click launchpad, including over floating objects. While an object tool (Text box, Code, Drawing, AI object) is armed, a dimmed preview of its default size follows the pointer; a plain click creates exactly that object in place, and dragging sets its size instead. Every page target, including existing objects and the left gutter, keeps the crosshair cursor because clicks always insert. Hovering the gutter shows the nearest segment boundary (Alt splits explicit spaces) with a centered Flow preview; clicking inserts a centered Flow object there in one undo step, or with AI object reserves an empty AI section at that boundary. Escape, window blur, or clicking Cancel placement disarms the tool. The preview is never saved, measured, mirrored in the minimap, or exported. Object actions remain in Context, not right-click menus; highlighted text and native/editor-specific contexts are preserved.
- **Settings** opens one fixed-size dialog with **Document**, **Workspace**, and **Browser** tabs, without changing canvas width. Document retains Layout and Theme, its AI model override, and Private. Workspace contains shared model defaults and opt-in indexing, with explicit revision-checked Save settings. Browser contains local display preferences. Document/browser edits apply immediately; workspace drafts persist across tab switches and closing/reopening Settings within the same document session. Context shows a selection hint when empty and the current selection’s properties when active.
- The selection inspector puts **Duplicate / Delete** icons beside the object heading, then the shared **Flow / Float** choice. Content editing and appearance precede **Layout**, which offers object margins and compact **Bring to front / Send to back** icon buttons beside its heading. Resize objects and snap Flow objects to the center by dragging on the canvas; there are no object Width/Height fields or centering button. Drawing dimensions keep proportions. Table row/column operations use compact labeled pairs before column alignment and appearance. **Add caption / Edit caption** is one shared action on eligible owners; removal, width matching, and Caption typography belong to the caption's own inspector. Multi-selection shows only group actions. The relevant document-wide **class style…** shortcut appears directly in Context, without a disclosure. Palette settings remain available from the text color menu and Settings → Document → Theme, not as a Context shortcut. Widget Edit code/Run and Update screenshot stay visible, while the saved preview and description fold under **Screenshot details**. Pending capture, missing screenshots, offline notices, and errors stay visible. Routine explanations use tooltips or the bottom **Help & shortcuts** fold. Selecting another object starts its inspector at the top. Controls retain 32px minimum targets, native keyboard behavior, and document-matching surfaces.
- Theme Defaults define base typography, text color, and spacing; Appearance supplies the page background. Paragraph classes retain partial overrides, inherited indicators, resets, and previews. Font sizes and lengths offer **em** and **px**; line height also offers **×** the paragraph font size. Every em is relative to Defaults font size, initially 16px. Inline Bold is always 700; font family, size, spacing, and inherited weight come from the paragraph. Box uses a thin current-color border and the selected family’s Soft tone, or Gray 5 for inherited/neutral color. The Box icon contains an A. Box uses the browser’s normal inline font box, with no glyph measurement or custom mark view. Its border includes the font’s reserved ascent/descent space. Links inherit text color and are always underlined. Browser selection highlights may extend to the full paragraph line height, so they are not the same boundary as this font-sized decoration. Decorations wrap with the text rather than becoming indivisible pills.
- **Settings → Document → Theme → Palette** offers Light/Dark appearance and Primary/Secondary hue sliders. Each document has two fixed palette sets with 22 swatches: Primary and Secondary plus Red, Amber, Green, Blue, Violet, and Pink in Strong/Soft pairs, followed by six individual adaptive grays. Strong is deep in Light mode and light in Dark mode; Soft is pale in Light mode and deep in Dark mode. Gray 1–6 reverse their tonal direction, including literal black and white endpoints. Colors have fixed tones; families cannot be added, renamed, deleted, or edited as raw RGB/hex. Mode and hue changes are live, saved, and undoable. Native text, object colors, drawings, captions, minimaps, readers, and exports all resolve the same fixed slots. Paste and AI content adopt destination mode and hues without importing colors. The compact palette grid keeps theme pairs first, fixed pairs next, and six grays last; native radio navigation, accessible tone names, selection, and focus indicators apply throughout. None/transparent and Inherit remain separate behaviors.
- **Appearance** explicitly controls the page and UI; it never follows OS preference or infers mode from a custom background. The fixed page surface is white in Light and #181818 in Dark. Header, text tools, Context/Assistant, menus, and minimap share it; canvas surround stays achromatic. Primary controls interface accents, selection, focus, editing outlines, and the minimap viewport border. Secondary affects document colors only. Interface status colors retain their meanings and readable contrast. UI tones are derived separately from authored swatches. Default native text uses Gray 2, captions Gray 3, table borders Gray 4, and inherited/neutral Box surfaces Gray 5. Each pair is designed for readable Strong/page, Strong/Soft, and default-text/Soft combinations; arbitrary swatch combinations are not automatically corrected. Images and widget source/screenshots keep their own colors; Code syntax colors follow the saved Light/Dark appearance but not the hues. Public reading and standalone HTML use saved appearance; PNG captures the current appearance.
- **Code objects** are plain-text source snippets with Flow or Float placement, preserved whitespace, automatic content height, horizontal scrolling, and line numbers. Choose a language identifier; syntax colors follow the document Light/Dark appearance and do not use or change the palette hues. Code is not executed. Its monospace typography remains configurable through the document's Code theme style; it has no paragraph class, inline marks, or paragraph shortcuts.
- **Heading / Subheading spacing:** presets use 2.5em and 2em Space before, respectively, measured against the theme's default font size. Saved explicit styles are unchanged.
- **Subheading** is always available between Heading and Body in the paragraph menu for main text and text boxes. Its initial theme style is 1.125em (18px at the default baseline), semibold, with 1.5em line height, 2em space above, and 0.5em below. It provides local subsection structure without nesting, numbering, folding, or minimap bookmarks; only Title and Heading remain navigation landmarks. `theme.blocks.subheading` is optional: omission uses this preset without rewriting saved documents, while an explicit override object inherits unspecified properties from Defaults like other classes.
- **List** is an independent unordered-list item, not a child of a list container. Tab on Body converts the whole paragraph to a top-level item, wherever the caret is; text, inline formatting, and selection are preserved. Across selected paragraphs, Tab converts Body and indents existing List items, leaving other classes unchanged. Enter splits an item into a new same-level item, including when the item is empty. Shift+Enter adds a line aligned with the item's text start. Tab / Shift+Tab or the toolbar arrows indent/outdent selected items independently, without changing neighboring items. Shift+Tab on a top-level item returns it to Body. Backspace at the start reduces one level; at the top level it returns the item to Body without deleting its text. Each level adds 24px indentation, never a font-size change. Top-level markers are solid dots; all sublevels use hollow dots. Pasted unordered lists flatten into independent paragraphs; ordered-list paste becomes Body text. List works in main and floating text, while tables always use Table; tables retain cell navigation.
- **Add → Paragraph** arms a boundary picker for main text. Move over the page to highlight the nearest paragraph break or space edge, then click to insert an empty Body paragraph and start typing. Mixed alignment leaves all three buttons inactive. New columns start left-aligned with an equal-share weight; adding/removing columns preserves the relative widths of surviving columns. New rows follow existing column alignment.

## Model and boundaries

### English and Simplified Chinese

Mote is English-first, with horizontal mixed English/Simplified Chinese document text. **Document → Layout → Text language** selects English (the default) or Simplified Chinese for the document content, without changing the interface. This language applies to the shared page, including text boxes, tables, captions, drawing labels, minimap snapshots, PNG, and standalone HTML. There are no per-passage language controls or automatic language detection. Vertical writing and language-driven right alignment/RTL layout are non-goals; ordinary table-column alignment is unchanged.

The three semantic typeface choices use installed fonts, not downloaded or embedded document fonts:

- **Sans serif:** English documents prefer Inter, Segoe UI, Helvetica Neue, Arial, Noto Sans, and Liberation Sans before the Chinese fallbacks. Simplified Chinese documents prefer Microsoft YaHei first. Both retain PingFang SC, Noto Sans CJK SC / Noto Sans SC, and system sans serif fallbacks. This keeps English curly apostrophes narrow while retaining Chinese glyph coverage.
- **Serif:** Georgia for English, with Songti SC, SimSun, and Noto Serif CJK SC / Noto Serif SC for Chinese, then the system serif fallback.
- **Monospace:** system monospace, SFMono-Regular, and Consolas, with Sarasa Mono SC, Noto Sans Mono CJK SC, and Microsoft YaHei fallbacks. Chinese glyph coverage and cell-width alignment are best-effort.

Prose and captions use normal word breaking, strict CJK punctuation breaking, and emergency wrapping for long unbreakable strings. **Theme → Defaults → Mixed-script spacing** defaults on and uses CSS `text-autospace` to add visual gaps between Chinese and Latin letters/numbers where the browser supports it. It never inserts spaces into stored or copied text. Code objects retain literal source whitespace and do not apply mixed-script spacing to their source. Title and Heading presets no longer apply negative tracking; existing saved theme overrides are not rewritten. Theme samples include mixed English/Chinese text. System-font availability and browser typography support can still change wrapping across devices; no identical-layout guarantee is made.

Editor composition transactions are grouped by editor and composition identity, without the ordinary typing timeout splitting a paused conversion. Global document shortcuts yield to composing/process-key events, table paragraph-input handling yields to composition, and document-history navigation waits until composition ends. Scoped Chromium checks use browser composition injection, not a native OS candidate window; Windows/macOS input methods and Safari/Firefox still need hands-on verification.

### Drawings

**Add → Drawing** creates a bounded sketch: drag to choose its width and height, or click for a default size. Creation opens an almost full-screen drawing editor. Select an existing drawing and click its centered pen button, double-click, press Enter, or choose **Edit drawing…** in Context to reopen it. The editor fits the drawing above a floating toolbar while preserving the object's aspect ratio. Done or Escape returns to the document; completed edits save through the normal document history and synchronization.

The toolbar offers Pen, whole-stroke Eraser, typed labels, document-palette colors, a discrete width slider, and undo/redo. Widths are **1, 2, 3, 4, 6, 8, 12, 16, 24, 32 document pixels**, initially **2px**. Magnification changes their screen appearance without changing stored widths. Changing color or width affects subsequent marks only. Each completed pen or eraser gesture is one undo step. Handles on the canvas's four edges crop or extend that side as one undo step, without stretching content: strokes and labels keep their document-pixel size and page position (arrow keys on a focused handle step 8px, Shift 1px). The More menu contains a Transparent/Solid background control (Solid is adaptive Gray 6), confirmed Clear drawing, and shortcut help. P/E/L selects tools; Ctrl/⌘Z and Ctrl/⌘Shift+Z undo/redo. Escape cancels unfinished input before closing. A blank drawing remains available for later work.

Drawings share Flow/Float placement, anchoring, ordering, clipboard, native saving, minimap, and exports with other objects. On the page, the right border, corner handles, and keyboard resizing always keep the aspect ratio; changing proportions is done by cropping or extending in the editor. Resizing scales stroke and label positions while retaining document-pixel pen widths and label font sizes. Editing controls are absent from reading, PNG/HTML exports, and AI snapshots. Viewports below 768px remain reading-only.

Select the sketch, open **Assistant**, and choose **Reserve for Assistant** to turn it into a figure, then review Original/Preview and accept through the existing Assistant workflow. Unlike ordinary object revisions, a drawing may become another supported floating kind, such as an SVG image or HTML widget. Acceptance is undoable; the resulting object uses its normal editing controls.

### Code, formulas, and HTML widgets

**Add → Code** arms a drawing tool: drag horizontally to choose width, or click for a default-width snippet. The new object starts empty with its caret ready. Its plain-text `source` preserves whitespace, grows to its measured content height, scrolls horizontally rather than wrapping long lines, and shows line numbers. Select JavaScript, TypeScript, Python, JSON, HTML, CSS, Shell, or SQL in the language picker; `plaintext` is the initial plain-text mode. The document Light/Dark appearance selects the matching syntax scheme; syntax colors are independent of the palette hues; source is displayed, never executed. Its size, weight, line height, and letter spacing come from the document-wide Code theme style. The typeface is always monospace; the appearance-matched syntax scheme supplies its own background, foreground, and token colors. The Code theme style is under Objects, not Paragraphs.

Height follows every source line, including blank and trailing lines; there is no vertical scrollbar or line wrapping. The horizontal scrollbar appears only when needed. Line numbers and the language header stay fixed while source scrolls. Select one object to edit; Enter and Shift+Enter insert line breaks, Tab / Shift+Tab indent/outdent, and paste flattens rich paragraphs into plain line breaks. Escape returns focus to the object. Drag its header to move it, or deselect it and drag anywhere inside; grouped objects stay in positioning mode. Copy returns the complete source without the header or line numbers. Reading and standalone HTML retain selection, Copy, and horizontal scrolling. PNG captures the visible object width from the beginning of each line, without Copy controls. Blank source objects are removed on deselection, like empty text boxes. The highlighter is a lightweight bundled lexer, not a full language parser or IDE.

**Add → Formula** inserts a centered Flow display-mode formula; Context can switch it to Float. The inspector edits its LaTeX source live, without `$$` or `\[...\]` delimiters; syntax errors retain the source and appear on the object. Width is user-controlled and height follows content. Formulas are centered, never automatically wrapped or shrunk, and can use explicit constructs such as `aligned`. Oversized content follows the existing page-edge cropping policy. **Math style…** opens a global size/color style inherited from Defaults, with px/em units and normal history/reset behavior; math typefaces remain KaTeX's. KaTeX's unsafe HTML commands are disabled (`trust: false`). The renderer and WOFF2 math fonts are bundled for offline HTML and PNG. This is not a full LaTeX document engine, and inline mathematics is not included.

**Add → HTML widget** immediately inserts a centered Flow widget with an editable button-counter demo and a neutral screenshot placeholder. No image upload is required; Context can switch it to Float. **Edit code…** opens one HTML/CSS/JavaScript source field; drop a single `.html` or `.htm` file into that field to replace the source in one document-undo step. Source edits save immediately, while **Run / Restart** recreates the iframe and executes the current source. Dropping a file does not run it or replace the screenshot. Each widget has its own DOM, CSS, globals, and libraries. Moving, resizing, selecting, changing mode, and front/back ordering retain its running state. Runtime interaction state is not saved or included in document undo; reopening starts from saved source.

HTML widgets resize by dragging their right border or corner handles; corner resizing adjusts width and height independently. Their iframe viewport follows the saved dimensions, while page zoom scales the entire widget. Hover and selection outlines surround only the widget body; its owned caption has a separate outline, matching tables. In editing mode, click/drag an unselected widget’s noninteractive interior to select/move it. Selection directly enables its contents for subsequent clicks and drags, without a separate interaction mode or button. Clicking elsewhere on the page deselects it and makes its interior draggable again. Selection and movement never restart the iframe; only Run / Restart or an explicitly restored source revision replaces its execution. Reading/mobile interiors are directly interactive. Each iframe uses `sandbox="allow-scripts"`, without access to Mote's DOM/storage or top-level navigation. This prevents namespace collisions and limits access, but is not a CPU/memory quota or a promise that arbitrary code cannot affect responsiveness.

Resource references, including CDN scripts and external data, are used as written. Mote does not inspect widget source, bundle or rewrite external resources, or guarantee offline operation for network-dependent demos. Normal browser resource restrictions still apply. There is no separate ECharts object or bundled chart library: authors can embed ECharts with their own script reference.

The example formula exercises aligned equations, fractions/roots, scripts, Greek letters, sums/binomial coefficients, integrals/derivatives, matrices, underbraces, cases, and vector notation. The two example widgets load pinned ECharts 6.0.0 from jsDelivr: **A week of attention** uses an `<attention-chart>` custom element with shadow DOM, a measure selector, legend filtering, tooltips, and bar-click details (also emitting `attention-select`); **Ideas in motion** animates a repeating six-pass bar ranking with value interpolation, Pause/Play, and Next pass. Reduced-motion preferences disable transitions and start the ranking paused. Their HTML sources and manually captured PNG previews live in `src/document/examples/`; no chart dependency is bundled. Existing example previews are retained (the ranking preview shows paused pass 4); Update screenshot captures a fresh run at the current saved dimensions, not that previously chosen animation state.

**Update screenshot** in Context sends only the current saved widget source and dimensions to Mote for a fresh, isolated browser run at 2× resolution. It does not restart the on-page widget, reproduce its current interactions, or require a cloud save first. The previous screenshot stays visible while capturing and on failure; an inline error offers another explicit attempt. A successful replacement is one undoable document edit and syncs normally. Source/dimension changes, history navigation, deletion, AI reservation, leaving editing, or switching documents invalidate pending captures. There is no automatic recapture on code changes, resize, reconnection, minimap rendering, or export. New widgets use a neutral placeholder until their first successful capture; existing embedded screenshots remain intact. The saved image is used for the minimap and PNG export, stretched to the object's saved rectangle; refresh it after code or dimension changes. Minimap snapshots remove live iframe content before insertion; PNG mounts a screenshot-only reader and never starts widget code. HTML exports keep live widgets, not screenshot substitutes. Code, formulas, and HTML widgets share object selection, Flow/Float placement, anchoring, movement, ordering, duplication/deletion, and document history. Of these kinds, only HTML widgets support captions. Float movement uses the page grid; Flow movement uses document boundaries and horizontal center snapping.

The example is a continuous document built around Flow figures, a table, Drawing, Formula, Code, and two interactive widgets. An overlapping note follows the landscape image on both axes, its built-in caption contributes to the Flow block’s height, and a separate Float demonstrates left-only text repulsion. The final explicit space demonstrates a deliberate pause rather than a spacer used to reserve object height. The example also describes current Files, cloud synchronization, Share/export, and Assistant controls.

### V0 representation

Rectangle, ellipse, and line object kinds are unsupported. Older documents containing them use the confirmed-reset recovery flow; imports containing them are rejected. No automatic migration or cloud-document rewrite is performed.

Native links use `{ type: "link", attrs: { href: "https://example.com/" } }` and require an absolute HTTP(S) URL. Older V0 underline-decoration marks are unsupported; there is no migration or rewrite of saved documents. Unsupported content uses the existing confirmed, revision-checked recovery flow.

Optional `language` is `en` or `zh-Hans` (omission means English). Optional `theme.autospace` is a boolean (omission means enabled). Both persist with the document, participate in history, and are validated on draft initialization and native import. They require no text rewriting or schema migration.

Optional `theme.flow: { spaceBefore?, spaceAfter? }` stores nonnegative theme lengths, separate from paragraph classes. Optional object `margins: { top, right, bottom, left }` requires all four finite signed numeric document-pixel values when present; omission means zero on every side. For content bounds `(x,y,w,h)` including caption overhang, layout bounds start at `(x-left,y-top)` and have size `(max(0,w+left+right),max(0,h+top+bottom))`. Neither field rewrites existing saved content when omitted.

KaTeX objects store `kind: 'katex'` and `latex` alongside shared floating geometry. HTML widgets store `kind: 'html'`, `html`, embedded `screenshot`, accessible `alt`, and explicit `height`. Math overrides live in `theme.blocks.math`; omission means inherited size/color, without rewriting the draft. Native import checks these fields and screenshot safety, but intentionally does not sanitize executable widget source. The `.mote` file contains source and screenshots, never live iframe state or run counters.

`MoteDocument` contains a `version: 'V0'`, optional `notes` (an ordered array of plain-text notes, or a string for a single note; absent means empty), width, four page margins, theme defaults and paragraph-class overrides, main-text editor JSON, and floating objects. Required `theme.mode` is `light` or `dark`; required `theme.hue` and `theme.secondaryHue` are finite OKLCH degrees in [0, 360), initially 28 (Huawei Red) and 265. `theme.palette`, `theme.defaults.background`, and clipboard/AI segment `palette` fields are unsupported, even when empty. Native color references are `primary`, `secondary`, `red`, `amber`, `green`, `blue`, `violet`, `pink` (each also supports `:soft`) and `gray1` through `gray6` (no Soft tones). Palette definitions are shared renderer code, never saved custom hex values. Older V0 documents use the existing confirmed, revision-checked reset flow; declining preserves stored data. Unsupported native imports leave the current document untouched. There is no palette migration. Each main-text block has a stable UUID. Main-text paragraph semantics are `title`, `heading`, `subheading`, `body`, `caption`, or `list`; List has a zero-based `listLevel`. Code is not a paragraph class: legacy V0 documents with `semantic: 'code'` paragraphs are rejected, not migrated. The Code entry remains in `theme.blocks` for Floating Code typography. Objects remain in the `floating` array and require `placement: "flow" | "float"`, an anchor UUID (or a document-top null anchor for Float), x/y, and width, with optional boolean `centered`. Each Flow has exactly one main-document atom `{ type: "flow", attrs: { id, objectId } }`; its `anchorId` is that block’s ID and its saved y is zero. Flow x is relative to the text-column left; `centered` derives x from the current column and object widths. A Float anchored to a paragraph, spacer, or document top uses page-space x and nonnegative anchor-relative y. A Float anchored to a Flow uses signed x/y offsets from the Flow object’s measured top-left, so annotations follow both axes. Images, HTML widgets, and tables may store an optional `caption:{content:JSONContent,width?:number}` subobject. Its `content` is a doc with exactly one paragraph whose `attrs` contains only `id`; all captions use the theme Caption style and appear below their owner. An omitted width follows the owner; an explicit finite positive document-pixel width remains fixed when the owner is resized and may exceed the owner's width within the page. Caption width is centered on the owner; captions have no own floating ID, x/y, placement, or detach state. Previous V0 bare-document captions are rejected without migration. Legacy `textFlow` and missing placement are rejected, without migration. Legacy `attachment` keys anywhere in V0 data, even null, are rejected through confirmed-reset recovery; no migration is performed. Native rich text uses `{ type: "link", attrs: { href } }` only for absolute HTTP(S) destinations, alongside bold, fixed-color, and Box marks; links are supported in main text, text boxes, table cells, and captions, not Code or Drawing. Older V0 underline-decoration marks are rejected without migration. Text/table objects store constrained rich-text content; text boxes also store optional `background` and `borderColor` colors (null or omitted means transparent), `padding`, and optional/null `decoration: { kind: "info" | "warning", color: paletteReference }`; Floating Code stores plain `source` and a safe language identifier, with syntax colors following `theme.mode`; images store embedded image data and an accessible description; HTML widgets store HTML, an embedded screenshot, accessible description, and height; formulas store LaTeX source; drawings store bounded strokes and labels, height, and a Gray 6/transparent background; captions are supported only on image, HTML, and table objects; all other kinds reject the field. Code has no saved height; its rendered height follows source content. Built-in captions follow their owning object's layout. An omitted kind denotes a text box. Tables have their own constrained schema: one table, exactly one paragraph per cell, no editable paragraph semantic attribute, and the shared composable inline marks. Table objects may store `style: 'simple' | 'academic' | 'business'` (omitted means simple) and boolean `headerRow`; other kinds reject both fields. The table node stores a `columns` array of `{ width, align }`, with normalized proportional widths and left/center/right alignment. An absent array means equal-width, left-aligned columns. Column commands update structure and metadata in one transaction; rectangular paste extends metadata when it grows the table. Rendering uses a colgroup and column-wide cell decorations, with noneditable divider controls excluded from the minimap. Images use their intrinsic aspect ratio; tables grow vertically with their cell content.

List retains the flat `paragraph` node and stable block UUIDs; each list paragraph stores `semantic: 'list'` and a zero-based `listLevel`. There are no list containers, ownership relationships, or nested item nodes. Floating Code objects share the ordinary anchor, repulsion, space-flow, minimap, persistence, and undo systems; they are not parsed as rich-text paragraphs.

Each spacer stores a stable block UUID and a `height` in document pixels. Consecutive spacer nodes normalize to one, summing heights and transferring floating objects to the retained anchor with their offsets preserved. Text has no saved height or capacity reservation. The 12px removal threshold applies at gesture completion, not as a side effect of changing typography. Old V0 text-height reservations are no longer interpreted; V0 makes no layout-migration promise.

Gap previews use transient editor decorations; creation previews do not insert saved document nodes. Resizing an existing gap adds or removes room at the drag's starting position: floating objects at or below that position move by the height change, while those above stay put. Later main-text anchors move normally, and built-in captions remain part of their object without a separate spacer shift. Upward dragging can produce overlap; ordinary paragraph/space anchor offsets remain nonnegative. Flow objects and their anchored annotations follow their block without receiving a second spacer shift. Mouse release commits once, even if Alt has already been released. Escape, pointer cancellation/capture loss, window blur, zoom/mode changes, and document replacement cancel a drag. Each completed gesture and any resulting merge form one document undo step. Normal paragraph margins are preserved rather than added twice when a gap separates them. Closing a space never resizes or deletes its Floats; their new positions determine left-only repulsion of following main text.

When an ordinary anchor is deleted, its Floats move to the closest surviving preceding block, or the document-top origin. Removing a Flow atom removes its object, and deleting a Flow object removes its atom. Surviving anchored Floats are reanchored using measured page positions; a caption remains part of its surviving object. Deleting or cutting a whole segment instead removes its owned composition, including Flow objects, anchored Floats, and the captions they own. The shared history restores document snapshots and editor selections without stealing focus or undoing view preferences. Reset to example remains confirmed and clears history. Only the current V0 is supported: loading checks its identity and initializes content through the editor schemas, with current V0 validation and no historical upgrades. An editor parsing failure offers a confirmed reset to example for authenticated workspace documents; this revision-checked reset also replaces the cloud save. Declining leaves stored data untouched. Public readers can never reset content.

Desktop tabs edit independent working copies rather than taking an exclusive document lock. A per-tab identity lock prevents duplicated tabs from sharing one local recovery record; without Web Locks, new page sessions always fork. Dirty local copies are never replaced automatically by remote content. Clean private editors check for newer cloud versions. A public latest-link reader fetches the current cloud document once when opened and makes no update checks; reloading fetches later cloud saves.

Storage-access failures show Retry, never a reset prompt. Local save failures retain the in-memory document and warn before leaving. **Synced** means a backend acknowledgment; **Saved locally · changes pending** is not a cloud backup. Authentication failures preserve edits and offer sign-in in a separate tab.

IndexedDB (`mote-cloud` → `copies`) holds per-session recovery, not the authoritative workspace. Clearing browser data can remove unsynced work. **Files → Local recovery** exposes pending copies, including those belonging to closed tabs. The former `mote-local` draft remains untouched and can be explicitly imported as a new cloud document. SQLite holds cloud content; backups are manual only, and native `.mote` export remains available.

**New** starts a local draft, not a cloud file. A single empty Body paragraph with default document settings stays out of Files, including after autosave, Ctrl/⌘S, reload, or switching documents. Text, Notes, objects, explicit document structure, or changed document settings make it eligible for normal cloud saving; browser/workspace preferences do not. Private also saves the document before confirming its cloud access setting. Reverting to the untouched blank before its first save keeps it local. Local export remains available; public Link sharing requires a saved cloud document. AI reservations remain local until the document is saved or an explicit generation/handoff request needs a retained input. Examples and imports still create files immediately. Existing cloud documents are never automatically deleted or suppressed when emptied.

Floats may deliberately overlap other Floats and Flow objects; Flow blocks retain their own vertical positions in the main document. Pointer and keyboard movement, duplication, and resizing stop at the document's horizontal edges; group movement preserves relative positions; built-in captions remain part of their objects. Content editing and widget interaction activate only when exactly one floating object is selected. Multi-selected text boxes, tables, and widgets remain in positioning mode: dragging a Float-only selection moves the group, table dividers stay hidden, and widget frames remain inert. Reading-mode interaction is unchanged. Changing document width does not rewrite saved offsets, and shrinking the page can still leave existing content outside its bounds. Automatic Float insertion/paste measures rendered size and staggers when either the new or existing object would completely cover the other; partial overlap remains allowed. Float duplicates also stagger while preserving group relationships. Flow insertion, duplication, and paste create actual document blocks rather than staggered overlays. Captions have no independent x/y or placement; their optional centered width is saved separately from owner geometry. This is insertion-only placement, not ongoing collision avoidance or a full spatial layout inspector.

- **Floating clipboard:** focus one object or marquee/Shift-select a group, then use Ctrl/⌘C, X, and V to copy, cut, and paste. All floating kinds are supported. Built-in captions travel as part of eligible objects, and a copied Flow also carries its anchored Floats and block atom. Paste adds a newly selected group with fresh object, Flow-block, and rich-text IDs, preserving relative placement and stacking. Flow payloads insert remapped blocks at the caret or segment boundary. Float-only payloads retain the copied page position, or use the main-text caret's height when pasting in the main editor, and stagger to avoid fully covering existing objects. Placement uses destination measurements and page bounds; oversized groups retain their dimensions rather than being scaled. Repeated paste adds independent groups. Native V0 data has an HTML carrier and readable text fallback; fixed palette references follow the destination mode and hues as in segment paste. Cut and paste each undo in one step. While editing floating text, table cells, source fields, or widget contents, the content editor keeps its clipboard behavior. AI-reserved objects cannot be copied or cut. Floating paste never replaces a main-text or segment selection.

## Document files

The editing header’s **Share** and **Files → row menu → Share…** open the same dialog: **Link** controls the document's single optional latest-version public link; **Export** offers PNG, HTML, and native .mote exports. New documents start with Link off, and opening the dialog never creates a link. For the open document, enabling first synchronizes its working copy; if sync fails, no link or URL is created. For another document, enabling shares its cloud-saved content without syncing or switching the open document. When enabled, the tab shows the URL and **Copy link**. **Replace link** and **Disable sharing** each require confirmation; disabling permanently revokes that URL, and enabling again creates a fresh one. Copying, replacing, or disabling does not require a document save. Private disables only Link and opens Export; offline still permits local exports. Link state is server-owned, outside document undo and export settings. Public latest-link readers fetch the current cloud document once when opened; reloading fetches later cloud saves. Notes are omitted from public shares. **Files → Import → Choose file…** creates a new cloud document rather than replacing the open one. Ctrl/⌘S synchronizes the active working copy.

Opening Share from Files preserves the list’s search, sort, scroll position, and row focus on return. The open document exports its current working copy, including unsynced edits. Other documents are fetched and validated when the dialog opens; exports use that cloud snapshot, not local recovery copies. A pending-local-change hint makes this distinction explicit. Loading failures can be retried or dismissed without changing either document; unsupported content is not reset from Share. An already loaded source remains exportable offline, but fetching another document requires a connection. Pending AI candidates are never exported.

Internal Notes are preserved only in native `.mote` exports. PNG and HTML publish the page without notes; importing an exported HTML file therefore starts with empty notes.

The **Filename** field starts with the selected document’s name and supplies the export name, with the selected extension added automatically (an existing PNG/HTML/Mote extension is replaced, not duplicated). Where `showSaveFilePicker()` is available, export opens the browser's native Save As dialog with that suggested name and format filter. The picker is invoked directly from the click before export preparation; canceling does not generate or download a file. Bytes are written only after generation succeeds, and success is reported after the writable stream closes. Elsewhere, Mote uses an ordinary download with the chosen filename; browser preferences determine whether it prompts for a location. The filename is session-local UI state, not part of the document.

- **PNG:** one full-length image with a **Resolution** selector: **1× · Original** or **2× · High resolution** (default). The selector is export-local UI state, not document content. At 2×, each document CSS pixel gets two output pixels per axis (four times the pixel area); a 960px-wide page exports at 1920px. Text, formulas, and vectors render directly at the selected resolution rather than enlarging a finished bitmap. Embedded images and widget screenshots use a matching raster scale, but remain limited by their source detail. Layout stays at native document size after images/fonts/layout settle, independent of display density, scroll position, and view zoom, including the theme background, spaces, tables, drawings, formulas, and floating objects. The page's horizontal edges crop overflowing content; the width never grows to accommodate objects. Fractional pixel extents round upward. No app chrome, page shadow, selection controls, or added bottom padding. Animated images become a still frame. Output dimensions are capped at 32,767px per axis and 32 million pixels in total; smaller browser limits can also prevent export. It checks rasterization support and reports failures rather than silently shrinking/truncating the document. Oversized 2× exports suggest trying 1×; HTML and `.mote` remain alternatives. Scoped raster checks use Chromium; other engines' HTML-in-SVG raster support varies.
- **HTML:** a single file that opens directly from disk, with inline CSS/JavaScript and embedded document/images/math fonts. Mote content and self-contained widgets work offline; widgets referencing online resources still require them. It mounts the same `DocumentCanvas` through `ReadDocument`, sharing text schemas, theme styles, anchor/repulsion measurement, floating-object layout, fit/zoom, minimap, and heading navigation. The shell has no top bar, Edit button, File/View menus, or zoom buttons. Auto zoom, zoom gestures/shortcuts, and automatic minimap/heading navigation remain; the minimap hides on small screens. The page keeps its authored background without a border or shadow; the minimap shares that background and the exposed canvas uses the same neutral gray surround as the app. The Mote reader itself does not access IndexedDB, localStorage, Web Locks, or a server; widget code runs separately in sandboxed iframes. The page and minimap crop horizontal overflow just like app reading mode; zoom still permits horizontal navigation within the page. Text stays selectable and searchable. JavaScript is required; ordinary system fonts remain system fonts, so typography can vary across devices and the shared layout recalculates accordingly. The V0 document JSON, with internal Notes omitted, is embedded in a non-executable `#mote-document` script element, so Mote-exported HTML can be imported back as an editable document.
- **Mote document (`.mote`):** binary gzip of UTF-8 JSON containing the existing `MoteDocument`, including `version: "V0"`, IDs, theme, geometry, rich text, and embedded assets. There is no archive manifest, custom binary header, encryption, or base64 wrapper around the file. Session history, selection, zoom, and browser preferences are excluded. Both compressed and decompressed data are capped at 128 MiB. Only the current V0 schema is supported; V0 does not promise compatibility with older builds. Ordinary gzip tools can inspect the JSON.

Import accepts `.mote` and Mote-exported `.html`/`.htm` files (case-insensitive extensions). Native files are decompressed; HTML is parsed in an inert template and must contain exactly one `script#mote-document` with type `application/json`. Extraction never runs the outer HTML reader/scripts or loads its resources. After opening the imported document, its authored widgets run in the usual sandboxed frames. Both paths validate the embedded JSON, including the current V0 schema, geometry, safe image/style values, and rich-text schema. HTML files and extracted JSON are capped at 128 MiB. This is not a general HTML-to-document converter; older exports must still match the current V0 schema. Unsupported or corrupt files do not alter the current document. There is no migration or repair layer. Successful import creates a new cloud document with a fresh document ID; existing files are untouched.

PDF export is deferred. PNG and arbitrary HTML cannot be imported back.

## Structure

```text
src/cloud/      working-copy sync, connection recovery, routing, Files/Share/Settings dialogs
src/app/        application shell, controls, responsive styles
src/document/   V0 model, examples, IndexedDB, history, validation, file codecs/PNG export, clipboard, Code language IDs/highlighting
src/editor/     constrained Tiptap schemas, inline formatting, editor interactions
src/canvas/     measured anchors, Flow mounts, Float layer, owned captions, spatial interactions, shared reader, zoom, minimap
src/theme/      semantic styling, shared palette, theme-derived UI colors and controls
src/reader/     offline reader entry and single-file HTML export
src/ai/         reservations, task state, service client, review UI
server/         moted, cloud store, indexing/retrieval, worker isolation, task guide, preview/delivery helpers, fake runner
```

Flow atoms expose noneditable mount points inside the main editor. `DocumentCanvas` portals the existing object renderer and any built-in caption into those mounts, using their actual normal-flow heights rather than saved-height spacers or absolute overlays. Float objects remain in the spatial layer. Editing, shared reading, minimap snapshots, PNG, and standalone HTML use this same rendering path.

The Vite configuration builds the offline reader as a production IIFE and stylesheet behind `virtual:mote-reader-bundle`. The HTML exporter embeds those build outputs; it has no handwritten alternate document renderer. Export codecs and the reader bundle load with the main application so an already-open document can export even after the browser goes offline. This increases the initial bundle; it does not add HTTP caching, a service worker, or fresh-load offline support. No export dependencies were added.

The minimap shares the rendered page through an inert, noneditable DOM snapshot, with editing controls and accessibility duplicates removed. Both sizing modes share this renderer and navigation geometry. Proportional mode keeps the page's aspect ratio and scrolls the miniature for long notes; fit mode compresses only the vertical axis as needed. Main-document zoom changes the viewport indicator, not miniature content scale. Scroll-only updates translate the existing snapshot and indicator; layout/content changes refresh the snapshot once per animation frame.

Editing allows scrolling past the document bottom until it sits about 15% down the canvas viewport. This view-only room adapts to viewport height, shares clearance with the Notes overlay, and never changes document geometry or exports; reading/mobile retain their normal bottom clearance. The minimap keeps the real page snapshot and tracks the full scroll range.

Blank documents show **Start writing…** in their sole empty paragraph and focus it on opening. Clicking unused space below the final main-flow block, outside the left selection margin and into the scroll-past-bottom area, continues writing at the logical end—not at the clicked height. A final paragraph receives the caret at its text end. A final explicit space or Flow object (including its caption) offers a temporary Body writing position with a **Continue writing…** hint. Clicking alone changes neither content, page geometry, history, nor exports; typing/pasting commits normal paragraphs, and Enter commits an empty paragraph plus the next writing line. Escape or clicking away dismisses the uncommitted caret. Floats keep their own interactions and can extend the visible page without changing the main-text destination. Side gutters, modifiers, creation tools, and reading/mobile keep their existing behavior. Placeholders and tail hints are omitted from minimap snapshots and exports.

## Deployment

The current app is live at **https://mote.ylxdzsw.com**. Nginx serves `/var/www/mote` using `/etc/nginx/conf.d/mote.conf`, with the existing wildcard origin certificate and workspace cookie gate. Documents/AI require login; explicit shared reader URLs bypass it. Deployment includes the durable `moted` service, with no scheduled backups. See [CLOUD.md](CLOUD.md) for manual backup and restore instructions.

The deployment sets `Cache-Control: no-store` and disables Nginx ETags/expiration for HTML, JavaScript, CSS, and fallback responses. Cloudflare receives the origin directive and currently reports `DYNAMIC`/`BYPASS`, so the pre-release build is not cached at the edge. There is no service worker. Intentional IndexedDB document persistence is separate from HTTP caching. For each task, build with `npm run build`, publish `dist/` assets to `/var/www/mote` before replacing `index.html`, then run `nginx -t && systemctl reload nginx`. Verify the live HTML and its referenced assets against the build and check `Cache-Control: no-store`. Publish files with Nginx-readable permissions (normally 0644; for example, `install -m 644`), rather than preserving restrictive source permissions. Keep backend code outside the static directory. Restart `moted` only when backend changes require it, after checking active tasks/workers; preserve cloud documents, AI state, and manual backups. See [Storage and service](CLOUD.md#storage-and-service).

Vite development and preview responses also send `Cache-Control: no-store`. `public/_headers` carries the same rule for static hosts that support that format. Other hosts must explicitly set `Cache-Control: no-store` on **all** responses, including HTML and built assets.

Review the early-development decisions in `.mu/AGENTS.md` before a release.

## Verification

Run `npm run build` for TypeScript checking and both production bundles. Run `npm run test:ai` for essential Flow/clipboard/caption, reservation, transport recovery, fake-backend, cloud CAS/privacy, indexing, and retrieval invariants without real model calls. The backup tests use isolated temporary data; they do not back up production. Test definitions in `package.json` and `tests/`/`server/*.test.mjs` are the source of truth for automated coverage.

For UI changes, use an isolated fake backend and a scoped Chromium check against dev or the production preview. Set `MOTED_DEV_ORIGIN` to the browser's exact origin, including the preview port. Exercise the changed interaction, undo/redo and persistence where relevant, desktop and compact editing (including 768px), and fresh mobile reading below 768px. Review rendered output and browser errors. Changes to layout, objects, captions, or the document schema also need the affected shared-reader, minimap, clipboard, native/HTML round-trip, and PNG paths checked. Use focused checks for the changed invariants; there is no general browser regression suite.

Browser automation does not certify native OS IME behavior, physical trackpad gestures, or Safari/Firefox rendering. System fonts can alter wrapping, and PNG raster support varies by engine. Development notes in [.mu/MEMORY.md](.mu/MEMORY.md) record historical checks and limitations; they are not a claim that every old fixture or interaction still exists.

GitHub Actions runs on push, pull request, and manual dispatch. On Ubuntu with Node.js 22 and 24, it installs the lockfile with `npm ci`, runs `npm run build`, and runs `npm run test:ai`. Only npm's download cache is reused. CI does not deploy the demo, run browser checks, or call model providers. See [.github/workflows/ci.yml](.github/workflows/ci.yml).
