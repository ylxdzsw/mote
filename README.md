# Mote

[![CI](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml/badge.svg)](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml)

A local-first demo exploring semantic text and anchor-relative spatial placement.

## Run

Use Node.js 22.12+ (or a current release) and npm.

```sh
npm install
npm run dev
```

Open the URL printed by Vite, normally `http://localhost:5173` (it selects the next port if occupied). The development server listens on all interfaces for previews; do not expose it as a production server. Keep the same origin between sessions to access the same local draft.

```sh
npm run check   # TypeScript
npm run build   # TypeScript + production bundle in dist/
npm run preview
npm run test:ai # Essential reservation and fake-backend checks; no model calls
```

## Optional AI assistant

The toolbar has two distinct AI buttons: **AI insert or replace paragraphs** replaces all paragraphs touched by a text selection, or uses the whole paragraph at the caret when the selection is empty (including an existing empty line); **AI draw or replace floating object** revises the selected object, or arms a drawing tool when no single object is selected. Creation stays in the toolbar; the AI sidebar contains one tab per reserved agent session. Describe a research, writing, formula, table, or interactive-object task and choose **Generate**. **Document → Layout → Mu model** accepts a raw Mu model reference; empty uses `codex/gpt-5.6-luna`. The model setting belongs to the document and round-trips through `.mote` files; credentials do not.

Tabs retain requests, streamed agent output, and follow-ups within the same session. New reservations activate their tab; **Request…** on a reserved region opens its matching tab, and **Locate** selects and reveals that region. Arrow keys/Home/End navigate the tab strip. Draft requests and tab order survive reload. Background completion updates status without changing the active tab. **Stop** and errors retain the reservation; **Accept**, **Discard**, and explicit region deletion release it and close its tab. Closing the pane only hides it; after the last reservation is released, the ordinary inspector returns. Deleting a reserved floating object with Delete/Backspace, or choosing **Delete region** in its on-document controls, abandons its task. Paragraph controls also provide **Delete region**. Undo restores deleted document content as ordinary content, never an agent session or its reservation. Ordinary cross-boundary typing/cut/history edits remain protected.

The read-only transcript uses lazy-loaded `ansi_up`, not a terminal emulator or an interactive shell. Mu's piped `-o concise` output is append-only; ANSI styling is supported, raw HTML is escaped, and terminal hyperlinks are disabled. Output follows the bottom until you scroll up; **Latest** resumes following. Only the active tab has an SSE connection, while background tasks keep their existing status polling. Switching tabs/reconnecting replays missing events; earlier requests stay visible across revisions. Transcripts have bounded retained history with omission/failure notices, and are separate from document persistence and exports. Candidate validation—not transcript text—still determines readiness. Sign-in and data-sharing details are under **About AI · Sign in**, with actionable sign-in feedback on authentication failures.

Generation sends the **entire document**, including embedded assets, and a full rendered PNG snapshot. The agent also receives the selected area/position/dimensions or whole-paragraph text selection, the [Mote task guide](server/guide.md), read-only source access, environment/writable-path information, and a validated output contract. Nothing is uploaded merely by opening the assistant or drawing an area. Ordinary editing, reading, persistence, and exports do not require AI or a login.

Concurrent tasks reserve nonoverlapping content through generation and review. You may edit other regions and move reserved objects. Before the first request, reserved floating areas can also be resized; starting generation freezes their dimensions while the snapshot is prepared. Once a request has been sent, size stays locked through review, including after Stop. Their content stays locked throughout. Text selections expand to whole consecutive paragraphs in both the reservation and the agent request; partial-paragraph replacement is not supported. Selections crossing spacers are not supported. Paragraphs (including empty lines) and floating objects share the same striped reservation treatment. Reserving or discarding an empty paragraph does not add or remove a paragraph. Cross-boundary edits and history operations that would change a reservation are blocked. Initial generation targets one floating object or a paragraph range, not a multi-object native diagram transaction.

Ready candidates appear automatically **in place on the editing document**, without modifying its saved content. Selecting a reserved object, placing the caret in reserved text, or clicking/tabbing into a paragraph candidate reveals **Original / Candidate**, **Accept**, and **Discard** controls. These use compact on-document buttons, with no reservation-status title; the sidebar remains available for requests and follow-ups. Paragraph previews reflow the document and its anchored objects; floating previews follow the current placement. Generated widgets execute only in sandboxed, opaque-origin frames. Reading and exports use the accepted document, not pending previews. **Accept** makes one document-history change while preserving unrelated edits and current placement. **Stop** retains any previous complete candidate; **Discard** releases the reservation and removes a newly drawn floating area; existing paragraphs and objects remain. Follow-up requests reuse the task's Mu session when available. Accepted objects are ordinary Mote objects. Drawn floating areas use ordinary draft placeholders; pending candidates and task records are separate from document exports. Browser-local task recovery reconnects after reload; reset/import abandons old tasks. Server workspaces/results expire after 24 hours by default and are not cloud document storage.

Drawn areas are generic **New floating object** requests, not specifically figures or HTML widgets. New candidates may use KaTeX, text, table, rectangle, ellipse, line, label, image, or HTML. The agent guide explicitly prefers native KaTeX for formulas, with a direct LaTeX delivery example and no screenshot requirement. Existing-object revisions retain their kind. The first object request captures the current document and resized area; later follow-ups reuse that immutable snapshot.

### Fake-first development

Run the app at the exact development origin below and start a fake service in another terminal:

```sh
MOTED_FAKE_RUNNER=1 MOTED_USE_SYSTEMD=0 MOTED_PORT=5174 \
  MOTED_DEV_ORIGIN=http://127.0.0.1:5173 \
  MOTED_STATE_DIR=/tmp/moted-dev node server/moted.mjs
```

Vite proxies `/api/ai` to port 5174. The fake runner is selected only by server environment, never by a request parameter, and makes deterministic visible changes without calling Mu. `npm run test:ai` exercises the critical reservation, cancellation, validation, and task lifecycle invariants without a browser, systemd worker, or provider call.

### Pre-release service

Production AI calls are deliberately fixed to `https://mote.ylxdzsw.com/api/ai`. Nginx uses the existing `nginx_auth` cookie gate for AI endpoints; `/ai-login` serves the existing login flow. Mutations also require the exact allowed Origin. The ordinary static app remains public. The shared cookie represents one trusted deployment, not separate user accounts. Other static deployments work without AI; connecting their AI UI requires changing the pre-release endpoint/origin policy.

`moted.service` runs the Node supervisor from `/root/mote/server/moted.mjs`, listening at `/run/moted/moted.sock`. Each task runs Mu and its own Chromium browser as the unprivileged `mote-ai` user in a transient systemd service. Host/source/shared `.mu` reads are allowed, but host writes are restricted; writable paths are private `/tmp` and the task's output, journal, and cache directories. PID isolation prevents accidental cross-task process operations. CPU, memory, process-count, and deadline limits apply; stopping a worker terminates its control group. Configured root-only Unix-socket LLM providers get narrow task-local relays, without changing host socket permissions. Credentials are copied into the task-local Mu scope; broad host reads and outbound networking are intentional, so this is accidental-damage containment, not hostile-agent isolation or an exfiltration barrier.

See [service](server/moted.service.example) and [Nginx](server/mote-ai.nginx.example.conf) configuration examples. Defaults are two simultaneous workers, 15 minutes per run, 2 GiB memory and 200% CPU per worker. Inputs are bounded to 64 MiB; result JSON to 8 MiB and screenshot files to 10 MiB. Workers use the [preview helper](server/preview.mjs) and [delivery checker](server/check-result.mjs) to test widgets in Mote's iframe sandbox and deliver an exact-sized screenshot. Task journals and private artifacts stay under `/tmp/moted`; they are not publicly served. Inspect service failures with `journalctl -u moted.service` and task-specific `logs/` locally.

`GET /api/ai/tasks/:id/events?after=N` serves the cookie-gated SSE transcript. `Last-Event-ID` takes precedence on automatic reconnect. `transcript` events contain `{ id, attempt, kind, text }`, where IDs increase within the task, attempts start at 1, and kind is `request`, `stdout`, or `stderr`. Requests are recorded when queued, even if stopped before a worker starts. `reset` indicates that the cursor is outside retained history; `warning` reports output limits or storage failure. Heartbeats run every 15 seconds. Nginx buffering stays disabled and stream responses send `no-store, no-transform`. Only selected Mu output is exposed, not raw session/provider journals or configuration. Task mutations are serialized so discard/delete cannot race a revision into an orphaned worker.

Server transcript defaults are 2 MiB / 2048 events, at most 128 KiB per event and 256 pending writes; slow SSE clients disconnect at 128 queued events or 512 KiB. Per-attempt stdout/stderr logs each retain at most 1 MiB, with old logs trimmed to a 4 MiB task-wide default after each attempt. Environment overrides are `MOTED_TRANSCRIPT_MAX_BYTES`, `MOTED_TRANSCRIPT_MAX_EVENTS`, `MOTED_TRANSCRIPT_MAX_EVENT_TEXT`, `MOTED_TRANSCRIPT_MAX_PENDING`, `MOTED_TRANSCRIPT_HEARTBEAT_MS`, `MOTED_LOG_MAX_BYTES`, and `MOTED_LOG_TOTAL_MAX_BYTES`. Frontend history is capped at roughly 512K text characters / 2000 chunks per tab. Task-local transcript replay survives supervisor restart within the existing task lifetime; it is not permanent chat storage. Missing backend sessions offer accept/discard rather than an endless retry. If server cleanup fails, local release remains final and a notice explains that unconfirmed work expires automatically.

Menus preserve selection and support keyboard navigation.

The inspector offers the current paragraph style and **Document palette…**; the toolbar color menu also opens the palette. **View** keeps browser-local preferences separate.

Inline Bold is always 700; font family, size, spacing, and inherited weight come from the paragraph. Box uses a thin current-color border and the selected family’s Soft tone, or Subtle for inherited/neutral color; Underline follows the text color. The Box icon contains an A. Browser selection highlights may extend to the full paragraph line height, so they are not the same boundary as this font-sized decoration. Decorations wrap with the text rather than becoming indivisible pills.
- One document palette supplies all native color settings: four neutral swatches (Ink, Muted, Subtle, Paper), plus named Strong/Soft families (initially Key idea, Detail, Term, Caution). Raw opaque colors are editable only in the palette. Paragraph/default/math styles and shape, line, and text-box colors store palette references; changing a swatch updates every use, including the minimap and exports. Sidebar color fields show direct palette rows: Strong and Soft swatches side by side, followed by a clickable name that chooses Strong. Neutral colors have one swatch. Native radio semantics provide keyboard navigation and selected-state announcements; focused swatches participate in document undo/redo. None/Default and family-deletion replacement also use direct rows. The compact inline color popup still exposes Ink, Muted, and family Strong tones. None/transparent and Inherit/Default are separate behaviors, not colors. Families can be added, renamed, recolored, or deleted with replacement of references in one undo step; the four neutrals remain. Shape fills can use the matching Soft tone without becoming linked to their border. Palette previews warn about text contrast against Paper and matching Soft; other backgrounds may differ. Embedded images and HTML widget content remain independent.
- **Code** is a plain-text paragraph/block with a monospace default and preserved whitespace. Enter and Shift+Enter insert a newline within the block, Tab inserts two spaces, and Ctrl/⌘Enter inserts a Body paragraph after it. Backspace at the block start returns it to Body. Code strips phrase marks and pastes plain text; line breaks survive changing the class back to Body. Code typography is controlled centrally by its theme class.
- **List** is an independent unordered-list item, not a child of a list container. Enter splits it into a new same-level item, including when the item is empty. Shift+Enter adds a line aligned with the item's text start. Tab / Shift+Tab or the toolbar arrows indent/outdent selected items independently, without changing neighboring items. Backspace at the start reduces one level; at the top level it returns the item to Body without deleting its text. Each level adds 24px indentation, never a font-size change. Top-level markers are solid dots; all sublevels use hollow dots. Pasted unordered lists flatten into independent paragraphs; ordered-list paste becomes Body text. Code and List work in main and floating text, while tables always use Table.
- Borderless vertical spaces live at paragraph breaks. Hold **Alt** near a break and drag down to open a gap. Alt-drag anywhere in an unoccupied space, or on the first text line immediately below it, to resize it: down adds room, up removes it. The top stays fixed and following content moves. Gaps below **12 document pixels** are removed on resize release; normal theme paragraph spacing remains. Adjacent spaces merge, including after intervening text is deleted, preserving total height and floating-object offsets. Text always sizes naturally; there are no reserved/minimum text-segment heights. A small Alt-only margin cue identifies insertion points, and a transient size/removal hint appears during dragging. Spaces have no individual selection state or inspector, but can be included or split in a segment selection.
- **Segment selection:** drag the 24-screen-pixel strip immediately outside the page's left edge. Clicking alongside a paragraph selects it; dragging extends through whole paragraphs. Normal endpoints snap to any paragraph boundary or either edge of an explicit space. **Alt** additionally permits positions inside explicit spaces; it never splits paragraphs. Clicking alongside a space or theme gap without dragging leaves no segment selected; empty segment selections are not allowed. Top/bottom handles adjust the selection with the same snapping but cannot collapse it; focused handles also support Up/Down and Home/End, with Alt allowing 1px steps inside spaces. The cursor and handles share a right-pointing marker. Edge dragging auto-scrolls; Escape cancels a drag or clears a finished selection. The highlight is continuous across the selected range, including theme-generated gaps; those gaps remain destination-theme spacing rather than copied explicit spaces. Included floating objects are highlighted in full by anchor ownership, even beyond the main-text band; objects merely intersecting it are excluded. Attached labels follow their targets; lines follow their connected start target or free start anchor. A split-space boundary belongs to the trailing portion, and the final portion owns objects extending beyond that space.
- **Segment clipboard:** Ctrl/⌘C and X copy/cut the active segment; V replaces it. Pasting keeps the inserted segment selected, including exact partial-space boundaries after adjacent spaces merge. Cutting clears the selection but retains the cut location for a following paste. Cut/paste preserve explicit-space heights, including pieces shorter than the space-resize removal threshold, and each is one document undo step. Native segment paste in the main editor inserts before the caret's paragraph (after it at a nonempty paragraph's end), or replaces whole selected paragraphs; it never merges into paragraph text. Pasted objects and blocks receive fresh IDs, internal connections remain internal, and external connections detach. Destination paragraph styles and neutral palette roles apply; referenced color families are reused or imported without changing existing destination colors. Clipboard data includes a native V0 payload, an HTML-carried equivalent, and a plain-text fallback. Ordinary text paste remains in text editors, not the segment insertion marker. Segments touching AI reservations cannot be copied, cut, or replaced until those tasks are accepted/discarded. Selection is transient and absent from saved documents, minimaps, reading, and exports.
- Rich-text floating boxes anchored to main-text blocks. Choose **Text box**, then drag across the page to set its initial width (120px minimum where space permits); height follows text. New boxes start empty with the caret inside. Their per-object background and border colors both default to transparent and can be changed or cleared in the inspector. Editing outlines are separate from the saved border. An unselected object can be dragged from its interior to move it; clicking once selects it without placing a caret. Once selected, clicking or dragging inside edits/selects text instead of moving the object. Click elsewhere on the page to deselect and move it again. The **top, left, or bottom border always moves**, and the **right border resizes**; no extra movement handles or expanded border targets are used. There are no delete buttons, corner resize handles, or anchor markers. Focused objects move with arrow keys (Shift for 1px); their right borders support left/right arrows for width. Press Delete/Backspace with the outer object focused to remove it immediately; Undo restores it. Undoable actions do not ask for confirmation.
- Floating images share the same anchor, drag, resize, and delete behavior. Drop one or more local images onto the document, or use **+ → Image** to choose a PNG, JPEG, WebP, GIF, or AVIF (up to 10 MB per file); images are embedded in the browser-local draft without an upload. An explicitly requested AI task includes them in its full-document snapshot. A multi-image drop is one undo step, uses the drop position at any zoom, and rejects the whole batch if a file is invalid. Resizing preserves proportions. Select an image to edit its accessible description or replace its file in the sidebar.
- Floating tables use the same selection-first interaction as text boxes: drag an unselected table from any cell to move the table; select it first to edit/select cell contents or resize internal column dividers. Once selected, click a cell, use Tab / Shift+Tab to navigate, and add/remove rows or columns through the sidebar. Every cell uses the global **Table** paragraph class, independent of Body but with the same preset. Table is available in the theme editor and through **Table style…**, never in the normal paragraph-class dropdown; the toolbar shows a fixed Table label inside cells. Composable **Bold**, palette colors, and **Box/Underline** remain available. Each cell contains exactly one paragraph: Enter, Shift+Enter, and Ctrl/⌘Enter insert soft newlines, not paragraph spacing. Pasted paragraphs/headings flatten to newlines while preserving text and supported inline marks. Pasted table/spreadsheet ranges still fill separate cells. Tables support cell selection, rich-text paste, and document-wide undo/redo for text and row/column changes. The last row and column cannot be removed through the sidebar; delete the floating object to remove the entire table.
- Rectangles, ellipses, lines, and labels are regular floating-object kinds, sharing anchoring, movement, selection, marquee selection, grid snapping, ordering, persistence, undo, zoom, and minimap behavior with text, images, and tables. Rectangles can be square or rounded; ellipses can be circles; both have per-object fill/stroke colors, width, and Solid/Dashed outlines. Lines can be straight or simple elbow routes, have per-object stroke settings, arrows at either end, draggable endpoints, and optional connections to floating objects. Default strokes follow the Defaults font color; shape fill defaults to None. Labels are single-paragraph rich text using the fixed Label class (Caption-equivalent presets, independently editable), never wrap automatically, and can attach to object center/top/bottom or to line center/left/right/above/below positions. Labels fit their text height and show a hover outline in editing mode. Top-outside and bottom-outside attachments use a gap of one third of the resolved Label font size (4px at the default 12px); inside and line attachment gaps remain 8px. Double-clicking an attachable object selects or creates its label; labels can be detached and remain independently movable. Like text boxes and tables, an unselected label moves by dragging its text; once selected, its text accepts ordinary caret placement and text-selection drags. Enter finishes label editing and Shift+Enter inserts a soft break. Empty/whitespace-only labels and text boxes, including zero-width-only text, disappear when editing/selection ends; blank formulas are cleaned up on deselection. Empty tables retain their editable grid. Abandoned empty content is also cleaned up when opening a draft for editing, never by reading-only views. Zero-length line gestures do not leave invisible objects.
- A **page-wide 16px dot grid**, with one origin at the document's top-left, appears only while dragging or resizing floating objects, including creation and table-column resizing. Objects snap to that same grid in both text and space areas; Alt bypasses snapping but not page bounds. Resizing or merging spaces never moves the grid origin. Selection, text editing, hover, marquee selection, reading mode, and the minimap do not show it. Dragging unoccupied document padding (all four sides), inserted space, or the surrounding gutters, outside the left segment-selection strip, starts rectangular marquee selection for any floating kind; Shift adds. Transparent shape interiors are click-through, while filled shapes and images can be moved from their interiors. Marquee and group movement preserve relative positions, and attached line endpoints/labels follow their targets.
- **Table columns** resize by dragging internal dividers, adjusting only the two adjacent columns while preserving total table width. The outer right border resizes the whole table proportionally. Dividers support Left/Right arrows (Shift for 1px), a 40px minimum where space permits, and Escape cancellation; zoom/mode changes cancel an active drag. Drag previews are transient and each release is one undo step. **Left / Center / Right** in the inspector aligns the entire column containing the caret, or all columns intersecting a rectangular selection. Mixed alignment leaves all three buttons inactive. New columns start left-aligned with an equal-share weight; adding/removing columns preserves the relative widths of surviving columns. New rows follow existing column alignment.
- Configurable document width (320–2400px, initially 960px) and four margins (initially 48px each). Left/right main-text margins can be linked or edited independently and always leave at least 120px for text. Top/bottom margins are independent (0–2400px): top spacing precedes main text, and bottom spacing follows the last main-text block or lowest floating object. The page remains continuous, without a minimum page height or branding footer; explicit spaces are retained. Changes are immediate and locally saved, with no Apply/Cancel stage.
- One chronological undo/redo history covers text across editors, paragraph/inline formatting, table structure, layout/theme changes, space insertion/resizing/removal, and floating-object creation/deletion/geometry/image changes. Numeric-field focus sessions, color adjustments, and continuous typing are grouped; each released layout drag is one step. Toolbar Undo/Redo and Ctrl/⌘Z / Ctrl/⌘Shift+Z (also Ctrl/⌘Y) work across editor focus and panel closing. Text/numeric settings inputs keep native input undo. History keeps up to 100 steps in memory and is cleared on reload or confirmed Reset to example; saved documents do not contain history.
- A live minimap on the right of the canvas shows text, semantic colors, whitespace, and floating boxes. Click a region to navigate or drag the shaded viewport to scrub vertically; horizontal position and editor selection are preserved. Wheel scrolling and keyboard arrows, Page Up/Down, Home/End work over the minimap. There is no hover popup. Native canvas scrollbars are hidden; wheel, touch, and trackpad scrolling remain available.
- The inspector, document settings, and AI assistant occupy the left sidebar; the minimap stays on the right in editing, reading, and standalone HTML. Small main-text heading bookmarks extend leftward toward the document, folding to 10px tabs until the minimap is hovered or a label receives keyboard focus. Expanded labels are up to 90px wide (60px on mobile when explicitly shown), with 9px text. Labels take no horizontal layout space and can overlap the centered document; the expanded label lane keeps them open while crossing gaps, and folds away on pointer exit. Floating notes remain visible in the miniature but do not contribute bookmarks. The current heading changes at a focus line 15% down the canvas viewport, capped at 120px; clicking a label aligns its heading to that line without changing horizontal position or text selection. Labels follow live edits and the miniature's scroll position; nearby labels spread out to stay readable. A very dense bookmark overlay can scroll independently over its labels. Full heading text is available in each label's tooltip and accessible name.
- Global settings under **View** offer faithful-proportion (default) and fit-whole-document minimap sizing, plus automatic/show/hide visibility. Automatic hides at viewport widths of 1050px and below, including mobile. Configure these preferences in editing mode; they also apply to in-app reading. Preferences live in browser-local storage, separately from the V0 document.
- Fixed app frame with independently scrolling document canvas and settings. In editing mode, zoom controls live in the top bar between save status and the mode selector; reading keeps the zoom gestures/shortcuts without a toolbar. The percentage always shows the actual scale. Its dropdown starts with **Auto** (the editing default), followed by 25%, 50%, 75%, 100%, 125%, 150%, 200%, or 300%. Auto fits the available canvas width, capped to keep at least 600 document pixels visible vertically and at 300%. It follows viewport, panel, and document-width changes. Zoom only the document using these controls, Ctrl/⌘ + wheel, pinch, or Ctrl/⌘ +/−; manual zoom leaves Auto and stays fixed across resizes. Ctrl/⌘ 0 restores Auto. Incremental zoom snaps near both 100% and the current calculated Auto scale without enabling Auto; continued zooming moves past either detent. Explicit presets stay exact. The page lays out at native document size and uses transform scaling, so zoom does not change text wrapping; a scaled outer footprint handles scrolling and centering. Zoom is view state, not saved document geometry.
- Desktop editing/reading modes; viewports under 768px are reading-only. Reading hides the top bar and all settings panels, with the **Edit / Read** switcher floating in the same top-right position as in editing mode (or **Try editing** there for tabs without ownership). Mobile and exported HTML have no mode switcher. Local save failures remain visible and retryable in preview. Reading has no visible page border or shadow and no outer left/right canvas padding; the document background fills the viewport, while document width, internal margins, wrapping, and spatial geometry stay unchanged. The minimap and heading navigation remain available; return to editing for File/View controls. On loading or first entering reading mode, zoom starts at the smaller of Auto and 100%, then stays fixed until changed. Reading Auto still fits the full document, including its internal margins, without any extra outer side gutter; selecting Auto or pressing Ctrl/⌘0 uses the uncapped Auto calculation, and its snap point remains available. Zooming in progressively crops only unused document-side margins before horizontal scrolling begins: the content span is the main-text area plus floating-object bounds, including attached labels, strokes, arrowheads, and overflowing formulas, limited to the existing page edges. With a 960px document and otherwise empty 48px side margins, that span is 864px. Unequal unused margins shrink proportionally, without reflowing or moving document content. Editing keeps its original gutters. Editing and reading independently remember their session zoom settings, including Auto; switching modes restores the destination mode’s setting. PNG retains the full native page and margins; standalone HTML shares the adaptive reading viewport.
- A single browser-local draft in IndexedDB, written after each document update by the editing tab. With Web Locks available, other tabs read without saving and offer **Try editing**; acquiring ownership reloads the latest saved draft with fresh undo history. Without Web Locks, concurrent editing is silently allowed. Save errors are visible and retryable. Ctrl/⌘S is a no-op throughout editing and reading modes, including settings fields; it does not open the browser Save dialog or change the document.

Direct insertion uses the last main-text caret as its starting anchor, even when a floating object is selected. Repeated insertion stays available. Spaces are created/resized with Alt-dragging, not through the object menu. Spaces span the page, including its text margins. Clicking one preserves the text caret rather than selecting the space. Ordinary dragging inside text still selects text; ordinary dragging inside document padding, a space, or either side gutter selects floating objects. Object interactions take precedence over gap manipulation, and an object drag keeps its original meaning when Alt is pressed to bypass snapping. Floating text and tables share the main text’s composable inline toolbar and document palette. In editing mode, object selection gates content editing/interaction for text boxes, tables, labels, and HTML widgets. Images, shapes, lines, and formulas remain movable when selected because they have no on-canvas content editor. Reading mode remains directly selectable/interactive without object selection; AI-reserved rich text stays locked.

## Model and boundaries

### English and Simplified Chinese

Mote is English-first, with horizontal mixed English/Simplified Chinese document text. **Document → Layout → Text language** selects English (the default) or Simplified Chinese for the document content, without changing the interface. This language applies to the shared page, including floating text, tables, labels, minimap snapshots, PNG, and standalone HTML. There are no per-passage language controls or automatic language detection. Vertical writing and language-driven right alignment/RTL layout are non-goals; ordinary table-column alignment is unchanged.

The three semantic typeface choices use installed fonts, not downloaded or embedded document fonts:

- **Sans serif:** English documents prefer Inter, Segoe UI, Helvetica Neue, Arial, Noto Sans, and Liberation Sans before the Chinese fallbacks. Simplified Chinese documents prefer Microsoft YaHei first. Both retain PingFang SC, Noto Sans CJK SC / Noto Sans SC, and system sans serif fallbacks. This keeps English curly apostrophes narrow while retaining Chinese glyph coverage.
- **Serif:** Georgia for English, with Songti SC, SimSun, and Noto Serif CJK SC / Noto Serif SC for Chinese, then the system serif fallback.
- **Monospace:** system monospace, SFMono-Regular, and Consolas, with Sarasa Mono SC, Noto Sans Mono CJK SC, and Microsoft YaHei fallbacks. Chinese glyph coverage and cell-width alignment are best-effort.

Prose uses normal word breaking, strict CJK punctuation breaking, and emergency wrapping for long unbreakable strings. Labels retain their explicit no-wrap behavior. **Theme → Defaults → Mixed-script spacing** defaults on and uses CSS `text-autospace` to add visual gaps between Chinese and Latin letters/numbers where the browser supports it. It never inserts spaces into stored or copied text. Code disables automatic spacing and retains literal whitespace. Title and Heading presets no longer apply negative tracking; existing saved theme overrides are not rewritten. Theme samples include mixed English/Chinese text. System-font availability and browser typography support can still change wrapping across devices; no identical-layout guarantee is made.

Editor composition transactions are grouped by editor and composition identity, without the ordinary typing timeout splitting a paused conversion. Global document shortcuts yield to composing/process-key events, table paragraph-input handling yields to composition, and document-history navigation waits until composition ends. Scoped Chromium checks use browser composition injection, not a native OS candidate window; Windows/macOS input methods and Safari/Firefox still need hands-on verification.

### Formulas and HTML widgets

**+ → KaTeX** inserts a floating display-mode formula. The inspector edits its LaTeX source live, without `$$` or `\[...\]` delimiters; syntax errors retain the source and appear on the object. Width is user-controlled and height follows content. Formulas are centered, never automatically wrapped or shrunk, and can use explicit constructs such as `aligned`. Oversized content follows the existing page-edge cropping policy. **Math style…** opens a global size/color style inherited from Defaults, with px/em units and normal history/reset behavior; math typefaces remain KaTeX's. KaTeX's unsafe HTML commands are disabled (`trust: false`). The renderer and WOFF2 math fonts are bundled for offline HTML and PNG. This is not a full LaTeX document engine, and inline mathematics is not included.

**+ → HTML widget** first asks for a screenshot, using the same embedded-image formats and 10MB limit as image objects. The new widget starts with an editable button-counter demo. **Edit code…** opens one HTML/CSS/JavaScript source field; drop a single `.html` or `.htm` file into that field to replace the source in one document-undo step. Source edits save immediately, while **Run / Restart** recreates the iframe and executes the current source. Dropping a file does not run it or replace the screenshot. Each widget has its own DOM, CSS, globals, and libraries. Moving, resizing, selecting, changing mode, and front/back ordering retain its running state. Runtime interaction state is not saved or included in document undo; reopening starts from saved source.

HTML widgets have independent width/height controls and corner resizing. Their iframe viewport follows the saved dimensions, while page zoom scales the entire widget. In editing mode, click/drag an unselected widget’s noninteractive interior to select/move it. Selection directly enables its contents for subsequent clicks and drags, without a separate interaction mode or button. Clicking elsewhere on the page deselects it and makes its interior draggable again. Selection and movement never restart the iframe; only Run / Restart or an explicitly restored source revision replaces its execution. Reading/mobile interiors are directly interactive. Each iframe uses `sandbox="allow-scripts"`, without access to Mote's DOM/storage or top-level navigation. This prevents namespace collisions and limits access, but is not a CPU/memory quota or a promise that arbitrary code cannot affect responsiveness.

Resource references, including CDN scripts and external data, are used as written. Mote does not inspect widget source, bundle or rewrite external resources, or guarantee offline operation for network-dependent demos. Normal browser resource restrictions still apply. There is no separate ECharts object or bundled chart library: authors can embed ECharts with their own script reference.

The example formula exercises aligned equations, fractions/roots, scripts, Greek letters, sums/binomial coefficients, integrals/derivatives, matrices, underbraces, cases, and vector notation. The two example widgets load pinned ECharts 6.0.0 from jsDelivr: **A week of attention** uses an `<attention-chart>` custom element with shadow DOM, a measure selector, legend filtering, tooltips, and bar-click details (also emitting `attention-select`); **Ideas in motion** animates a repeating six-pass bar ranking with value interpolation, Pause/Play, and Next pass. Reduced-motion preferences disable transitions and start the ranking paused. Their HTML sources and manually captured PNG previews live in `src/document/examples/`; no chart dependency is bundled. To refresh a preview, open its HTML at 690 × 400 and capture that viewport (the ranking preview shows paused pass 4).

The author-supplied screenshot is required and used for the minimap and PNG export, stretched to the object's saved rectangle. **Replace screenshot** updates it explicitly; authors should supply a matching aspect ratio and refresh it when needed. Mote does not capture widget HTML or verify that a screenshot matches the source/current state. Minimap snapshots remove live iframe content before insertion; PNG mounts a screenshot-only reader and never starts widget code. HTML exports keep live widgets, not screenshot substitutes. Both kinds share ordinary floating selection, anchoring, movement, grid, overlap/repel, labels, line connections, ordering, duplication/deletion, and document history.

### V0 representation

Optional `language` is `en` or `zh-Hans` (omission means English). Optional `theme.autospace` is a boolean (omission means enabled). Both persist with the document, participate in history, and are validated on draft initialization and native import. They require no text rewriting or schema migration.

KaTeX objects store `kind: 'katex'` and `latex` alongside shared floating geometry. HTML widgets store `kind: 'html'`, `html`, embedded `screenshot`, accessible `alt`, and explicit `height`. Math overrides live in `theme.blocks.math`; omission means inherited size/color, without rewriting the draft. Native import checks these fields and screenshot safety, but intentionally does not sanitize executable widget source. The `.mote` file contains source and screenshots, never live iframe state or run counters.

`MoteDocument` contains a `version: 'V0'`, width, left/right margins, theme defaults, paragraph-class overrides and the document palette, main-text editor JSON, and floating objects. Each main-text block has a stable UUID. Each floating object stores an anchor UUID (or a document-top null anchor), absolute document-space x, nonnegative anchor-relative y, width, and Overlap/Repel text-flow behavior where applicable. Text/table objects store constrained rich-text content; text boxes also store optional `background` and `borderColor` colors (null or omitted means transparent); images store an embedded source and accessible description; rectangles and ellipses store height, fill, stroke, stroke width, dash style, and rectangle corner style; lines store two anchor-relative endpoints, optional object connections, route, bend, arrowhead settings, and stroke settings; labels store constrained rich-text content and an optional attachment. A label is a single paragraph with fixed `label` semantics. Attached geometry is derived from current target layout, not saved as an absolute page position. An omitted kind denotes a text box. Tables have their own constrained schema: one table, exactly one paragraph per cell, no editable paragraph semantic attribute, and the shared composable inline marks. The table node stores a `columns` array of `{ width, align }`, with normalized proportional widths and left/center/right alignment. An absent array means equal-width, left-aligned columns. Column commands update structure and metadata in one transaction; rectangular paste extends metadata when it grows the table. Rendering uses a colgroup and column-wide cell decorations, with noneditable divider controls excluded from the minimap. Images use their intrinsic aspect ratio; tables grow vertically with their cell content.

Code and List retain the flat `paragraph` node and stable block UUIDs. A list paragraph stores `semantic: 'list'` and a zero-based `listLevel`; there are no list containers, ownership relationships, or nested item nodes. Code stores `semantic: 'code'` and unmarked text/soft breaks, rendered as `pre > code`. These blocks participate in the existing anchor, repulsion, space-flow, minimap, persistence, and shared undo systems.

Each spacer stores a stable block UUID and a `height` in document pixels. Consecutive spacer nodes normalize to one, summing heights and transferring objects and line endpoints to the retained anchor with their offsets preserved. Text has no saved height or capacity reservation. The 12px removal threshold applies at gesture completion, not as a side effect of changing typography. Old V0 text-height reservations are no longer interpreted; V0 makes no layout-migration promise.

Gap previews use transient editor decorations; creation previews do not insert saved document nodes. Resizing an existing gap adds or removes room at the drag's starting position: floating objects and free line endpoints at or below that position move by the height change, while those above stay put. Later main-text anchors move normally, and attached labels/connected endpoints follow their targets without moving twice. Upward dragging can produce overlap, but anchor-relative offsets remain nonnegative. Mouse release commits once, even if Alt has already been released. Escape, pointer cancellation/capture loss, window blur, zoom/mode changes, and document replacement cancel a drag. Each completed gesture and any resulting merge form one document undo step. Normal paragraph margins are preserved rather than added twice when a gap separates them. Closing a space never resizes or deletes its floating objects; overlap with the following text remains possible.

When an anchor is deleted, its floating objects move to the closest surviving preceding block, or the document-top origin. Their content is retained. The shared history restores document snapshots and editor selections without stealing focus or undoing view preferences. Reset to example remains confirmed and clears history. Only the current V0 is supported: loading checks its identity and initializes content through the editor schemas, without historical upgrades or a general-purpose document validator. An editor parsing failure offers a confirmed reset to the example in the owning tab; declining leaves the saved draft untouched. Reading tabs cannot reset it.

Desktop tabs request an exclusive `mote-local-draft` Web Lock before loading for editing. The owning tab retains it through reading-mode switches and load retries, until it closes or reloads. A competing tab opens a read-only snapshot, without autosave or normalization writes. **Try editing** makes a non-waiting ownership request, then reloads from IndexedDB before enabling editing. There is no automatic takeover, live synchronization, or merging. Browsers without Web Locks retain ordinary editing and saving, including concurrent last-writer-wins writes. A fresh mobile view neither requests ownership nor writes a draft; after widening to desktop, **Try editing** can acquire ownership.

Storage-access failures show Retry, never a reset prompt. Failed database opens are retried rather than cached permanently. Save failures retain the in-memory document and offer Retry for its latest state; “Saved in this browser” appears only after the write transaction completes. Pending or failed saves retain the unload warning.

IndexedDB (`mote-local` → `drafts` → `current`) is origin-specific local storage, not a backup. Another browser, port, hostname, or device has a different draft. Clearing site data removes it, and browsers may evict it. Export `.mote` files to keep editable copies outside the browser. There is no cloud sync, multi-tab conflict resolution, or document library.

The floating layer deliberately permits overlap. Pointer and keyboard movement, duplication, and resizing stop at the document's horizontal edges; group movement preserves relative positions and accounts for attached labels. Content editing and widget interaction activate only when exactly one floating object is selected. Multi-selected text boxes, labels, tables, and widgets remain in positioning mode: dragging an interior moves the group, table dividers stay hidden, and widget frames remain inert. Reading-mode interaction is unchanged. Changing document width does not rewrite saved offsets, and shrinking the page or growing unwrapped label text can still leave existing content outside its bounds. Direct inserts measure their rendered size and stagger when either the new or existing object would completely cover the other; partial overlap remains allowed. Duplicates also stagger while preserving group relationships. Explicit drag placement and attached labels retain their intended geometry. This is insertion-only placement, not ongoing collision avoidance or a full spatial layout inspector.

- **Floating clipboard:** focus one object or marquee/Shift-select a group, then use Ctrl/⌘C, X, and V to copy, cut, and paste. All floating kinds are supported. Attached labels accompany their targets; internal line connections remain within the copied group, while connections to objects outside it detach at their displayed positions. Cutting also detaches surviving connections to the removed objects. Paste adds a newly selected group with fresh object and rich-text IDs, preserving relative placement and stacking. It retains the copied page position, or uses the main-text caret's height when pasting in the main editor, and staggers to avoid fully covering existing objects. Placement uses destination measurements and page bounds; oversized groups retain their dimensions rather than being scaled. Repeated paste adds independent groups. Native V0 data has an HTML carrier and readable text fallback; referenced palette families follow the same import/remapping rules as segment paste. Cut and paste, including palette changes, each undo in one step. While editing floating text, labels, table cells, source fields, or widget contents, the content editor keeps its clipboard behavior. AI-reserved objects cannot be copied or cut. Floating paste never replaces a main-text or segment selection.

## Document files

In editing mode, **File** opens a modal with three exports and **Import .mote…**. Switching to mobile reading closes the modal. All processing is local. Export takes a snapshot of the latest in-memory content, not the last IndexedDB save. It does not alter selection, history, mode, or zoom. Ctrl/⌘S retains its existing no-op behavior.

The **Filename** field supplies the export name, with the selected extension added automatically (an existing PNG/HTML/Mote extension is replaced, not duplicated). Where `showSaveFilePicker()` is available, export opens the browser's native Save As dialog with that suggested name and format filter. The picker is invoked directly from the click before export preparation; canceling does not generate or download a file. Bytes are written only after generation succeeds, and success is reported after the writable stream closes. Elsewhere, Mote uses an ordinary download with the chosen filename; browser preferences determine whether it prompts for a location. The filename is session-local UI state, not part of the document.

- **PNG:** one full-length image at one bitmap pixel per document CSS pixel, independent of display density, scroll position, and view zoom. It captures the shared reader at native size after images/fonts/layout settle, including the theme background, spaces, tables, labels, shapes, lines, and floating text. The page's horizontal edges crop overflowing content; the width never grows to accommodate objects. Fractional pixel extents round upward. No app chrome, page shadow, selection controls, or added bottom padding. Animated images become a still frame. The initial implementation caps height at 32,767px and area at 32 million pixels; smaller browser limits can also prevent export. It checks rasterization support and reports failures rather than silently shrinking/truncating the document. HTML and `.mote` remain alternatives. Scoped raster checks use Chromium; other engines' HTML-in-SVG raster support varies.
- **HTML:** a single file that opens directly from disk, with inline CSS/JavaScript and embedded document/images/math fonts. Mote content and self-contained widgets work offline; widgets referencing online resources still require them. It mounts the same `DocumentCanvas` through `ReadDocument`, sharing text schemas, theme styles, anchor/repulsion measurement, floating-object layout, fit/zoom, minimap, and heading navigation. The shell has no top bar, Edit button, File/View menus, or zoom buttons. Auto zoom, zoom gestures/shortcuts, and automatic minimap/heading navigation remain; the minimap hides on small screens. The background fills the viewport without a visible page edge or shadow. The Mote reader itself does not access IndexedDB, localStorage, Web Locks, or a server; widget code runs separately in sandboxed iframes. The page and minimap crop horizontal overflow just like app reading mode; zoom still permits horizontal navigation within the page. Text stays selectable and searchable. JavaScript is required; ordinary system fonts remain system fonts, so typography can vary across devices and the shared layout recalculates accordingly. HTML is a published copy, not an import format.
- **Mote document (`.mote`):** binary gzip of UTF-8 JSON containing the existing `MoteDocument`, including `version: "V0"`, IDs, theme, geometry, rich text, and embedded assets. There is no archive manifest, custom binary header, encryption, or base64 wrapper around the file. Session history, selection, zoom, and browser preferences are excluded. Both compressed and decompressed data are capped at 128 MiB. Only the current V0 schema is supported; V0 does not promise compatibility with older builds. Ordinary gzip tools can inspect the JSON.

Import decompresses and checks the file before requesting replacement. External file checks cover its envelope, finite geometry, current field shapes, and safe embedded image/style values; rich-text content uses the same schema initialization as local drafts. No migration or repair layer is introduced. Corrupt gzip/UTF-8/JSON, unsupported versions, unsafe sources, schema failures, oversized files, and canceled replacement leave the existing draft untouched, without a reset-to-example prompt. Confirmed import remounts the editing session and clears undo history even if the document ID is unchanged, then uses ordinary local autosave and its visible retry behavior.

PDF export is deferred. PNG and HTML cannot be imported back.

## Structure

```text
src/app/        application shell, controls, responsive styles
src/document/   V0 data model, example, IndexedDB
src/editor/     constrained Tiptap schema and editor component
src/canvas/     anchor measurement, floating text interaction, zoom, minimap
src/theme/      shared semantic theme variables and controls
src/reader/     offline reader entry and single-file HTML export
```

The Vite configuration builds the offline reader as a production IIFE and stylesheet behind `virtual:mote-reader-bundle`. The HTML exporter embeds those build outputs; it has no handwritten alternate document renderer. Export codecs and the reader bundle load lazily from the main application. No export dependencies were added.

The minimap shares the rendered page through an inert, noneditable DOM snapshot, with editing controls and accessibility duplicates removed. Both sizing modes share this renderer and navigation geometry. Proportional mode keeps the page's aspect ratio and scrolls the miniature for long notes; fit mode compresses only the vertical axis as needed. Main-document zoom changes the viewport indicator, not miniature content scale. Scroll-only updates translate the existing snapshot and indicator; layout/content changes refresh the snapshot once per animation frame.

## Deployment

The current demo is live at **https://mote.ylxdzsw.com**. It is served as static files by Nginx from `/var/www/mote`, with the virtual host in `/etc/nginx/conf.d/mote.conf`. The existing wildcard Cloudflare Origin CA certificate covers the hostname. Normal editing/reading remains public and browser-local. Only the optional AI API is cookie-authenticated and backed by `moted`; there are no Mote accounts or cloud save/load features.

The deployment sets `Cache-Control: no-store` and disables Nginx ETags/expiration for HTML, JavaScript, CSS, and fallback responses. Cloudflare receives the origin directive and currently reports `DYNAMIC`/`BYPASS`, so the pre-release build is not cached at the edge. There is no service worker. Intentional IndexedDB document persistence is separate from HTTP caching. Future updates require `npm run build`, copying `dist/` to `/var/www/mote`, then `nginx -t && systemctl reload nginx`.

Vite development and preview responses also send `Cache-Control: no-store`. `public/_headers` carries the same rule for static hosts that support that format. Other hosts must explicitly set `Cache-Control: no-store` on **all** responses, including HTML and built assets.

Review the early-development decisions in `.mu/AGENTS.md` before a release.
