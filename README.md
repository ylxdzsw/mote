# Mote

[![CI](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml/badge.svg)](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml)

A private, AI-native document workspace combining semantic text with anchor-relative spatial placement. Documents live in the cloud, with independent local working copies and explicit conflict resolution. See [Cloud workspace](CLOUD.md) for saving, sharing, recovery, authentication, and operations.

## Run

Use Node.js 22.12+ (or a current release) and npm. For contributor invariants and a documentation map, see [.mu/AGENTS.md](.mu/AGENTS.md). Agent authors use the public, unversioned [built-in skill](public/skills/builtin/SKILL.md) or [external skill](public/skills/external/SKILL.md) and their shared references. Private-client/API changes use [server/agent-api.md](server/agent-api.md).

```sh
npm install
npm run dev -- --host 127.0.0.1
```

Run the fake backend below, then open **http://127.0.0.1:5173**. The exact origin must match `MOTED_DEV_ORIGIN`; use an isolated state/data directory. Vite proxies `/api` and `/a/` to port 5174. Development and preview scripts bind to `127.0.0.1` by default. Do not expose development or fake services publicly. Browser recovery remains origin-specific.

```sh
npm run check   # TypeScript
npm run build   # TypeScript + production bundle in dist/
npm run preview -- --host 127.0.0.1
npm run test:ai # Essential Flow model, reservation, and fake-backend checks; no model calls
```

### Desktop interface

Editing uses a compact document workbench: 28px standard controls, 12px UI text with 11px secondary labels, aligned property rows, and flat sections rather than stacked cards. The 50px title bar and stable 288px / 268px combined Context/Assistant lane keep the document in place. Settings, Files, Share/export, creation menus, and drawing/source editors use the same control scale. Prompts and source editors retain useful writing space; page-layout and typography explanations sit in contextual disclosures.

The canvas stage has 24px padding on all sides outside the document border, separate from authored text margins and the editing-only scroll-past-bottom room. Reading retains zero horizontal stage padding.

Interface density does not change document typography, geometry, or zoom. Light/Dark appearance and the Primary hue apply throughout, including Files and Local recovery. At `/`, Files is the workspace entrance: it stays open until you choose a document. Escape still cancels actions inside Files, and Files opened over a document remains dismissible. Private documents and public shares open without a loading screen; errors and upgrade decisions remain visible. Below 768px, Files uses larger touch targets and choosing a document opens the chrome-free reader. Browser Back or returning to `/` brings back Files.

Native paragraphs, text boxes, table cells, and captions use automatic CSS hyphenation with the document's text language, without changing alignment. Editing, reading, minimap, PNG, and standalone HTML share this styling. Available hyphenation dictionaries depend on the browser and operating system; Code, Drawing, and embedded widget source are unaffected.

On-document reservation markers, selection marquees, and placement/space guides stay above the document object stack without bringing reserved content itself to the front.

AI segment reservations use a full-page-width striped band and dashed border over their exact flow interval, including text margins and partial explicit spaces. Owned objects/captions protruding beyond the band get separate outlines without enlarging the reserved interval. Candidate previews use an unshaded solid border; empty reservations retain a full-width insertion line and selectable marker. These overlays are absent from reading, minimaps, and exports.

## AI assistant

AI work has two separate systems. The current document working copy is `{document,reservations}`: reservations are saved beside the native document under the same document revision compare-and-swap, but are not part of native JSON or exports. Proposal versions and execution artifacts belong to the separate task service. A reservation ID is also its task ID; the server creates a distinct stable random task token. Neither the token nor session state is editable or exportable.

Select content and choose **Reserve for Assistant** below its properties in the right lane. Reserved content shows only its still-editable properties, followed by Assistant in the same scrolling panel. Reserving is a local undoable edit and does not start generation. New reservations have two kinds: **Object** and **Segment**. A segment covers its selected paragraphs, explicit spaces, Flow blocks, owned objects/captions, and anchored Floats. A main-text selection expands to a whole-block segment, including intervening spaces and owned objects; a caret reserves its whole paragraph as a segment. A single-paragraph segment never changes type. Selection inside a text box, table, or caption reserves the whole owner object. Multiple independently selected objects cannot be reserved together; use the gutter to select a segment instead. Existing prose-only reservations retain their original narrow scope and proposals; they are not silently converted. **Add → AI object** reserves a new floating area; the placeholder is part of the current document state. A reservation-only draft, including a blank document, is retained and published by ordinary sync. Select a reserved area to show its task; there are no separate Context/Assistant tabs or task tabs.

The **Built-in / External** tabs are local UI choices only. They do not call the backend, assign an executor, change access, or stop work. Both kinds of agents may work concurrently and append into the same proposal list. The External tab exposes copyable task instructions/link; selecting it does not create or rotate a token. Copied instructions contain only the task link and reusable skill link. Task-specific context belongs in the JSON task description; reusable workflow guidance belongs in the skill and its linked references, not in the copied handoff. The Built-in tab exposes the request composer. **Stop** stops built-in execution only; an external agent may still submit while a built-in run is working or stopped. The same task and token remain associated with the reservation regardless of the visible tab.

The optional **Expires** time is a reservation property. It saves and undoes with the document; the saved value is checked when each resource request opens. Without it, the active reservation has no time limit or owner-inactivity pause. A newly saved reservation makes its waiting task available; an owner `GET /api/ai/tasks/:id` lazily ensures its task record. **Generate** uses the built-in `/revise` action; retries require explicit user action and never start automatically after reconnect or restart.

**Settings → Document → Layout → Mu model** accepts an optional raw Mu model reference; blank inherits the **Settings → Workspace** built-in default. Explicit overrides belong to the document and round-trip through `.mote` files; credentials do not. Built-in generation requires a model configured in one of these settings; there is no server-wide or Mu default fallback. Existing agent-session models are unchanged. References may be fixed `provider/model:effort` or floating `model:effort` for Mu’s configured provider fallback. Workspace settings are revision-checked cloud metadata, outside document content, undo, and export.

Model fields offer configured Mu references through an editable dropdown. The arrow browses configured references; typing filters them, and typing `:` after a known reference offers its configured effort hints. Arrow keys navigate, Enter selects, Escape dismisses, and Tab/blur retain the entered text. Custom references remain accepted without appearing in the suggestions. Suggestions load on demand from authenticated `GET /api/models`, which reads Mu configuration metadata without contacting a provider or testing model availability; unavailable suggestions do not block editing or saving. Document changes still apply immediately, while workspace changes require **Save settings**.

### Availability and retry boundaries

Opening, editing, saving, exporting, sharing, and managing files/settings do not require Mu or a working provider. Model failures retain reservations and proposals and do not block manual work. Missing model configuration produces an actionable Settings error without starting a worker or taking the workspace offline. Worker attempts are deadline-bound (15 minutes by default); failed or interrupted attempts require explicit Retry, including after a server restart.

Reservation creation/property edits, Accept, Discard, and deleting a reserved target are local undoable edits. Accept applies the selected cached proposal; Accept, Discard, and deletion remove the reservation from the current array rather than writing a `released:true` marker. They request an opportunistic early debounce to ordinary document sync after 650 ms and do not call task permission, acceptance, or release endpoints. The regular 30-second autosave, Ctrl/⌘S, operation-ID retry, and document revision CAS remain authoritative. Cloud authority is the last committed `{document,reservations}` state. Until that save, the previous saved reservation remains authoritative. Undo/redo restores the prior snapshot, including the same task ID; syncing a restored reservation makes its stable server token usable again. Generation is never repeated by undo. Older explicit released entries are stripped when history initializes and disappear from cloud state on the next ordinary save. Failed final saves preserve local work through the existing explicit recovery path.

Each tab's local task view/proposal/draft cache is retained while its task ID appears in the current reservations or any undo/redo snapshot. History holds up to 100 undo entries. Once the corresponding working copy is saved locally, dropping a redo branch or evicting an old history entry lets the browser prune cache entries no longer referenced by any snapshot. Unmount and the next open trim cache to current reservations; undo history itself is not persisted across reloads. A failed local save does not prune cache. This is per-working-copy browser cleanup only: it neither deletes server task artifacts nor revokes task tokens, and another independent/offline tab may still hold a reference. It is not full task or disk cleanup.

The task's latest proposal versions are cached in the working copy's local assistant state after retrieval, so **Original / Preview**, proposal validation, and Accept remain usable during a service outage while the task is referenced by current reservations or undo/redo history. Preview and Accept check the proposal against the actual current document and reservation structure, not the original geometry as a server submission contract. New-schema validation and the final native document validator protect persistence. HTML widgets execute only in their sandboxed, opaque-origin frames.

Current transport is `mote-agent-v7`, distinct from native document V1–V9. Versions are flat, append-only records `{id,label?,candidate}` with no agent/source field; submissions return `{taskId,versionId,status:"ready"}`. Concurrent agents share this sequence. The public `/skills/proposal-schema.json` describes the current native proposal grammar and has advisory `documentFormat:"mote"` / `documentFormatVersion:9` metadata; that hint is not echoed or proof of a document read. Submission validation is stateless and independent of the current document, target, agent origin, and session. The task base URL returns one JSON description combining request, exact target, optional expiry, segment transfer measurements, and resource/helper/schema links, without copied originals. Separate manifest/target/instructions endpoints are retired. Invalid-schema errors include the schema URL and JSON path where available. Owner Preview/Accept checks applicability to the actual document/scope; ordinary cloud validation and CAS establish persistence.

The task resource `document.json` is an optional read of the latest cloud document at access time, including tentative Notes for permitted tasks. It is not revision-pinned and no historical revision read is available. The task description's `.target` identifies reserved IDs and boundaries; its segment `.geometry` holds reference measurements, not frozen content. Agents cannot discover or fetch other workspace files. Native proposal fields must follow current V9 grammar even when the document was created under an older supported native version; native V1–V9 migration/compatibility remains separate.

External task access uses a stable 128-bit server token at `/a/<22-character-base64url-token>`, distinct from the task ID. A public request checks the saved reservation, its `expiresAt`, and privacy at request opening; submission checks active/expiry once at opening. A submission already admitted may finish harmlessly after a later edit or reservation removal. Current release is represented by omitting the reservation: outside the Private/deleted-document access gates, once that omission is saved the task capability follows the existing 404 path. An expired active reservation remains blocked at request opening; older explicit `released:true` records retain their legacy 410 rejection until saved without the reservation. There is no executor revision, generation authorization, or automatic server-side cleanup on Accept/Discard. Undo restores the same task ID, and syncing the restored reservation reactivates the same token. While Private is on, every public `/a` method is inaccessible; Private does not destroy the token, so disabling Private makes the same active, unexpired reservation link usable again. The trusted built-in socket may access its own Private document. Public Share links retain their separate policy: enabling Private revokes the active share permanently, and turning Private off does not restore it.

Current task actions are owner-only `GET /api/ai/tasks/:id`, `POST /api/ai/tasks/:id/revise` with `{prompt,operationId,model?,selectedVersion?}`, and `POST /api/ai/tasks/:id/stop`. The `revise` operation starts a built-in run and is retry-safe; Stop only stops that execution. `/executor`, `/workspace-read`, and `/release` mutations are obsolete and return 404. The former `/api/documents/:id/assistant` state remains read-only for older records, but the current client does not import those legacy task records into active Assistant state or show a task-recovery archive. The separate Files → Local recovery download remains available for working-copy recovery. Server task artifacts and versions are retained after Accept/Discard and have no automatic expiration or cleanup; this is separate from pruning the browser's working-copy cache and does not promise server disk cleanup.

The Assistant shows tasks attached to current reservations. Selecting a reserved region shows its task, and **Show in document** selects and reveals it. Draft requests survive reload while the reservation remains current. Background completion does not change the viewed task. A selected proposal appears **in place on the editing document**, without modifying saved content. The Assistant review uses **Original / Preview**, version choice, **Accept**, and **Discard**; the document has no on-canvas review buttons. Paragraph and segment previews reflow the document and anchored objects; individually reserved floating previews follow their current placement. There is no retained-task or recovery-archive UI; **Download task JSON** remains available for a current task. Files → Local recovery and its general **Download recovery** action remain available for working-copy recovery.

Concurrent reservations protect nonoverlapping content. Individual reservations lock content and body dimensions from reservation creation, independently of agent execution. They preserve user-owned placement and margins; caption width remains user-owned while caption content/removal stays reserved. Segment-owned objects remain locked as a composition. New segment targets carry `version:2`, independent of native document, candidate-envelope, and task-transport versions. They reserve exact intervals rather than whole touched spacers. Disjoint slices of the same spacer can be reserved independently. Alt-gutter selection chooses exact offsets; an empty interior selection reserves a position, consumes no space, and owns no objects. Insertion points conflict only strictly inside a reserved interval, not at either outer boundary; two tasks cannot reserve the same point. Structural splices, space shifts, and merge aliases map surviving reservation boundaries atomically with document edits and undo. Changing protected content or consuming a protected interval remains blocked. Targets without this version keep their original whole-spacer locking semantics. No reservation creation inserts a placeholder paragraph or changes native geometry. Cross-boundary edits and history operations that would disturb an active reservation remain blocked.

Drawn areas are generic **AI object** requests, not specifically figures or HTML widgets. Context labels the placeholder **AI object · Reserved for AI**, using the task’s new-object identity rather than its temporary HTML storage kind. Existing objects reserved for revision retain their kind label; accepted objects use their generated kind. New proposals may use Code, Formula (rendered by KaTeX), text, table, image, HTML, or drawing. Existing-object revisions retain their kind except that an explicitly requested Drawing revision may convert to another supported single-object kind. The original content and geometry in the Reservation remain useful for review, but current Preview/Accept decides applicability against the live document. Current v7 task resources do not provide pinned rendered snapshots; an optional `document.json` read supplies the latest saved native document at access time.

Segment proposals may mix complete objects and bare object-ID strings in `segment.objects`. A string means reuse that reserved object unchanged. The server validates unresolved grammar and explicit payloads, preserving strings. Preview/Accept checks that each ID is owned by the reservation and exists in the working document, deep-copies it literally, then uses normal full validation and segment application. No merge, coordinate repair, snapshot fallback, or special ID preservation occurs. Missing/out-of-scope references fail review; omitted objects stay omitted. The portable `extract.mjs TASK.json DOCUMENT.json RESULT.json` helper starts copy-edit-submit from the complete document and task description, retaining unchanged objects as IDs and emitting explicit adjusted Floats for partial-spacer boundaries. Images/screenshots stay embedded; no asset endpoint or native format change is introduced.

### Fake-first development

Run the app at the exact development origin below and start a fake service in another terminal:

```sh
mote_dev_dir=$(mktemp -d /tmp/mote-dev.XXXXXX)
MOTED_FAKE_RUNNER=1 MOTED_USE_SYSTEMD=0 MOTED_PORT=5174 \
  MOTED_DEV_ORIGIN=http://127.0.0.1:5173 \
  MOTED_STATE_DIR="$mote_dev_dir/ai" MOTED_DATA_DIR="$mote_dev_dir/data" \
  node --experimental-sqlite server/moted.mjs
```

Vite proxies `/api` and `/a/` to port 5174. The fake runner is selected only by server environment, never by a request parameter, and makes deterministic visible changes without calling Mu. Configure a model such as `fake` in Document or Workspace settings before generating; fake mode enforces the same explicit-model requirement. `npm run test:ai` exercises critical Flow atom/object, conversion, segment/clipboard, format migration, document CAS, sharing, recovery, backup, reservation, validation, and task-lifecycle invariants without a browser, systemd worker, or provider call.

### Pre-release service

The app and AI controls use same-origin APIs behind the existing `nginx_auth` cookie gate. Private navigation uses Nginx’s existing `/var/www/login.html` gate, preserving the requested URL through sign-in; there is no Mote-specific login page. `/`, `/d/:id`, and `/preview` require login. Private mutations require the exact allowed Origin. The single key represents one trusted workspace, not separate users. Explicit `/s/:token` read-only shares, their scoped data endpoint, and reservation-scoped `/a/:token` capabilities bypass login. The retired public `/api/agent/` route returns 404 without logging credentials; that route is used only on built-in workers’ private sockets. Capability requests authenticate the token, not a workspace cookie or Origin. Nginx does not access-log agent capability or public-share URLs (`/a/`, `/api/agent/`, `/s/`, and `/api/shared/`). See [CLOUD.md](CLOUD.md).

**Settings → Document** has a **Private document** lock toggle above the layout controls, separate from content and undo. A highlighted closed lock means Private; an open lock means not private. Hover for the current state and action. Enabling it permanently revokes the active public Share link, but only blocks the stable public task token while Private remains on. All public `/a/` methods are inaccessible while Private; disabling Private lets the same active, unexpired reservation token work again. The trusted built-in socket may still access its own Private document. Public-share revocation remains separate and permanent. Files marks private documents; owner access remains unchanged. Private controls public access, not trusted built-in work on this document. See the [Document Private policy](CLOUD.md#document-private-policy).

`moted.service` runs the Node supervisor at `/run/moted/moted.sock`, storing cloud documents in `/var/lib/mote/documents.sqlite` and durable AI sessions in `/var/lib/mote-ai`. Each task runs Mu and Chromium as the unprivileged `mote-ai` user in a transient systemd service. Workers cannot access the document database, backups, Nginx credentials, or sibling task directories. Each receives its own explicit read-only snapshot and approved source/config resources. Workers still have outbound networking and configured provider access; this is not a hostile-user multi-tenant sandbox.

See the [service](server/moted.service.example), [Nginx deployment](deploy/mote.nginx.conf), and [document-export backup policy](CLOUD.md#manual-backup). Defaults are two workers, 15 minutes per run, 2 GiB memory, and 200% CPU per worker. Request bodies are capped at 128 MiB, result JSON at 8 MiB, and each widget screenshot at 10 MiB. Candidate validation never executes HTML. Explicit owner-requested widget screenshots use a separate disposable browser sandbox, not the supervisor or AI delivery path. Server task artifacts and proposal versions are retained after Accept and Discard and do not expire or auto-clean up. The browser's separate per-working-copy view/proposal/draft cache is pruned according to undo/redo references after local saves; that does not remove server artifacts or guarantee disk cleanup. An optional reservation `expiresAt` controls access; there is no owner-inactivity pause. Inspect failures with `journalctl -u moted.service`. Unexpected HTTP failures include a safe error reference in the response and browser feedback, correlated with sanitized structured journal diagnostics; see [Error diagnostics](CLOUD.md#error-diagnostics).

`GET /api/documents/:id/events` serves the cookie-gated document SSE stream. Its `update` events distinguish connection readiness, document/privacy/assistant changes, task changes, and task-scoped transcript entries/warnings/closure. Consumers subscribe before reconciling current state on connection/reconnection, so missed invalidations require no persistent event journal. `GET /api/ai/tasks/:id/transcript?after=N` returns bounded `{ events, reset, warning }` history for the viewed task; live entries and history merge by task-local event ID. Entries contain `{ id, attempt, kind, text }`, where IDs increase within the task, attempts start at 1, and kind is `request`, `stdout`, or `stderr`. Requests are recorded when queued, even if stopped before a worker starts. `reset` indicates that the cursor is outside retained history; `warning` reports output limits or storage failure. The active transcript resumes after validated network reconnection; **Reconnect** also offers an explicit retry. Opening the stream and its 15-second heartbeats do not renew owner activity. Nginx buffering stays disabled and stream responses send `no-store, no-transform`. Only selected Mu output is exposed, not raw session/provider journals or configuration. Built-in run/submission state is serialized; reservation release is an ordinary document revision, not a task delete/release call.

Server transcript defaults are 2 MiB / 2048 events, at most 128 KiB per event and 256 pending writes; slow SSE clients disconnect at 128 queued events or 512 KiB. Per-attempt stdout/stderr logs each retain at most 1 MiB, with old logs trimmed to a 4 MiB task-wide default after each attempt. Environment overrides are `MOTED_TRANSCRIPT_MAX_BYTES`, `MOTED_TRANSCRIPT_MAX_EVENTS`, `MOTED_TRANSCRIPT_MAX_EVENT_TEXT`, `MOTED_TRANSCRIPT_MAX_PENDING`, `MOTED_TRANSCRIPT_HEARTBEAT_MS`, `MOTED_LOG_MAX_BYTES`, and `MOTED_LOG_TOTAL_MAX_BYTES`. Frontend history is capped at roughly 512K text characters / 2000 chunks per tab. Task-local transcript replay survives supervisor restart and remains bounded; it is not unlimited chat storage. Cached proposals remain locally previewable/acceptable during service failure; generation never automatically retries.

## Editing and reading

Pointer feedback follows the current click/drag action: writing surfaces use an I-beam, object selection/movement uses a move cursor, and task selection and other activation use a hand. Code text uses an I-beam while its inert line-number gutter uses the default pointer. Modifier changes refresh the cue without mouse movement: Ctrl/⌘ makes links navigable, Shift switches object interiors to selection, and available Alt-space targets show vertical resizing. Reserved sections, including their spaces, select the task rather than offering text editing or space resizing. A selected caption leaves its owner's body in selection-first mode. Disabled labeled choices use the default pointer.

- A cloud document library with blank file creation, opening, filtering, renaming, archiving, importing, and deletion. Native V1–V9 documents are supported. V1 is unchanged; V2 adds optional Slides; V3 adds table color pairs; V4 restricts saved theme weights to Regular (400) or Bold (700); V5 adds permanent image/widget markup; V6 adds optional document-level `theme.justifyText`; V7 adds optional document-level `theme.firstLineIndent`; V8 adds the Separator paragraph class; V9 converts old decks to continuous documents. Unsupported versions produce an actionable error without replacing saved content.
- **Files**, opened from the document title, is a searchable document switcher. Click a row to open it; arrow keys navigate and Enter opens. Sort by recent modification or name, use each row’s menu for Share/Rename/Archive/Delete (Unarchive in the collapsed **Archived** group), and choose **New** to create a blank file. In the form, you can name the file, choose its appearance (Light or Dark) and text language (English or Simplified Chinese), and mark it Private. When a nonblank search matches neither current nor archived files, **New file “…”** opens the same form with the trimmed search text as its editable name. Down Arrow from search focuses the shortcut; only **Create** makes the document. Appearance and text language remember the last submitted choices in this browser; Private starts unchecked. These settings do not change the current page. Cancel returns to the same Files search and position. The name labels the file, not an inserted Title paragraph. **Import** accepts `.mote` files. Archived and Local recovery use matching compact disclosure rows stacked at the bottom of the list area, with counts aligned on the right. Both expand inline; Local recovery counts pending or unsupported working copies on this device and stays highlighted when copies need attention. Desktop rows are 28px high, with 44px touch targets on mobile. There is no permanent Refresh button: reopening Files fetches the list, and a failed list load offers Retry. Mobile uses a tall sheet with dates beneath names. **Share → Export** produces PNG, HTML, and compressed `.mote`. The Files row’s **Share…** opens the same Link/Export dialog without opening that document, including on the mobile start screen. **Share → Link** controls one optional latest-version read-only link; opening the dialog never creates one.
- Semantic paragraph classes (`title`, `heading`, `subheading`, `body`, `caption`, `list`), plus fixed Table styling, retain theme-controlled typography. Inline formatting composes Bold or inherited weight, a fixed palette color or inherited color, None/Box decoration, and a separate native Link mark. Links are available in main text, floating text boxes, table cells, and captions—not Code or Drawing—and inherit text color while remaining underlined. Inline Bold is disabled and shown pressed when every selected paragraph is already bold through its effective style, including inherited weights and table headers; Ctrl/⌘B is a no-op in that state. Mixed or regular paragraph selections remain toggleable, including removing existing inline Bold marks, and other marks are unchanged. Code is a separate floating-object kind, not a paragraph class or rich-text editor.
- **Links:** Link replaces Underline in the Text strip. Select text and choose Link to focus its URL row below the strip; choosing Link on an existing link removes it. A caret inside a link shows the row without taking focus, and Ctrl/⌘K focuses it. Enter or blur commits; Escape cancels; an empty value removes the link. A valid URL entered at an empty caret inserts its URL as a linked label. Values are trimmed; bare domains gain `https://`, while only absolute, credential-free HTTP(S) URLs are accepted (no relative paths, `mailto:`, or `tel:`; localhost requires an explicit protocol such as `http://localhost:5173`). Unsafe protocols, control characters, and invalid URLs are rejected. Typing a URL does not create a link. Ordinary paste may detect explicit HTTP(S) URLs and preserves safe incoming rich links. Ctrl/⌘Shift+V strips incoming link marks and skips URL detection, but a paste inside an existing link inherits that destination link. Ctrl/⌘-click opens a link in a new tab while editing; ordinary reading clicks also open a new tab. Links have no popover. The Clear formatting action is removed.
- The **50px title bar** keeps a clickable document title and live save indicator on the left, with quiet history, Add, zoom, Share, Theme, Settings, and Preview controls on the right. The save indicator stays visually plain, with a pointer cursor and “Click to sync” tooltip; click to sync or retry a local save. Ctrl/⌘S remains available. Share, Theme, and Settings remain flat icons with hover tooltips at every editing width. Share uses a link icon and opens Link/Export tabs; Theme uses a palette icon beside Settings and opens document typography and palette controls directly; Settings uses a gear and opens Document/Workspace/Browser tabs. There is no collapsing More menu. Preview opens a local snapshot in a separate tab/window without changing the editor’s selection, zoom, scroll, or Assistant context. Repeating Preview refreshes the same preview window if it is still open. There is no Read/Edit toggle. Mobile documents, public links, previews, and standalone HTML have no title bar, Files button, or editing controls.
- The right lane combines **Context and Assistant**, with one stable width per breakpoint (288px desktop, 268px at 1050px and below). Unreserved selections show properties followed by **Reserve for Assistant**. Reserved selections retain only editable properties above their task: individual objects keep placement, stacking, and margins; selected captions keep width controls; reserved paragraphs and section compositions have no editable properties. Properties, task controls, and recovery share one scrolling area. Eligible unreserved rich-text selections show a fixed **Text** strip above it: paragraph class, Bold, palette color, Box, and Link. Table/Caption keep fixed class indicators; Code/source and non-text objects do not show rich-text tools. Tab reaches its controls normally; arrows/Home/End navigate the focused strip, and Escape returns to the retained caret. Menus preserve selection; the color menu includes recent colors. Creation stays separate under **Add** or the right-click launchpad, including over floating objects. While an object tool (Text box, Code, Drawing, AI object) is armed, a dimmed preview of its default size follows the pointer; a plain click creates exactly that object in place, and dragging sets its size instead. Page insertion targets, including existing objects and the left gutter, show a crosshair; Ctrl/⌘-hover over a link retains a hand because Ctrl/⌘-click opens the link instead. Hovering the gutter shows the nearest segment boundary (Alt splits explicit spaces) with a centered Flow preview; clicking inserts a centered Flow object there in one undo step. AI object is page-only and always creates one floating object reservation; select an empty gutter position and choose Reserve for Assistant to create an insertion task. Escape, window blur, or clicking Cancel placement disarms the tool. The preview is never saved, measured, mirrored in the minimap, or exported. Object actions remain in Context, not right-click menus; highlighted text and native/editor-specific contexts are preserved.
- **Settings** opens one fixed-size dialog with **Document**, **Workspace**, and **Browser** tabs, without changing canvas width. Document opens layout controls directly, without nested Layout/Theme tabs; its AI model override remains here, with the Private control left-aligned above layout and no introductory subtitle. **Theme** has its own fixed-size **Document Theme** dialog from the title bar, with Defaults, Palette, paragraph classes, and object styles. Opening Theme from the title bar selects the paragraph class at the active end of the rich-text selection, including a caret inside a Text object. Captions open Caption and table cells open Table. Without a text selection, Theme reopens the last section (initially Defaults). Opening it preserves the canvas selection; choosing another Theme section stays manual. Context class-style shortcuts and the text color menu’s palette shortcut open that dialog at the relevant section. Workspace contains the default built-in agent model, with explicit revision-checked Save settings. Browser contains local display preferences. Theme/document/browser edits apply immediately; workspace drafts persist across tab switches and closing/reopening Settings within the same document session. The right lane shows a selection hint when empty and the current selection’s available properties and reservation controls when active.
- The selection inspector puts **Duplicate / Delete** icons beside the object heading, then the shared **Flow / Float** choice. Content editing and appearance precede **Layout**, which offers object margins and compact **Bring to front / Send to back** icon buttons beside its heading. Resize objects and snap Flow objects to the center by dragging on the canvas; there are no object Width/Height fields or centering button. Drawing dimensions keep proportions. Table row/column operations use compact labeled pairs before column alignment and appearance. **Add caption / Edit caption** is one shared action on eligible owners; removal, width matching, and Caption typography belong to the caption's own inspector. Multi-selection shows only group actions. The relevant document-wide **class style…** shortcut appears directly in Context, without a disclosure. Palette settings remain available from the text color menu and Theme, not as a Context shortcut. Widget Edit code/Run and Update screenshot stay visible, while the saved preview and description fold under **Screenshot details**. Pending capture, missing screenshots, offline notices, and errors stay visible. Below Assistant, **Editing & shortcuts** shows guidance for the selection and **Assistant & privacy** explains reservations and access. Each row expands independently and appears only when relevant. Selecting another object starts its inspector at the top. Controls retain 32px minimum targets, native keyboard behavior, and document-matching surfaces.
- Theme Defaults define base typography, text color, and spacing; Appearance supplies the page background. **Justify text** is a document-wide Defaults checkbox beside Mixed-script spacing and is off by default. **First-line indent** is a document-wide Defaults checkbox beside Justify text; it is off by default and adds a two-character indent when checked. Paragraph classes retain partial overrides, inherited indicators, resets, and previews. Separator adds an optional positive **Line thickness** in px or em; when omitted, it resolves to 1px. No other paragraph class supports this field. Theme **Weight** is a compact **Regular / Bold** segmented choice (400 / 700), with the usual inheritance and reset behavior. Font sizes and lengths offer **em** and **px**; line height also offers **×** the paragraph font size. Every em is relative to Defaults font size, initially 16px. Inline Bold is always 700; font family, size, spacing, and inherited weight come from the paragraph. Box uses a thin current-color border and the selected family’s Soft tone, or Gray 5 for inherited/neutral color. The Box icon contains an A. Box uses the browser’s normal inline font box, with no glyph measurement or custom mark view. Its border includes the font’s reserved ascent/descent space. Links inherit text color and are always underlined. Browser selection highlights may extend to the full paragraph line height, so they are not the same boundary as this font-sized decoration. Decorations wrap with the text rather than becoming indivisible pills.
- **Theme → Palette** offers Light/Dark appearance and Primary/Secondary hue sliders. Each document has two fixed palette sets with 22 swatches: Primary and Secondary plus Red, Amber, Green, Blue, Violet, and Pink in Strong/Soft pairs, followed by six individual adaptive grays. Strong is deep in Light mode and light in Dark mode; Soft is pale in Light mode and deep in Dark mode. Every hue uses the same OKLCH rule per mode: fixed lightness, a capped share of that hue's available sRGB chroma, and a lightness nudge only where Strong would fall below 4.5:1 on the page. Each hue slider is painted with the Strong tones it produces in the current mode. New documents start at 29° (close to Huawei Red) and 262° (close to IBM Blue). Gray 1–6 reverse their tonal direction, including literal black and white endpoints. Colors have fixed tones; families cannot be added, renamed, deleted, or edited as raw RGB/hex. Mode and hue changes are live, saved, and undoable. Native text, object colors, drawings, captions, minimaps, readers, and exports all resolve the same fixed slots. Paste and AI content adopt destination mode and hues without importing colors. The compact palette grid keeps theme pairs first, fixed pairs next, and six grays last; native radio navigation, accessible tone names, selection, and focus indicators apply throughout. None/transparent and Inherit remain separate behaviors.
- **Appearance** explicitly controls the page and UI; it never follows OS preference or infers mode from a custom background. The fixed page surface is white in Light and #181818 in Dark. Header, text tools, Context/Assistant, menus, and minimap share it; canvas surround stays achromatic. Primary controls interface accents, selection, focus, editing outlines, and the minimap viewport border. Secondary affects document colors only. Interface status colors retain their meanings and readable contrast. UI tones are derived separately from authored swatches. Default native text uses Gray 2, captions Gray 3, table borders Gray 4, and inherited/neutral Box surfaces Gray 5. Each pair is designed for readable Strong/page and default-text/Soft combinations, with Strong/Soft at least 3:1 for borders and large text; arbitrary swatch combinations are not automatically corrected. Images and widget source/screenshots keep their own colors; Code syntax colors follow the saved Light/Dark appearance but not the hues. Public reading and standalone HTML use saved appearance; PNG captures the current appearance.
- **Code objects** are plain-text source snippets with Flow or Float placement, preserved whitespace, automatic content height, horizontal scrolling, and line numbers. Choose a language identifier; syntax colors follow the document Light/Dark appearance and do not use or change the palette hues. Code is not executed. Its monospace typography remains configurable through the document's Code theme style; it has no paragraph class, inline marks, or paragraph shortcuts.
- **Title / Heading / Subheading presets:** all three explicitly use Bold (700). Title inherits the Defaults typeface at 2.5em, with 3em Space before and after. Heading has 2em before and 1.5em after; Subheading has 2em before and 0.5em after. All em values use the theme's default font size. Seeding does not overwrite existing styles. Theme fields show their resolved values with an inheritance icon when following Defaults (or the Flow baseline); the reset icon on an override restores inheritance.
- **Subheading** is always available between Heading and Body in the paragraph menu for main text and text boxes. Its initial theme style is 1.125em (18px at the default baseline), Bold (700), with 1.5em line height, 2em space above, and 0.5em below. It provides local subsection structure without nesting, numbering, folding, or minimap bookmarks; only Title and Heading remain navigation landmarks. `theme.paragraphs.subheading` is seeded in new-document themes. When it is absent in a custom theme, properties inherit from Defaults; there is no implicit Subheading fallback.
- **Separator** is a semantic paragraph class in the ordinary class chooser for main text and Text objects, not a separate object or layout choice. It is unavailable in table cells and owned captions. An empty Separator draws a full-width horizontal rule behind a normal centered text area, so the native caret remains visible at the insertion point; rich-text label content sits centered between equal flank rules. Wrapped labels stay centered and the flanks shorten. Shift+Enter inserts the ordinary soft break; Enter starts a following Body paragraph. Converting to Body retains the text. The Separator class's text color controls rule color independently of any inline label color. New-document themes preset this color to Gray 4, a lighter neutral; existing saved colors and omitted-color inheritance remain unchanged. Document-wide justification and first-line indent do not apply.
- **List** is an independent unordered-list item, not a child of a list container. Tab on Body converts the whole paragraph to a top-level item, wherever the caret is; text, inline formatting, and selection are preserved. Across selected paragraphs, Tab converts Body and indents existing List items, leaving other classes unchanged. Tab and Shift+Tab stay inside rich text: ineligible paragraph classes and captions consume the key without changing content or moving focus; Shift+Tab on Body also does nothing. Enter splits an item into a new same-level item, including when the item is empty. Shift+Enter adds a line aligned with the item's text start. Tab / Shift+Tab or the toolbar arrows indent/outdent selected items independently, without changing neighboring items. Shift+Tab on a top-level item returns it to Body. Backspace at the start reduces one level; at the top level it returns the item to Body without deleting its text. Each level adds 24px indentation, never a font-size change. Top-level markers are solid dots; all sublevels use hollow dots. Pasted unordered lists flatten into independent paragraphs; ordered-list paste becomes Body text. List works in main and floating text, while tables always use Table; tables retain cell navigation, stopping at the first/last cell rather than moving focus outside the table.
- **Add → Paragraph** arms a boundary picker for main text. Move over the page to highlight the nearest paragraph break or space edge, then click to insert an empty Body paragraph and start typing. The document start and end are available, including after a trailing vertical space. Existing spaces keep their heights; this tool does not split their interiors. Insertion is one undo step, separate from subsequent typing. This remains a Body-only paragraph insertion tool; use the normal paragraph-class chooser to make a Separator. Escape, window blur, zoom/mode changes, and history navigation cancel the tool. The marker is transient and absent from reading, minimaps, and exports.
- Borderless vertical spaces live at paragraph breaks. Hold **Alt** near a break and drag down to open a gap. Alt-drag anywhere in an unoccupied space, or on the first text line immediately below it, to resize it: down adds room, up removes it. The top stays fixed and following content moves. Gaps below **12 document pixels** are removed on resize release; normal theme paragraph spacing remains. Adjacent spaces merge, including after intervening text is deleted, preserving total height and floating-object offsets. Text always sizes naturally; there are no reserved/minimum text-segment heights. A small Alt-only margin cue identifies insertion points, and a transient size/removal hint appears during dragging. Spaces have no individual selection state or inspector, but can be included or split in a segment selection.
- **Flow and Float:** object placement is independent of content kind. Text boxes, tables, images, drawings, formulas, Code, and HTML widgets can use either placement through **Context → Flow / Float**. A **Flow** is a first-class, indivisible block in the main document: its actual rendered content and any built-in caption occupy normal vertical flow, so following blocks move when its height changes. Drag sideways within the text column, with a center snap and guide; **Alt** bypasses that snap. Snapping to the center keeps it centered as its width or the column changes; drag sideways to position freely again. Each drag moves on one axis: when the vertical target would move it to a different document position, the preview and drop preserve its original horizontal position and centering, with an insertion line and edge auto-scroll. Otherwise, dragging previews only horizontal movement, without a vertical insertion line. Left/Right moves a focused Flow by 1px (Shift for 10px); Up/Down moves it across a neighboring block. A **Float** uses free page placement and the shared grid. Main text uses only the interval to the Float’s left, returning to full width below it; there is no Overlap/Repel switch. If the remaining left interval, after object margins and the 8px text clearance, is less than 15% of the main text column width (excluding page margins), text skips that vertical band and resumes at the next usable width below. The cutoff is fixed, independent of zoom, and shared by editing, reading, and exports; text never switches to the Float’s right. Floats may overlap Flow objects and other Floats. A Float anchored to a Flow follows its horizontal and vertical movement.
- **Select All (Ctrl/⌘A):** In main text, on the canvas, or with an object selected by its border, select the whole document as one gutter selection. In a text box, table cell, or caption being edited, select only its text. Repeating the shortcut keeps the same scope. Source editors, Notes, and other text fields keep their own Select All.

- **Segment selection:** drag in the document’s empty left margin or the 24-screen-pixel strip immediately outside its left edge. The transparent page border joins these into one continuous hit area. Text, objects, captions, and their controls keep priority over margin selection; the outer strip remains available even with a zero left margin. The hit area is visually transparent, without a separate fill or edge, and blends into the surrounding canvas on all sides. It is available only while editing. Clicking alongside a paragraph or Flow selects that whole block; dragging extends through whole blocks. Normal endpoints snap to paragraph/Flow boundaries or either edge of an explicit space. **Alt** additionally permits positions inside explicit spaces; it never splits paragraphs or Flow blocks. Clicking alongside a space or theme gap places an empty segment selection for pasting. Either handle can collapse the selection or cross the other, automatically exchanging start/end roles with the same snapping. Empty selections show one indicator with the two boundary handles overlapped; either endpoint can be dragged, and dragging the indicator expands in either direction. They have no highlighted content and do not copy or cut. The cursor and handles share a right-pointing marker, retained throughout dragging even outside the strip. Edge dragging auto-scrolls; Escape cancels a drag or clears a finished selection. The highlight is continuous across the selected range, including theme-generated gaps; those gaps remain destination-theme spacing rather than copied explicit spaces. Included floating objects are highlighted in full by anchor ownership, even beyond the main-text band; objects merely intersecting it are excluded. A selected Flow owns its object, including its built-in caption, and anchored Floats. A split-space boundary belongs to the trailing portion, and the final portion owns objects extending beyond that space.
- **Reserved segments are selection units:** clicking their content, blank space, or gutter interior selects the task rather than starting an inner selection, including with Alt. A drag or boundary handle started outside cannot end inside a reserved segment; the selection includes the whole reserved interval and its owned objects. A 3-screen-pixel boundary hit zone keeps empty insertion selection available immediately before/after it. Marquee selection never picks individual segment-owned objects. Unrelated overlapping objects retain their own interaction. Accept/Discard returns the region to ordinary selection.
- **Move a segment:** drag inside its highlighted band or any highlighted owned object to reorder the whole segment. A grab cursor and insertion line mark the move; paragraph/Flow boundaries and explicit-space edges snap normally, while Alt permits dropping inside an explicit space. Boundary handles still resize the selection, and empty selections remain insertion/selection markers rather than movable content. Moving keeps paragraph, Flow-block, and object IDs, object stacking, anchored Floats, and built-in captions within their owning objects; only split spaces need new IDs. The moved range stays selected, including partial spaces after merging. Each move is one undo step, without changing the clipboard. Dropping within the original range or on either boundary does nothing. Edge dragging auto-scrolls; Escape, pointer cancellation, capture loss, blur, mode/zoom changes, and document replacement cancel without changing content. AI-reserved source content and changes that would disturb a reservation are blocked. Clear the segment selection with Escape or click elsewhere to return to ordinary text/object interaction.
- **Paragraph clipboard:** with only a text caret, Ctrl/⌘C copies and Ctrl/⌘X cuts the entire paragraph, including its semantic class, list level, and inline formatting. Wrapped lines remain one paragraph. Complete paragraph text selections use the same clipboard format; partial selections keep ordinary text behavior. Paragraph copies contain no floating objects. Cutting main-text paragraphs retains their objects and reanchors them to the surviving predecessor; cutting the last paragraph leaves an empty editable paragraph. Known whole paragraphs paste after the current nonempty paragraph, replace an empty paragraph or a complete-paragraph selection, and honor partial text selections with ordinary rich-text replacement. Immediate cut → paste restores the cut boundary, including between merged spaces; caret movement, another edit, Escape, or loss of editor focus clears that location. Main and floating text share this behavior. Table cells support caret-only copy/cut while retaining their required single-paragraph containers and flattened paste. A selected caption box copies its rich paragraph content; cutting removes only the caption, while text selections inside its editor use ordinary rich-text clipboard behavior. Ctrl/⌘Shift+V pastes plain text at the caret. External HTML/plain text is not guessed to represent complete paragraphs. Native paragraph metadata has a rich HTML carrier and plain-text fallback; new block IDs and fixed palette references follow segment clipboard rules. Cut and paste each undo in one step. AI reservations remain protected.
- **Segment clipboard:** Ctrl/⌘C and X copy/cut the active segment; V replaces it. Pasting keeps the inserted segment selected, including exact partial-space boundaries after adjacent spaces merge. Cutting clears the selection but retains the cut location for a following paste. Cut/paste preserve explicit-space heights, including pieces shorter than the space-resize removal threshold, and each is one document undo step. A main-text selection crossing a Flow copies/cuts as a composed segment with its owned objects. Native segment paste in the main editor inserts after the caret's nonempty paragraph, or before an empty paragraph without deleting its anchored objects; text selections expand to whole paragraphs for replacement. It never merges into paragraph text. Explicit gutter targets also accept copied Mote paragraphs. Pasted objects and blocks receive fresh IDs; Flow references and two-axis anchors are remapped together, and built-in captions remain part of their copied objects. Destination paragraph styles, appearance, and Primary/Secondary hues apply; fixed palette slots retain their identities. Clipboard data includes a native version-1 payload, an HTML-carried equivalent, and a plain-text fallback. Ordinary text paste remains in text editors, not the segment insertion marker. Segments touching AI reservations cannot be copied, cut, or replaced until those tasks are accepted/discarded. Selection is transient and absent from saved documents, minimaps, reading, and exports.
- Rich-text floating boxes anchored to main-text blocks. Choose **Text box**, then click a top-level boundary to insert a centered Flow, or Alt-drag to set the width of a Float (120px minimum where space permits); height follows text. New boxes start empty with the caret inside. **Context → Appearance → Border** offers None (default, borderless and transparent), Left (4px left border), and All sides (1px border). A bordered box picks one color pair rather than separate background and border colors: Strong draws the border and Soft fills the background. The shared pair picker uses a 3×3 grid: Primary, Secondary, and Gray (Gray 4 / Gray 5) on the first row, followed by the six fixed hue families. Text boxes start Secondary and keep the chosen pair when switching border styles. Decorations add no generated heading/icon or text-color change and never add palette entries. Both Flow and Float support them. Decorated boxes default to 0.75em padding when none is explicitly set; padding stays editable. Fixed palette references, clipboard, reading, minimaps, and exports retain the decoration. Editing outlines are separate from the saved border. An unselected object can be dragged from its interior to move it; clicking once selects it without placing a caret. Once selected, clicking or dragging inside edits/selects text instead of moving the object. Click elsewhere on the page to deselect and move it again. The **top, left, or bottom border always moves**, and the **right border resizes**; no extra movement handles or expanded border targets are used. There are no delete buttons, corner resize handles, or anchor markers. Focused Float objects move with arrow keys (Shift for 1px); their right borders support left/right arrows for width. Press Delete/Backspace with the outer object focused to remove it immediately; Undo restores it. Undoable actions do not ask for confirmation.
- Floating images share the same anchor, drag, resize, and delete behavior. Drop one or more local images onto the document, or use **Add → Image** to choose a PNG, JPEG, WebP, GIF, or AVIF (up to 10 MB per file); images are embedded in the local working copy and uploaded with cloud synchronization; SQLite deduplicates embedded image data internally. An explicitly requested AI task includes them in its full-document snapshot. A multi-image drop is one undo step, uses the drop position at any zoom, and rejects the whole batch if a file is invalid. Resizing preserves proportions. Select an image to edit its accessible description or replace its file in the sidebar.
- **External image paste:** pasting a single image file arms the same Flow-first placement tool as **Add → Image** after its file picker. Click a top-level boundary to insert a centered Flow, or Alt-drag in either direction to size a proportional Float. Alt-click alone inserts nothing; there is no default-sized Float or separate Enter-to-place behavior. Escape, blur, another tool, zoom/mode changes, and history navigation cancel placement. Confirmation selects the image and is one undo step. Native Mote object/segment/paragraph paste, mixed text content, source inputs, widget frames, and image drops keep their existing behavior. Clipboard image data uses the same validation and 10 MB limit as uploads; HTML-only remote image URLs are not fetched. Paste one image at a time, or use a batch file drop.
- Floating tables use the same selection-first interaction as text boxes: drag an unselected table from any cell to move the table; select it first to edit/select cell contents or resize internal column dividers. Once selected, click a cell, use Tab / Shift+Tab to navigate, and add/remove rows or columns through the sidebar. Every cell uses the global **Table** paragraph class, independent of Body but with the same preset. Table is available in the theme editor and through **Table style…**, never in the normal paragraph-class dropdown; the toolbar shows a fixed Table label inside cells. Composable **Bold**, palette colors, **Box**, and **Link** remain available. Each cell contains exactly one paragraph: Enter, Shift+Enter, and Ctrl/⌘Enter insert soft newlines, not paragraph spacing. Pasted paragraphs/headings flatten to newlines while preserving text and supported inline marks. Pasted table/spreadsheet ranges still fill separate cells. Tables support cell selection, rich-text paste, and document-wide undo/redo for text and row/column changes. The last row and column cannot be removed through the sidebar; delete the floating object to remove the entire table. **Context → Appearance → Style** chooses **Simple** (Gray 4 grid), **Academic** (ACM/IEEE-style top, header, and bottom rules without vertical lines), or **Business** (row dividers with alternating Soft stripes). The independent **Header row** checkbox bolds the first row (weight 600 in V1–V3, 700 in V4+); Simple adds a Soft fill, Academic a rule beneath it, and Business a Strong band with page-colored text, restarting the stripes below. **Color** selects one of the eight Strong/Soft families or the Gray pair. Simple uses its Soft tone for the header; Business uses Strong for the header and Soft for stripes. Existing tables keep Gray for Simple and Secondary for Business until a color is chosen. The choice stays when switching styles; Academic ignores it and hides the picker. Colors follow Light/Dark mode and document hues, including in reading and exports.

- **Captions** are available only on images, HTML widgets, and tables, and always appear below their owner (including tables) with an 8px gap. Use **Context → Add caption**; the double-click add/edit shortcut is image-only. A caption is a dedicated selectable subobject: click once to select it, then click inside to edit as with a text box. Dragging its box moves the owner. Its right border resizes caption width centered on the owner; that width may exceed the owner's width while remaining within the page. Omitted width follows the owner; an explicit positive document-pixel width stays fixed when the owner is resized. Pressing Delete while the caption is focused and selected removes only the caption, not its owner. Captions use the document Caption style and one paragraph with natural wrapping and explicit line breaks. The Text strip offers Bold, palette colors, Box, and Link; there is no paragraph-class picker or independent font/size. Pasted paragraphs flatten to line breaks. **Remove caption** clears it; an empty caption disappears after leaving caption selection. Flow height and Float text repulsion include the caption. Copy, duplicate, owner deletion, and undo preserve the owner/caption composition; body resize handles resize the owner while caption text rewraps. The native field is `caption:{content:JSONContent,width?:number}`; `content` is a doc with one paragraph whose attrs contain only its ID. A caption has no floating ID, layout, placement, or detach state. Text boxes, Drawings, Code, and Formulas do not support captions; see [FORMAT.md](FORMAT.md) for the full shape. Empty text boxes and blank formulas disappear when editing/selection ends; empty tables retain their grid.
- A **page-wide 16px dot grid**, with one origin at the document's top-left, appears only while dragging or resizing floating objects, including creation and table-column resizing. Floats snap to that same grid in both text and space areas; Alt bypasses snapping during existing-object movement/resizing, but selects Float mode (with snapping) during ordinary object creation. Page bounds always apply. Flow uses continuous horizontal placement and center snapping within its text column. Resizing or merging spaces never moves the grid origin. Selection, text editing, hover, marquee selection, reading mode, and the minimap do not show it. Dragging unoccupied document padding (all four sides), inserted space, or the surrounding gutters, outside the left segment-selection strip, starts rectangular marquee selection for any floating kind; Shift adds. Images and drawings can be moved from their interiors. Float group movement preserves relative positions, with captions laid out as part of their owning objects. Move a composed section containing Flow blocks through segment selection.
- **Table columns** resize by dragging internal dividers, adjusting only the two adjacent columns while preserving total table width. The outer right border resizes the whole table proportionally. Dividers have a 40px minimum where space permits and support Escape cancellation; zoom/mode changes cancel an active drag. Drag previews are transient and each release is one undo step. **Left / Center / Right** in the inspector aligns the entire column containing the caret, or all columns intersecting a rectangular selection. Mixed alignment leaves all three buttons inactive. New columns start left-aligned with an equal-share weight; adding/removing columns preserves the relative widths of surviving columns. New rows follow existing column alignment.
- Configurable document width (320–2400px, initially 960px) and four margins (initially 32px left/right and 48px top/bottom). Left/right main-text margins can be linked or edited independently and always leave at least 120px for text. Top/bottom margins are independent (0–2400px): top spacing precedes main text, and bottom spacing follows the last main-text block or lowest floating object. The page is continuous and has no minimum page height or branding footer. Changes are immediate and locally saved, with no Apply/Cancel stage.
- **Notes:** each document has plain-text scratchpads for outlines, backup content, and plans. Expanding Notes below the canvas automatically opens a blank first note if none exist, including when restoring an expanded pane. This automatic blank is not saved or added to undo history until edited, so opening Notes does not retain an otherwise empty draft. Use **+** after the tabs to add more notes. Empty or whitespace-only tabs show **×** for removal; nonempty notes must be cleared first. Removing the last note leaves an empty pane with **+** available; collapsing and expanding it opens a fresh blank note. Numbered tabs switch notes and scroll horizontally when full; Left/Right and Home/End navigate focused tabs. The arrow and unoccupied header area toggle the pane; the Notes label appears only when folded. Each note has its own content; adding and removing notes participate in document undo. Pane preferences update locally without rerendering the document or rebuilding its minimap snapshot. Its independently scrolling pane overlays the document without resizing it or changing Auto zoom, leaving Context/Assistant visible at full height. Extra bottom scroll space keeps the end of the page reachable above the pane. Drag the top divider to resize the pane. Clicking the blank area below a note focuses its actual text end without inserting whitespace or adding an undo step; an existing trailing empty line remains numbered and receives the caret. Escape from the text area collapses it. The browser remembers open state and preferred height, initially collapsed at 200px; short windows cap the pane to preserve canvas space. Reading and mobile hide the pane. Notes save and recover with the document, survive duplication and native `.mote` export/import, and are omitted from Preview, public shares, PNG, and HTML. Authorized agents can read notes as tentative working context, but cannot edit them.
- **Keyboard policy:** prefer browser defaults and conventional editor commands, not a parallel keyboard-operated canvas. Keep rich-text Bold (Ctrl/⌘B), Link (Ctrl/⌘K while editing rich text), clipboard/select-all, document save (Ctrl/⌘S), undo/redo, normal caret/selection movement, contextual Enter/Delete, Escape cancellation and table/list/code editing keys. UI controls retain native Tab/Shift+Tab and ordinary activation, with conventional composite-control navigation. Add uses ordinary tabbable buttons rather than a custom arrow-key grid. Pointer geometry handles are not Tab stops and have no keyboard movement/resizing commands. There is no Alt+F10 toolbar shortcut, Ctrl/⌘D object duplication, or drawing-tool letter shortcuts; duplicate and drawing tools remain available in their existing controls. Ctrl/⌘ +/−/0 belong to the browser, while the dropdown and canvas gestures control document zoom.
- One chronological undo/redo history covers text across editors, internal Notes, paragraph/inline formatting, table structure, layout/theme changes, space insertion/resizing/removal, and floating-object creation/deletion/geometry/image changes. Numeric-field focus sessions, color adjustments, and continuous typing are grouped; each released layout drag is one step. Toolbar Undo/Redo and Ctrl/⌘Z / Ctrl/⌘Shift+Z (also Ctrl/⌘Y) work across editor focus and panel closing. Text/numeric settings inputs keep native input undo. History keeps up to 100 steps in memory and is cleared on reload; saved documents do not contain history.
- A live minimap on the left of the canvas shows text, semantic colors, whitespace, and floating boxes. Click a region to navigate or drag the shaded viewport to scrub vertically; horizontal position and editor selection are preserved. Wheel scrolling works over the minimap; keyboard scrolling uses ordinary browser behavior rather than a separate minimap handler. There is no hover popup. Native canvas scrollbars are hidden; wheel, touch, and trackpad scrolling remain available.
- The context inspector and AI assistant occupy the right sidebar; document settings and browser preferences open in dialogs. The minimap stays on the left in editing and live reading. Small main-text title and heading bookmarks extend rightward toward the document. At rest, only their identical 2px left edges are visible; transparent 10px-wide hit areas remain until the minimap or a folded bookmark is hovered, or a label receives keyboard focus. The wider area that expanded labels would occupy never triggers initial expansion. Expanded labels are up to 90px wide (60px on mobile when explicitly shown), with 9px text. The folded 10px bookmark lane participates in document centering; expanded labels overlay the page without changing layout or zoom; pointer position within the expanded label lane keeps them open while crossing gaps, and they fold away on pointer exit. Only the label buttons intercept clicks, with 20px-tall targets that meet when labels are closely stacked; empty areas of the overlay pass through to the canvas, including segment selection. Labels show the navigation pointer, while empty areas retain the underlying action’s cursor. Expanded Title and Heading bookmarks share a neutral background and the same narrow minimap-side accent; only Title text is semibold. Every bookmark whose section intersects the viewport uses accent-colored borders and text without changing its background when revealed. A continuous section runs from its heading box to the bottom of its last visible main-flow block before the next landmark (or the final block). Outer Space before/after and the trailing page margin do not count; internal gaps, authored explicit spaces, and Flow objects with their captions remain inside the section. Its label stays highlighted while that range is visible even if the heading is above the viewport. Intersection must have positive height: touching a viewport edge exactly does not highlight a section. All intersecting labels receive equal emphasis. Folded bookmarks hide text, background, and the other borders, with no distinction for Title or current location. Hit areas, document centering, and the viewport indicator remain unchanged. A single title is omitted when it is the first main-text paragraph; leading explicit space is ignored, but an empty paragraph counts. Multiple titles all receive labels. Floating notes remain visible in the miniature but do not contribute bookmarks or affect the title count. Clicking a label aligns the start of its paragraph’s effective Space before with the viewport top, scaled with document zoom, without changing horizontal position or text selection. It uses the heading’s own spacing, not the preceding block’s Space after or an explicit spacer; zero Space before puts the paragraph box at the top. Jumps respect normal scroll limits without adding blank space, and section highlighting remains independent. Labels follow live edits and the miniature's scroll position; nearby labels spread out to stay readable. A very dense bookmark overlay can scroll independently over its labels. Full title or heading text is available in each label's tooltip and accessible name.
- Display settings under **Settings → Browser** offer faithful-proportion (default) and fit-whole-document minimap sizing, plus automatic/show/hide visibility. Automatic hides at viewport widths of 1050px and below, including mobile. Minimap visibility is controlled here, not in the title bar. Configure these preferences in editing mode; readers instead share automatic minimap visibility and faithful-proportion sizing across mobile, public links, and Preview. Preferences live in browser-local storage, separately from document content.
- **Settings → Browser → Editing guides** has two independent options, both off by default. **Show formatting marks** paints centered dots for ordinary spaces, `→` for literal tabs, `↵` for explicit line breaks, and `¶` at paragraph ends in native rich text. Automatic wrapping has no mark. **Show vertical spacers** brackets explicit spacer blocks in the left page margin, not ordinary paragraph spacing. Neither option changes document content, wrapping, clipboard text, the minimap, reading, or exports.
- **Editor scrolling and zoom:** the editor retains its fixed app frame, independently scrolling canvas/settings, and percentage dropdown. Auto (the default) fits available canvas width, capped to keep at least 600 document pixels visible vertically and at 300%, following viewport, panel, and document-width changes. Desktop canvas padding, zoom policy, and scroll clearance are established on opening, even while Assistant recovery temporarily disables editing. Resize-driven fitting—including minimap toggles—commits the scale and scroll-anchor correction before paint, without an intermediate frame at the previous zoom. Presets are 25%, 50%, 75%, 100%, 125%, 150%, 200%, and 300%. Ctrl/⌘ + wheel and trackpad/touch pinch over the editing document change document zoom; manual zoom leaves Auto and remains fixed across resizes. Gesture zoom snaps near 100% and Auto without enabling Auto. Ctrl/⌘ +/−/0 retain browser zoom. The page lays out at native document size and uses transform scaling with a scaled outer footprint, so document zoom changes neither wrapping nor saved geometry. PNG and minimap captures retain native document geometry.
- **Reading and Preview:** desktop documents open in the editor; viewports under 768px use `ReaderPage`, the same chrome-free shell as Preview and public links. Mobile Files is only available with no selected document; direct `/d/:id` URLs go straight to authenticated reading. Browser Back or `/` returns to Files. Private working copies retain sync/recovery handling and actionable save failures. **Preview** passes a browser-local copy of the current document to the live reader in a separate tab/window. It includes unsynced edits but excludes Notes, model overrides, and unaccepted AI candidates. No save, share link, or upload is needed, and Private documents work. The first opening loads the app in that tab. It is a snapshot: click Preview again for newer edits; use HTML export for a retained copy. Readers use **native webpage scrolling and browser zoom**, including mobile pinch and desktop browser shortcuts/gestures, with no Mote zoom controls or percentage overlay. On opening, the full authored page is fitted to the available width, never enlarged beyond 100%; device orientation changes refit it. Ordinary window resizing and browser zoom retain that initial document scale rather than continuously fitting away the user’s zoom. Narrower windows may therefore scroll horizontally. The viewport remains device-width, and authored wrapping, margins, and spatial geometry remain unchanged; there is no progressive margin cropping. The page and minimap keep the authored background, without page borders or shadows. The minimap is fixed beside the webpage and follows window scrolling; bookmarks navigate the window. All readers retain sandboxed widgets, selectable text, and automatic minimap visibility (hidden at 1050px and below).
- Each tab has an independent, recoverable IndexedDB working copy. Cloud autosave runs every 30 seconds, skips clean copies, and also saves on Ctrl/⌘S. Incoming updates use one document-scoped SSE connection per open tab. Atomic revision checks reject concurrent stale writes. Conflict actions are **Save as copy**, **Discard local changes**, and **Overwrite cloud version**; overwrite directly replaces the cloud content after checking the observed revision, without an additional recovery copy. There is no merging or conflict preview.

Object dimensions are adjusted directly by dragging their canvas borders or resize handles, not through Width/Height fields in Context. Caption width retains its separate inspector controls.

Tables and images have no outer content padding in either Flow or Float: their body selection outlines closely follow the table or image boundary, retaining only the 1px body border. Table-cell padding, configurable text-box padding, and the separate caption gap are unchanged. The shared rendering applies this styling to existing documents as well as new objects, including reading, minimaps, PNG, and newly generated standalone HTML.

**Flow spacing and object margins are separate.** Theme → Objects → **Flow objects** sets nonnegative **Space before / Space after** in px or em for every Flow block. New themes preset both to **1.5em**; saved themes are unchanged. For any consecutive paragraphs and Flow objects, the style gap is the maximum of the preceding block's After and the next block's Before. At document edges, Space before the first block and Space after the last block are ignored: the page margins alone control edge spacing. Object margins extend the body-and-caption layout footprint and add to the collapsed style gap; they never collapse themselves and remain effective at page edges. Omitted Flow Before is 0; omitted After follows Body. Explicit space blocks add their saved height to the surrounding collapsed gap as independently authored pauses; leading/trailing spaces remain blocks and separate neighboring paragraph/Flow spacing from the page edge. Internal object padding is unchanged.

Context → Layout → **Margins** adjusts each Flow or Float object's layout footprint with signed Top/Right/Bottom/Left values in document pixels. Positive values reserve room; negative values contract the footprint and allow content to overlap surrounding layout. Margins surround the complete body-and-caption composition without changing its size, internal padding, or caption gap. Flow height and centering, Float text repulsion (with its existing 8px text clearance), placement snapping/bounds, and insertion overlap use the footprint. Repulsion remains anchor-forward: an object never reflows the preceding content that establishes its own anchor position. Flow style spacing sits outside that footprint. Manual x coordinates and anchored annotations still refer to the actual body origin. An over-contracted footprint has zero width/height rather than inverted bounds. Selection/resize handles and hit testing remain on the content; page and reading extents retain both visible content and reserved space, subject to the existing page-edge cropping policy. Focusing a margin field shows a dashed footprint outline; it is absent from reading, minimaps, and exports. Margins survive placement conversion, clipboard operations, history, and file round-trips. Individual AI tasks preserve the user's latest margins; section reservations lock them with the composition.

Opening Settings clears document-object and segment selections. The combined panel follows the selected object, passage, section, preview, or reservation handle: unreserved content offers **Reserve for Assistant**, and reserved content shows its existing task. Caption and table-cell selections reserve the whole owner; main-text selections reserve whole-block segments and their owned objects. Mixed reserved/unreserved selections ask the user to select one reserved area instead of offering task links or a new reservation; independently selected objects are not silently batched. Clearing selection never falls back to an old text caret. There are no task tabs: clearing selection clears the task view, while focusing controls inside Assistant preserves the selected area. **Show in document** deliberately selects and reveals its target. New AI-area creation shows its task immediately. Accept and Discard remove the reservation from the current array and return to normal properties for the remaining selection; Undo restores the task. No retained-task or Assistant recovery-archive UI is shown. Task drafts and results remain available while their task is referenced by the current state or undo/redo history; background completion never takes over the panel. Files → Local recovery remains separate. Settings and the Context/Assistant lane do not change canvas width.

**Object creation** is Flow-first for Text box, Table, Image, Drawing, Code, Formula, and HTML widget. Add and the right-click launchpad arm a top-level boundary picker across the page; nothing is inserted until you click the visible destination. A click creates a centered Flow at that boundary, not at a retained caret or the launchpad origin. Hold **Alt** to replace the Flow preview with a Float-sizing crosshair and grid, then drag to create a Float. Alt-click without a drag inserts nothing. The gesture is fixed at pointer-down: releasing Alt during a drag does not change placement. Escape cancels. Text boxes, Code, tables, and formulas use the drawn width with natural content height; images preserve proportions; drawings and widgets use both dimensions. Creation snaps Floats to the grid even while Alt is held; Alt still bypasses snapping when moving/resizing existing objects. Flow creation uses block boundaries and explicit-space edges, never splits a space interior, and commits in one undo step. The tool exits after insertion. Paragraph stays boundary-only. AI object retains page click/drag area reservation only. Empty section reservations use the normal gutter insertion selection and Reserve for Assistant. File drops remain direct Float insertion; picked and pasted images use the common placement tool. Context can switch placement afterward. Spaces are created/resized with Alt-dragging, not through the object menu. Spaces span the page, including its text margins. Clicking one preserves the text caret rather than selecting the space. Ordinary dragging inside text still selects text; ordinary dragging inside the right margin, other document padding, a space, or the right gutter selects floating objects. The empty left margin and the 24px outer left strip select segments instead. Object interactions take precedence over gap manipulation, and an object drag keeps its original meaning when Alt is pressed to bypass snapping. Floating text and tables share the main text’s composable inline toolbar and document palette. In editing mode, object selection gates content editing/interaction for text boxes, tables, and HTML widgets. Images and formulas remain movable when selected because they have no on-canvas content editor. Reading mode remains directly selectable/interactive without object selection; AI-reserved rich text stays locked.

## Model and boundaries

### English and Simplified Chinese

Mote is English-first, with horizontal mixed English/Simplified Chinese document text. **Document → Layout → Text language** selects English (the default) or Simplified Chinese for the document content, without changing the interface. This language applies to the shared page, including text boxes, tables, captions, drawing labels, minimap snapshots, PNG, and standalone HTML. There are no per-passage language controls or automatic language detection. Vertical writing and language-driven right alignment/RTL layout are non-goals; ordinary table-column alignment is unchanged.

The three semantic typeface choices use installed fonts, not downloaded or embedded document fonts:

- **Sans serif:** English documents prefer Inter, Segoe UI, Helvetica Neue, Arial, Noto Sans, and Liberation Sans before the Chinese fallbacks. Simplified Chinese documents prefer Microsoft YaHei first. Both retain PingFang SC, Noto Sans CJK SC / Noto Sans SC, and system sans serif fallbacks. This keeps English curly apostrophes narrow while retaining Chinese glyph coverage.
- **Serif:** Georgia for English, with Songti SC, SimSun, and Noto Serif CJK SC / Noto Serif SC for Chinese, then the system serif fallback.
- **Monospace:** system monospace, SFMono-Regular, and Consolas, with Sarasa Mono SC, Noto Sans Mono CJK SC, and Microsoft YaHei fallbacks. Chinese glyph coverage and cell-width alignment are best-effort.

Prose and captions use normal word breaking, strict CJK punctuation breaking, and emergency wrapping for long unbreakable strings. **Theme → Defaults → Mixed-script spacing** defaults on and uses CSS `text-autospace` to add visual gaps between Chinese and Latin letters/numbers where the browser supports it. It never inserts spaces into stored or copied text. **Theme → Defaults → Justify text** uses browser-native `text-align: justify` for native prose paragraphs in main text and Flow/Float text objects, including headings, lists, and captions; Separator paragraphs are excluded and final lines remain start-aligned. It has no per-class, paragraph, or inline override. Table column alignment stays unchanged, and Code, formulas, and HTML widget contents are unaffected. **Theme → Defaults → First-line indent** is an optional checkbox. When checked, it uses `text-indent: 2ic` for semantic Body paragraphs in main text and Flow/Float Text objects only; it indents only the first formatted line, while wrapped and soft-break lines start normally. Headings, lists, Separator paragraphs, captions, tables, Code, formulas, and HTML widget contents are unaffected. It is language-independent, independent of justification, and does not rewrite content whitespace or add per-class, paragraph, or inline overrides. Existing CSS `hyphens: auto` remains enabled for backwards compatibility and with justification; automatic hyphenation depends on document language and browser dictionaries. There is no language detection, inserted soft hyphens, or stored text rewrite. Code objects retain literal source whitespace and do not apply mixed-script spacing to their source. New themes start with letter spacing of **0px**, inherited by paragraph and object styles; **em** remains available, and existing saved values and units are unchanged. Title and Heading presets no longer apply negative tracking; existing saved theme overrides are not rewritten. Theme samples include mixed English/Chinese text. System-font availability and browser typography support can still change wrapping across devices; no identical-layout guarantee is made.

Editor composition transactions are grouped by editor and composition identity, without the ordinary typing timeout splitting a paused conversion. Global document shortcuts yield to composing/process-key events, table paragraph-input handling yields to composition, and document-history navigation waits until composition ends. Scoped Chromium checks use browser composition injection, not a native OS candidate window; Windows/macOS input methods and Safari/Firefox still need hands-on verification.

### Spatial instructions

Reserve a segment, passage, or object, then choose **Assistant → Spatial instructions → Annotate…**. The drawing editor shows the current original document through the shared read-only renderer, with Pen, whole-stroke Eraser, Labels, palette, and undo/redo. Underlying content cannot be manipulated while drawing. **Done** or Escape returns to the same working selection. **Edit…** revisits the marks; **Clear** removes them. These controls are shared by Built-in and External, and remain editable while an agent is working.

Markup is a reservation property, not authored content. Each committed stroke/label edit uses ordinary undo, local saving, and reservation synchronization. Deselecting, changing documents, or reloading does not discard saved marks. Accept/Discard removes the reservation and its active instructions together; Undo restores them. Marks are excluded from accepted content, reading, minimaps, public shares, PNG, standalone HTML, and native `.mote` exports. **Download task JSON** for a current reservation can contain its markup.

While editing, annotations overlay every marked active reservation directly on the document, even when it is not selected. Select an annotated reservation to reveal the same centered pen button used by drawings; click **Edit annotations** or double-click its reserved content to reopen spatial instructions. A reservation without strokes or labels has neither canvas editing shortcut: start its first annotation through **Assistant → Spatial instructions → Annotate…**. Clearing all marks removes the canvas shortcuts. The marks follow the current target and canvas zoom without intercepting ordinary clicks or changing layout; only the edit button takes pointer input. Showing a proposal hides that reservation's annotations and canvas editing shortcuts; returning to Original restores them. Accept/Discard removes the overlay, and Undo restores it with the reservation.

Only editable strokes/labels and their coordinate extent are saved—no captured background or separate document snapshot. Coordinates use document pixels relative to the current reserved target, independent of zoom. Segment/passage surfaces cover the page width. Marks follow the reservation origin without semantic attachment or automatic rearrangement when content geometry changes. They describe the reserved original, not whichever proposal is being previewed. The annotation surface never expands the reserved write scope.

The task link returns the latest cloud-saved markup. Agents can reread it and optionally render it with the current document and surroundings using the shared local preview helper; images are not required inputs. Changing marks does not restart generation or guarantee that an already-running agent has reread them.

Permanent image and HTML-widget markup is retired as an authoring feature. Reserve either kind and annotate it through Assistant instead. Existing native V5+ marks still render, copy, and round-trip normally, including reader/export appearance. Their unreserved object inspector offers **Clear existing markup**; existing marks are never silently deleted or converted into reservations.

### Drawings

**Add → Drawing** arms boundary selection: click to insert a centered Flow sketch at its default size, or Alt-drag to choose the width and height of a Float. Creation opens an almost full-screen drawing editor. Select an existing drawing and click its centered pen button, double-click, press Enter, or choose **Edit drawing…** in Context to reopen it. The editor fits the drawing above a floating toolbar while preserving the object's aspect ratio. Done or Escape returns to the document; completed edits save through the normal document history and synchronization.

The toolbar offers Pen, whole-stroke Eraser, typed labels, document-palette colors, a discrete width slider, and undo/redo. Widths are **1, 2, 3, 4, 6, 8, 12, 16, 24, 32 document pixels**, initially **2px**. Magnification changes their screen appearance without changing stored widths. Changing color or width affects subsequent marks only. Each completed pen or eraser gesture is one undo step. Handles on the canvas's four edges crop or extend that side as one undo step, without stretching content: strokes and labels keep their document-pixel size and page position. The More menu contains a Transparent/Solid background control (Solid is adaptive Gray 6), confirmed Clear drawing, and shortcut help. Choose tools in the toolbar; Ctrl/⌘Z and Ctrl/⌘Shift+Z undo/redo. Escape cancels unfinished input before closing. A blank drawing remains available for later work.

Drawings share Flow/Float placement, anchoring, ordering, clipboard, native saving, minimap, and exports with other objects. On the page, the right border and corner handles always keep the aspect ratio; changing proportions is done by cropping or extending in the editor. Resizing scales stroke and label positions while retaining document-pixel pen widths and label font sizes. Editing controls are absent from reading, PNG/HTML exports, and AI snapshots. Viewports below 768px remain reading-only.

Select the sketch and choose **Reserve for Assistant** below its properties to turn it into a figure, then review Original/Preview and accept through the existing Assistant workflow. Unlike ordinary object revisions, a drawing may become another supported floating kind, such as an SVG image or HTML widget. Acceptance is undoable; the resulting object uses its normal editing controls.

### Code, formulas, and HTML widgets

**Add → Code** arms boundary selection: click to insert a centered Flow snippet, or Alt-drag to choose the width of a Float. The new object starts empty with its caret ready. Its plain-text `source` preserves whitespace, grows to its measured content height, scrolls horizontally rather than wrapping long lines, and shows line numbers. The language picker starts with **Plain text**, followed alphabetically by **C, CSS, HTML, JavaScript, Python, Rust, Shell, SQL**. C uses the C/C++ parser. TypeScript, JSON, and other unsupported saved identifiers remain valid and retain their source and identifier, but display as plain text until another language is chosen. The document Light/Dark appearance selects the matching syntax scheme; syntax colors are independent of the palette hues; source is displayed, never executed. Its size, weight, line height, and letter spacing come from the document-wide Code theme style. The typeface is always monospace; the appearance-matched syntax scheme supplies its own background, foreground, and token colors. The Code theme style is under Objects, not Paragraphs.

Height follows every source line, including blank and trailing lines; there is no vertical scrollbar or line wrapping. The horizontal scrollbar appears only when needed. Line numbers and the language header stay fixed while source scrolls. Select one object to edit. The shared CodeMirror editor provides:

- **Enter / Shift+Enter:** carry indentation forward, use the language's block rules, and open a blank indented line between matching brackets. Plain text only carries existing leading whitespace.
- **Tab / Shift+Tab:** insert an indentation unit at the caret or indent/outdent selected lines. Backspace removes a leading indentation step. Existing source supplies the spaces/tabs and indent width; the fallback is two spaces, and literal tabs display at four columns. Opening source never reformats it.
- **Brackets and quotes:** language-aware pairing, skip over an inserted closer, delete an empty pair together, and highlight matching brackets. Notes and plain-text mode do not enable automatic pairing.
- **Ctrl/⌘+/** toggles comments; **Alt+↑/↓** moves lines; **Shift+Alt+↑/↓** duplicates them. Home moves between the first non-whitespace character and the line start. The current line number is emphasized without an active-line background.
- **Ctrl+M** (**Alt+Shift+M** on macOS) toggles whether Tab moves keyboard focus instead of indenting. **Escape** returns focus to the object, collapses Notes, or closes widget source.

Typing, commands, paste, and composition use the single document-wide undo history, including caret/selection restoration. Paste flattens rich paragraphs into plain line breaks and retains blank/trailing lines. Drag the language header to move an object, or deselect it and drag anywhere inside; grouped objects stay in positioning mode. Copy returns the complete source without the header or line numbers. Live reading retains selection, Copy, and horizontal scrolling. HTML files keep selectable source and horizontal scrolling, without a Copy button. PNG captures the visible object width from the beginning of each line, without Copy controls. Blank source objects are removed on deselection, like empty text boxes.

Code, plain-text Notes, and HTML-widget source share the eagerly loaded editing core. Online readers/editors load language definitions on demand for actual objects or the selected language; HTML also supports embedded JavaScript/CSS. Failed language loads retain editable plain text and offer Retry. Editing and static source rendering share parsers, syntax classes, and theme colors. HTML export captures the highlighted source from the shared renderer. It loads only the languages needed by nonempty Code objects; the resulting file includes no language parsers or editor runtime. A failed load leaves the document unchanged and can be retried. Autocomplete, snippets, folding, search panels, multiple cursors, and linting are not enabled; there is no compiler, language server, or automatic formatter.

**Add → Formula** arms boundary selection: click to insert a centered Flow display-mode formula, or Alt-drag to choose the width of a Float. The inspector edits its LaTeX source live, without `$$` or `\[...\]` delimiters; syntax errors retain the source and appear on the object. Width is user-controlled and height follows content. Formulas are centered, never automatically wrapped or shrunk, and can use explicit constructs such as `aligned`. Oversized content follows the existing page-edge cropping policy. **Math style…** opens a global size/color style inherited from Defaults, with px/em units and normal history/reset behavior; math typefaces remain KaTeX's. KaTeX's unsafe HTML commands are disabled (`trust: false`). HTML export captures formula HTML+MathML or errors with the shared display CSS and WOFF2 fonts, without the KaTeX engine. Live reading and PNG use the same renderer. This is not a full LaTeX document engine, and inline mathematics is not included.

**Add → HTML widget** arms boundary selection: click to insert a centered Flow widget, or Alt-drag to draw a Float viewport. It starts with an editable button-counter demo and a neutral screenshot placeholder. No image upload is required; creation previews do not execute widget code. **Edit code…** opens one HTML/CSS/JavaScript source field; drop a single `.html` or `.htm` file into that field to replace the source in one document-undo step. Source edits save immediately, while **Run / Restart** recreates the iframe and executes the current source. Dropping a file does not run it or replace the screenshot. Each widget has its own DOM, CSS, globals, and libraries. Moving, resizing, selecting, changing mode, and front/back ordering retain its running state. Runtime interaction state is not saved or included in document undo; reopening starts from saved source.

HTML widgets resize by dragging their right border or corner handles; corner resizing adjusts width and height independently. Their iframe viewport follows the saved dimensions, while page zoom scales the entire widget. Hover and selection outlines surround only the widget body; its owned caption has a separate outline, matching tables. In editing mode, click/drag an unselected widget’s noninteractive interior to select/move it. Selection directly enables its contents for subsequent clicks and drags, without a separate interaction mode or button. Clicking elsewhere on the page deselects it and makes its interior draggable again. Selection and movement never restart the iframe; only Run / Restart or an explicitly restored source revision replaces its execution. Reading/mobile interiors are directly interactive. Each iframe uses `sandbox="allow-scripts"`, without access to Mote's DOM/storage or top-level navigation. This prevents namespace collisions and limits access, but is not a CPU/memory quota or a promise that arbitrary code cannot affect responsiveness.

Resource references, including CDN scripts and external data, are used as written. Mote does not inspect widget source, bundle or rewrite external resources, or guarantee offline operation for network-dependent demos. Normal browser resource restrictions still apply. There is no separate ECharts object or bundled chart library: authors can embed ECharts with their own script reference.

**Update screenshot** in Context sends only the current saved widget source and dimensions to Mote for a fresh, isolated browser run at 2× resolution. It does not restart the on-page widget, reproduce its current interactions, or require a cloud save first. The previous screenshot stays visible while capturing and on failure; an inline error offers another explicit attempt. A successful replacement is one undoable document edit and syncs normally. Source/dimension changes, history navigation, deletion, AI reservation, leaving editing, or switching documents invalidate pending captures. There is no automatic recapture on code changes, resize, reconnection, minimap rendering, or export. New widgets use a neutral placeholder until their first successful capture; existing embedded screenshots remain intact. The saved image is used for the minimap and PNG export, stretched to the object's saved rectangle; refresh it after code or dimension changes. Minimap snapshots remove live iframe content before insertion; PNG mounts a screenshot-only reader and never starts widget code. HTML exports keep live widgets, not screenshot substitutes. Code, formulas, and HTML widgets share object selection, Flow/Float placement, anchoring, movement, ordering, duplication/deletion, and document history. Of these kinds, only HTML widgets support captions. Float movement uses the page grid; Flow movement uses document boundaries and horizontal center snapping.

### V1–V9 document formats

V9 saves a continuous page, an ordered list of objects, and a flat main flow of paragraphs, explicit spaces, and Flow references. It requires the three document typography switches (`autospace`, `justifyText`, `firstLineIndent`) and represents inline Box as `{type:"box"}`. Object geometry, stable IDs and sparse style inheritance are unchanged. See [FORMAT.md](FORMAT.md) for the native grammar.

Every schema or meaning change gets a new version. `loadDocument` migrates older versions in memory through ordered, pure, ID-preserving steps; loading never saves, and the next ordinary save persists the upgrade. V1→V2 and V2→V3 are non-breaking. The breaking V3→V4 step maps each explicit saved theme weight below 550 to 400 and each weight at least 550 to 700, preserving sparse inheritance, IDs, and unrelated data; it does not add or special-case Heading overrides, and omitted weights continue to inherit from the converted parent/default. V1–V3 retain 1–1000 weight validation for native documents and snapshots; V4 and newer accept only 400 or 700. V4→V5 is non-breaking and preserves existing content unchanged; V5→V6, V6→V7, and V7→V8 are non-breaking and change only the version. V0 is permanently unsupported. If active reservations exist on a breaking path, the owner chooses: **Upgrade** removes the current reservations through an ordinary cloud document save, or **Decline** shows a read-only preview without upgrading the stored version or releasing reservations. Removal does not permanently revoke the stable task token; restoring a reservation and saving it can make the same token usable again. See [FORMAT.md → Versioning and migration](FORMAT.md#versioning-and-migration). The breaking V8→V9 step drops legacy slide boundaries and crops, joins the content in order, and estimates marker-anchored Float offsets without a browser. No spacer or Separator is inserted. Text outside a former crop becomes visible. Other migration changes preserve appearance. New documents and candidate grammar use V9. Unknown or unsupported data gets an actionable error and remains recoverable. Only the current agent protocol, `mote-agent-v7`, is supported; its flat proposal versions and receipts carry no source revision, agent origin, or native document version. Legacy task records remain stored but are not imported into current Assistant state or shown in a task-recovery archive; no compatibility adapter, history conversion, or automatic continuation is provided. General Files local recovery downloads remain. Task-protocol versions are distinct from native document versions. Public readers and HTML publication omit the entire optional `authoring` object; native `.mote` preserves it.

## Document files

The editing header’s **Share** and **Files → row menu → Share…** open the same dialog: **Link** controls the document's single optional latest-version public link; **Export** offers PNG, HTML, and native `.mote`. New documents start with Link off, and opening the dialog never creates a link. For the open document, enabling first synchronizes its working copy; if sync fails, no link or URL is created. For another document, enabling shares its cloud-saved content without syncing or switching the open document. When enabled, the tab shows the URL and **Copy link**. **Replace link** and **Disable sharing** each require confirmation; disabling permanently revokes that URL, and enabling again creates a fresh one. Copying, replacing, or disabling does not require a document save. Private disables only Link and opens Export; offline permits native/PNG export with available assets, and HTML export once the document’s required Code languages have loaded. Link state is server-owned, outside document undo and export settings. Public latest-link readers fetch the current cloud document once when opened; reloading fetches later cloud saves. V9 permanently revokes existing deck links before serving the new layout; continuous-document links stay active. To share a former deck again, review the converted document, save it, and enable a new link. Notes are omitted from public shares. **Files → Import → Choose file…** creates a new cloud document rather than replacing the open one. Ctrl/⌘S synchronizes the active working copy.

Each unarchived Files row menu places **Archive** between **Rename** and **Delete**; archived rows show **Unarchive** in the same position. The **Archived** group and **Local recovery** share a bottom-aligned stack with one divider above it; both start collapsed each time Files opens. Spare space separates them from short unarchived lists; long lists and expanded sections scroll together. Recovery expands without leaving Files or resetting its search, sort, or archive state. Its Open working copy, Download recovery, and confirmed Discard actions retain their existing local-copy semantics; the earlier browser draft remains download-only. Files has no status footer or routine progress/success messages; disabled controls indicate an operation is in progress, and the updated list shows completion. Failed operations open a dismissible error popup without losing the current form or list context. Failed list loads offer Retry in the popup and in the list after dismissal; authentication failures offer a sign-in link. Both groups share search and row actions, sort within their groups, and search does not expand Archived; the main count shows matching unarchived files and the Archived heading counts matching archived files. Archiving or unarchiving needs no confirmation, and a row moves only after server acknowledgment. Archiving the open document leaves it open; opening or editing it later does not unarchive it. New, imported, and **Save as copy** documents start unarchived, and exports omit archive state.

Opening Share from Files preserves the list’s search, sort, scroll position, and row focus on return. The open document exports its current working copy, including unsynced edits. Other documents are fetched and validated when the dialog opens; exports use that cloud snapshot, not local recovery copies. A pending-local-change hint makes this distinction explicit. Loading failures can be retried or dismissed without changing either document. An already loaded source remains exportable offline subject to required Code languages having loaded for HTML export; fetching another document requires a connection. Unsupported documents remain unchanged and produce an actionable error; pending AI candidates are never exported.

Internal Notes are preserved only in native `.mote` exports. Preview, PNG, and HTML show the page without notes.

The **Filename** field starts with the selected document’s name and supplies the export name, with the selected extension added automatically (an existing PNG/HTML/Mote extension is replaced, not duplicated). Where `showSaveFilePicker()` is available, export opens the browser's native Save As dialog with that suggested name and format filter. The picker is invoked directly from the click before export preparation; canceling does not generate or download a file. Bytes are written only after generation succeeds, and success is reported after the writable stream closes. Elsewhere, Mote uses an ordinary download with the chosen filename; browser preferences determine whether it prompts for a location. The filename is session-local UI state, not part of the document.

- **PNG:** one full-length image with a resolution selector in the PNG row: **1×** (original size) or **2×** (high resolution, default). The selector is export-local UI state, not document content. At 2×, each document CSS pixel gets two output pixels per axis (four times the pixel area); a 960px-wide page exports at 1920px. Text, formulas, and vectors render directly at the selected resolution rather than enlarging a finished bitmap. Embedded images and widget screenshots use a matching raster scale, but remain limited by their source detail. Layout stays at native document size after images/fonts/layout settle, independent of display density, scroll position, and view zoom, including the theme background, spaces, tables, drawings, formulas, and floating objects. The page's horizontal edges crop overflowing content; the width never grows to accommodate objects. Fractional pixel extents round upward. No app chrome, page shadow, selection controls, or added bottom padding. Animated images become a still frame. Output dimensions are capped at 32,767px per axis and 32 million pixels in total; smaller browser limits can also prevent export. It checks rasterization support and reports failures rather than silently shrinking/truncating the document. Oversized 2× exports suggest trying 1×; HTML and `.mote` remain alternatives. Scoped raster checks use Chromium; other engines' HTML-in-SVG raster support varies.
- **HTML:** a single read-only page that opens directly from disk. It keeps selectable prose, links, tables, drawings, images, highlighted source, and formulas with embedded math fonts. Widgets remain interactive in sandboxed iframes and may need a connection for their own resources. There is no Mote runtime, minimap, internal Notes, or embedded native document. Use `.mote` for an editable copy.
- **Mote document (`.mote`):** binary gzip of UTF-8 JSON containing a V1, V2, V3, V4, V5, V6, V7, V8, or V9 `MoteDocument`, including `format: "mote"`, its version, IDs, theme, nested layout, rich text, `authoring` notes/model override, and embedded assets. There is no archive manifest, custom binary header, encryption, or base64 wrapper around the file. Session history, selection, zoom, and browser preferences are excluded. Both compressed and decompressed data are capped at 128 MiB. V1–V9 are supported; unknown versions and schema changes are not silently converted. Ordinary gzip tools can inspect the JSON.

Import accepts only `.mote` files. The gzip payload is validated and migrated through the native V1–V9 load path. Import creates a new file with a fresh document ID; unsupported or corrupt files do not alter existing documents. Previously downloaded HTML reader files still open in a browser but cannot be imported.

**Native printing:** open Preview or another reader and use the browser’s Print command (Ctrl/⌘P), selecting Save as PDF where available. Print CSS hides the minimap, code-copy buttons, and reader notices; removes initial screen-fit scaling; and leaves pagination, paper, margins, headers/footers, and destination to the browser. This is not a dedicated PDF export: pages can split compositions. Review the browser preview for clipping, floating-object placement, and widget output.

PPTX export and dedicated PDF generation/pagination remain deferred. PNG and HTML cannot be imported back.

## Structure

```text
src/cloud/      working-copy sync, connection recovery, routing, Files/Share/Settings dialogs
src/app/        application shell, controls, responsive styles
src/document/   V1–V9 model, IndexedDB, history, validation, file codecs/PNG export, clipboard, Code language IDs
src/editor/     constrained Tiptap schemas, inline formatting, shared source editing/highlighting, lazy language definitions
src/canvas/     measured anchors, Flow mounts, Float layer, owned captions, spatial interactions, shared reader, zoom, minimap
src/theme/      semantic styling, shared palette, theme-derived UI colors and controls
src/reader/     shared reader shell, local Preview, single-file HTML export
src/ai/         reservations, task state, service client, review UI
shared/         closed native validation/migrations, fixed palette and safe-link rules
public/skills/  unversioned public agent entries, shared references, and portable helpers
server/         moted, cloud store, worker isolation, private task API, preview/delivery helpers, fake runner
```

Native validation and palette-slot validity come from `shared/`; UI controls do not maintain a second document validator. Palette colors are derived once per theme-variable build or drawing-extraction operation, while recent-color slots track the fixed palette references independently of appearance. Browser preferences belong to editing surfaces; readers use their shared presentation defaults without a separate settings mode.

Flow atoms expose noneditable mount points inside the main editor. `DocumentCanvas` portals the existing object renderer and any built-in caption into those mounts, using their actual normal-flow heights rather than saved-height spacers or absolute overlays. Float objects remain in the spatial layer. Editing, shared reading, minimap snapshots, PNG, and standalone HTML use this same rendering path.

Preview and Share mount the same `ReaderPage` over `ReadDocument` and `DocumentCanvas`; only the source of the document differs. Preview passes the published working copy over a browser-local message port to `/preview`. The URL carries no document data and cannot reopen the snapshot by itself. Share reads the latest saved revision through its existing capability endpoint.

HTML export serializes the same settled, authored-width sheet as PNG. Flow objects and captions stay in normal layout. Float order and measured wrap shapes are baked in; CSS anchors follow originating blocks where supported, with measured page positions as the fallback. Different fonts and hyphenation can shift wrapping. The renderer is shared; the exported page does not remeasure layout with Mote code.

The minimap shares the rendered page through an inert, noneditable DOM snapshot, with editing controls and accessibility duplicates removed. The initial snapshot renders immediately when the minimap mounts, with subsequent updates batched through the existing animation-frame scheduler. Both sizing modes share this renderer and navigation geometry. Proportional mode keeps the page's aspect ratio and scrolls the miniature for long notes; fit mode compresses only the vertical axis as needed. Main-document zoom changes the viewport indicator, not miniature content scale. Scroll-only updates translate the existing snapshot and indicator; layout/content changes refresh the snapshot once per animation frame.

Editing allows scrolling past the document bottom until it sits about 15% down the canvas viewport. This view-only room adapts to viewport height, shares clearance with the Notes overlay, and never changes document geometry or exports; reading/mobile retain their normal bottom clearance. The minimap keeps the real page snapshot and tracks the full scroll range.

Blank documents show **Start writing…** in their sole empty paragraph and focus it on opening. Clicking unused space below the final main-flow block, outside the left selection margin and into the scroll-past-bottom area, continues writing at the logical end—not at the clicked height. A final paragraph receives the caret at its text end. A final explicit space or Flow object (including its caption) offers a temporary Body writing position with only a caret, no placeholder text. Clicking alone changes neither content, page geometry, history, nor exports; typing/pasting commits normal paragraphs, and Enter commits an empty paragraph plus the next writing line. Escape or clicking away dismisses the uncommitted caret. Floats keep their own interactions and can extend the visible page without changing the main-text destination. Side gutters, modifiers, creation tools, and reading/mobile keep their existing behavior. The blank-document placeholder and temporary caret are omitted from minimap snapshots and exports.

Main-text insertion carets at Flow/space boundaries and before leading blocks use the same vertical, Body-colored caret as the temporary end position. They follow Body typography and first-line indentation, and the adjacent blocks' spacing without inserting placeholder paragraphs or moving existing content. Gap carets appear only after their position is measured. Native carets paint in paragraph text, not structural containers, avoiding a misplaced flash while the browser/editor resolves boundary clicks. Click destinations and native text dragging are unchanged. Leaving a gap selection to edit a Flow object's text, table, caption, or source preserves that nested editor's caret and selection visibility.


## Deployment

The durable compatibility boundary is native `.mote` documents, not agent protocols or internal SQLite schemas. Backups are primarily manual collections of native document exports. Historical database migrations and cross-version database snapshot restores are not maintained; use the matching old build to export documents for recovery. This does not authorize resetting live storage. See [CLOUD → Manual backup](CLOUD.md#manual-backup).

The current app is live at **https://mote.ylxdzsw.com**. Nginx serves `/var/www/mote` using `/etc/nginx/conf.d/mote.conf`, with the existing wildcard origin certificate and workspace cookie gate. Documents/AI require login; explicit shared reader URLs bypass it. Deployment includes the durable `moted` service, with no scheduled backups. See [CLOUD.md](CLOUD.md) for manual backup and restore instructions.

The deployment sets `Cache-Control: no-store` and disables Nginx ETags/expiration for HTML, JavaScript, CSS, and fallback responses. Cloudflare receives the origin directive and currently reports `DYNAMIC`/`BYPASS`, so the pre-release build is not cached at the edge. There is no service worker. Intentional IndexedDB document persistence is separate from HTTP caching. For each task, build with `npm run build`, publish `dist/` assets to `/var/www/mote` before replacing `index.html`, then run `nginx -t && systemctl reload nginx`. Verify the live HTML and its referenced assets against the build and check `Cache-Control: no-store`. Publish files with Nginx-readable permissions (normally 0644; for example, `install -m 644`), rather than preserving restrictive source permissions. Keep backend code outside the static directory. Restart `moted` only when backend changes require it, after checking active tasks/workers; preserve cloud documents, AI state, and manual backups. See [Storage and service](CLOUD.md#storage-and-service).

Vite development and preview responses also send `Cache-Control: no-store`. `public/_headers` carries the same rule for static hosts that support that format. Other hosts must explicitly set `Cache-Control: no-store` on **all** responses, including HTML and built assets.

Publish `dist/skills/` with the other static assets. Its Markdown, helper source, and harness are served as inert plain text; agents download them for local use. Keep the canonical helpers in `server/` and their public copies in `public/skills/helpers/` identical when changing delivery or preview. Built-in workers read `public/skills/` from the read-only source tree, so those source files must also be readable by the `mote-ai` worker (normally 0644, directories 0755).

Review the early-development decisions in `.mu/AGENTS.md` before a release.

## Verification

Run `npm run build` for TypeScript checking and the app and agent-preview builds. Run `npm run test:ai` for essential Flow/clipboard/caption/migration, reservation, transport recovery, fake-backend, cloud CAS/privacy, and task access invariants without real model calls. The backup tests use isolated temporary data; they do not back up production. Test definitions in `package.json` and `tests/`/`server/*.test.mjs` are the source of truth for automated coverage.

For UI changes, use an isolated fake backend and a scoped Chromium check against dev or the production preview. Set `MOTED_DEV_ORIGIN` to the browser's exact origin, including the preview port. Exercise the changed interaction, undo/redo and persistence where relevant, desktop and compact editing (including 768px), and fresh mobile reading below 768px. Review rendered output and browser errors. Changes to layout, objects, captions, or the document schema also need the affected shared-reader, minimap, clipboard, native round-trip, HTML, and PNG paths checked. Use focused checks for the changed invariants; there is no general browser regression suite.

Browser automation does not certify native OS IME behavior, physical trackpad gestures, or Safari/Firefox rendering. System fonts can alter wrapping, and PNG raster support varies by engine. Development notes in [.mu/MEMORY.md](.mu/MEMORY.md) record historical checks and limitations; they are not a claim that every old fixture or interaction still exists.

GitHub Actions runs on push, pull request, and manual dispatch. On Ubuntu with Node.js 22 and 24, it installs the lockfile with `npm ci`, runs `npm run build`, and runs `npm run test:ai`. Only npm's download cache is reused. CI does not deploy the demo, run browser checks, or call model providers. See [.github/workflows/ci.yml](.github/workflows/ci.yml).
