# Mote

[![CI](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml/badge.svg)](https://github.com/ylxdzsw/mote/actions/workflows/ci.yml)

A private, AI-native document workspace combining semantic text with anchor-relative spatial placement. Documents live in the cloud, with independent local working copies and explicit conflict resolution. See [Cloud workspace](CLOUD.md) for saving, sharing, recovery, authentication, and operations.

## Run

Use Node.js 22.12+ (or a current release) and npm.

```sh
npm install
npm run dev
```

Run the fake backend below, then open **http://127.0.0.1:5173**. The exact origin must match `MOTED_DEV_ORIGIN`; use an isolated state/data directory. Vite proxies `/api` to port 5174. Do not expose development or fake services publicly. Browser recovery remains origin-specific.

```sh
npm run check   # TypeScript
npm run build   # TypeScript + production bundle in dist/
npm run preview
npm run test:ai # Essential reservation and fake-backend checks; no model calls
```

## AI assistant

The **Context** panel offers **Revise this passage** for main text and **Revise with AI** for a floating object. A gutter segment selection generates a native composed section: an empty segment inserts at that point; a nonempty segment replaces its paragraphs, explicit spaces, and owned floating objects. Without a segment selection, revision replaces all paragraphs touched by a text selection, or the whole paragraph at the caret (including an empty line). **Add → AI object** arms a drawing tool for a new floating area. The **Assistant** tab contains the request and review workflow; multiple reservations have their own session tabs. Describe a research, writing, formula, diagram, table, or interactive-object task and choose **Preview candidate**. **Document settings → Layout → Mu model** accepts an optional raw Mu model reference; blank inherits the workspace default. Explicit overrides belong to the document and round-trip through `.mote` files; credentials do not.

**Files → Management** sets workspace defaults for built-in agents and indexing. Blank built-in inherits `MOTED_MU_DEFAULT_MODEL`, then Mu's configured default; blank indexing inherits the workspace built-in default, not a document override. New documents inherit rather than writing a fixed model override. Existing explicit document overrides and existing agent-session models are unchanged. References may be fixed `provider/model:effort` or floating `model:effort` for Mu's configured provider fallback. Settings are revision-checked cloud metadata, outside document content/undo/export. Opening Management never probes a model; enabling auto-indexing authorizes background model work.

**Auto-index documents** is off by default. When enabled, saved documents are indexed after 100 seconds without another content save (10× the autosave interval), including after the browser closes. The indexer receives the complete native document and writes a concise discovery description, choosing important topics and useful visual/interactive material rather than inventorying every object. Private documents can be indexed for their own built-in agent. Status and explicit failed-work retry are available in Management. Disabling pauses work without deleting completed indexes or changing session retrieval permissions.

Each agent session separately enables **Use workspace documents** (built-in) or **Allow workspace reads** (external). The server confirms this permission; executor changes reset it. Enabled agents can download a permission-filtered `workspace-index.md`, **search the file rather than read it whole**, and fetch full relevant native documents before referring to them or reusing sections/compositions. Descriptions are discovery hints, never evidence. Current privacy applies to every index/source request, including historical reads; disabling blocks future reads but cannot recall previously fetched context. Retrieval does not expand the reserved write region or bypass candidate acceptance. A direct user-query interface is deferred.

### Availability and retry boundaries

Opening, editing, saving, exporting, sharing, and managing files/settings do not require Mu or a working provider. An agent failure retains its reservation/result for explicit Retry or Discard; unrelated content stays editable. Mu default resolution is asynchronous, limited to five seconds, and runs only when an authorized generation/indexing job needs it. Worker attempts are deadline-bound (15 minutes by default); failed or interrupted attempts require explicit retry, including after a server restart. Indexing never blocks ordinary cloud saves.

Mu itself has a finite provider retry budget: five retries after the initial request for a fixed provider, or three per configured floating candidate, with 1/2/4-second backoff and bounded `Retry-After`. Mote does not add a generation retry loop. Worker cleanup uses bounded subprocesses and six progressively spaced state checks. Unconfirmed cleanup retains the execution/artifacts and blocks subsequent built-in runs until service recovery, rather than releasing isolation or probing indefinitely.

AI and cloud HTTP requests have a 15-second deadline including response reads. Healthy task checks are about two seconds during active work and ten seconds after completion. Transient status failures back off 10/20/40 seconds, then pause after four failures; access/permanent client errors pause immediately. **Check status** resumes monitoring, not generation. Transcript failures close the stream and require **Reconnect**. Assistant-state refreshes do not accumulate overlapping requests and pause on sync errors/conflicts until explicit Retry. Local recovery and manual editing remain independent of those assistant operations.

Generated segments have **free height at the document width**. They may combine semantic main text, explicit spaces, and multiple native floating objects, with internal connectors and attached labels. They are not flattened into one widget. The existing document theme and neutral colors apply; referenced color families are merged without changing existing colors. The gutter selection's anchor-based ownership defines the replacement scope, not visual intersection. Alt-split spaces retain their unselected pieces and objects. The selection height is context, not a fixed output box; following content reflows naturally.

Each reservation has an **Agent & access** disclosure with the **Built-in / External** switch and workspace-read permission. Built-in keeps the chat workflow and creates no public grant. External replaces the composer with **Copy instructions** and **Copy link** so an agent on any machine can download the full immutable document, target, rendered snapshot, exact-version guide, and portable submission/preview helpers. Selecting External grants access; copying does not create another link. Controls stay disabled until the server confirms a switch. An uncertain response keeps them disabled with **Retry confirmation** and opens the access disclosure. Returning to External creates a fresh link; old links and old built-in runs never regain delivery rights. Switching back to Built-in does not start generation automatically, and completed candidates survive switching.

The link is a secret bearer capability: anyone holding it can read the entire input snapshot and submit a replacement for the reserved region, but cannot save the document or accept changes. External results use the same validation and inline review as built-in results. Access ends on switching back, acceptance, discard, region deletion, or document deletion; closing the tab does not revoke it. Revocation blocks future reads/submissions, not downloaded copies or an external process already running. External status is **Awaiting submission**, not a claim that Mote is monitoring the agent. Handoff credentials stay outside document exports and task recovery JSON.

Tabs retain requests, streamed agent output, and follow-ups within the same session. New reservations activate their tab; **Request…** on a reserved region opens its matching tab, and **Show in document** selects and reveals that region. Arrow keys/Home/End navigate the tab strip. Draft requests and tab order survive reload. Background completion updates status without changing the active tab. **Stop** and errors retain the reservation; **Accept**, **Discard**, and explicit region deletion release it and close its tab. Closing the pane only hides it; after the last reservation is released, the ordinary inspector returns. Deleting a reserved floating object with Delete/Backspace, or choosing **Delete region** in its on-document controls, abandons its task. Paragraph controls also provide **Delete region**. Undo restores deleted document content as ordinary content, never an agent session or its reservation. Ordinary cross-boundary typing/cut/history edits remain protected.

The read-only transcript uses lazy-loaded `ansi_up`, not a terminal emulator or an interactive shell. Mu's piped `-o concise` output is append-only; ANSI styling is supported, raw HTML is escaped, and terminal hyperlinks are disabled. Output follows the bottom until you scroll up; **Latest** resumes following. Only the active tab has an SSE connection, while background tasks keep their existing status polling. Switching tabs/reconnecting replays missing events; earlier requests stay visible across revisions. Transcripts have bounded retained history with omission/failure notices, and are separate from document persistence and exports. Candidate validation—not transcript text—still determines readiness. **Help & privacy** explains reservations and data sharing; with actionable authentication feedback on failures.

The assistant shows a session strip when multiple tasks exist, followed by the active task title and anchored scope. Before the first request, the Request composer sits below the scope with a data-sharing reminder. Submitted requests use ordinary UI text; technical Mu output remains monospace. Activity opens while work is running and is initially collapsed after completion; it can be reopened without losing the transcript. Review has its own summary, **Original / Preview** view selector, and **Accept / Discard** actions, separate from the follow-up composer. The composer stays at the bottom on normal-height screens; short windows scroll the whole task to keep review actions accessible. The panel shares the Context lane’s 288px desktop / 268px compact width. It retains the document-matching surface and theme accents.

The first built-in request or external handoff uses an acknowledged immutable cloud revision of the **entire document**, including embedded assets, and a full rendered PNG snapshot. Both executors receive the selected target, the [Mote task guide](server/guide.md), and the same validated submission contract. Built-in workers additionally have read-only source and local environment guidance; external agents need no Mote checkout or Mu installation. Ordinary cloud saving uploads documents to Mote; built-in generation shares that document with the configured model, and External grants its holder download access. Manual editing does not require a successful model call. Later executor switches and follow-ups retain the original input snapshot.

Concurrent tasks reserve nonoverlapping content through generation and review. You may edit other regions and move individually reserved objects. Before the first request or external handoff, individually reserved floating areas can also be resized; preparing either freezes their dimensions with the snapshot. Once a request has been sent, size stays locked through review, including after Stop. Their content stays locked throughout. Segment-owned objects are locked as a composition, including placement. A partial-space segment locks its touched spacer's structure/height, but not surrounding paragraphs or unowned floating objects; two tasks cannot independently reserve pieces of that same spacer. Empty insertion bookmarks survive unrelated edits and reject losing or replacing their reserved boundary. Text selections still expand to whole consecutive paragraphs, without splitting paragraphs or crossing spaces; use the gutter segment selection to include spaces. Paragraphs, segment regions/insertion points, and floating objects share striped reservation treatment. Reserving or discarding an empty paragraph or segment does not add a saved placeholder. Cross-boundary edits and history operations that would change a reservation are blocked.

Ready candidates appear automatically **in place on the editing document**, without modifying its saved content. Selecting a reserved object or segment, placing the caret in reserved text, or clicking/tabbing into a candidate reveals **Original / Candidate**, **Accept**, and **Discard** controls. These use compact on-document buttons, with no reservation-status title; the sidebar remains available for requests and follow-ups. Paragraph and mixed-segment previews reflow the document and its anchored objects; individually reserved floating previews follow their current placement. Generated widgets execute only in sandboxed, opaque-origin frames. Reading and exports use the accepted document, not pending previews. **Accept** makes one document-history change, including an entire mixed composition and any palette additions, while preserving unrelated edits. **Stop** retains any previous complete candidate; **Discard** releases the reservation and removes a newly drawn floating area; existing paragraphs, segments, and objects remain. Follow-up requests reuse the task's Mu session when available. Accepted content consists of ordinary Mote blocks and objects. Drawn floating areas use ordinary draft placeholders; pending candidates and task records are separate from document exports. AI requests, snapshots, and candidates are cloud-associated and recover across devices. Local task-state copies use their own revision checks; conflicting or stale candidates remain inspectable without locking or changing incompatible content. Acceptance is a local undoable action, and the candidate is retained until that exact accepted document is acknowledged by the cloud. Switching documents does not abandon tasks.

Drawn areas are generic **New floating object** requests, not specifically figures or HTML widgets. New candidates may use Code, KaTeX, text, table, rectangle, ellipse, line, label, image, or HTML. The agent guide includes direct native examples for Code and KaTeX; neither needs a screenshot. Existing-object revisions retain their kind. The first object request captures the current document and resized area; later follow-ups reuse that immutable snapshot.

### Fake-first development

Run the app at the exact development origin below and start a fake service in another terminal:

```sh
MOTED_FAKE_RUNNER=1 MOTED_USE_SYSTEMD=0 MOTED_PORT=5174 \
  MOTED_DEV_ORIGIN=http://127.0.0.1:5173 \
  MOTED_STATE_DIR=/tmp/moted-dev/ai MOTED_DATA_DIR=/tmp/moted-dev/data \
  node --experimental-sqlite server/moted.mjs
```

Vite proxies `/api` to port 5174. The fake runner is selected only by server environment, never by a request parameter, and makes deterministic visible changes without calling Mu. `npm run test:ai` exercises critical document CAS, sharing, recovery, backup, reservation, validation, and task-lifecycle invariants without a browser, systemd worker, or provider call.

### Pre-release service

The app and AI controls use same-origin APIs behind the existing `nginx_auth` cookie gate. Private navigation uses Nginx’s existing `/var/www/login.html` gate, preserving the requested URL through sign-in; there is no Mote-specific login page. `/` and `/d/:id` require login. Private mutations require the exact allowed Origin. The single key represents one trusted workspace, not separate users. Explicit `/s/:token` read-only shares, their scoped data endpoint, and reservation-scoped `/api/agent/:token` capabilities bypass login. Capability requests authenticate the token, not a workspace cookie or Origin; Nginx does not access-log that route. See [CLOUD.md](CLOUD.md).

Document settings has a **Private** checkbox, separate from content and undo. Enabling it revokes public sharing and external-agent access, without disabling the document's own built-in agent or discarding completed candidates. Disabling it does not revive old links. Files marks private documents; owner access remains unchanged. Private controls access, not trusted indexing. The [Document Private policy](CLOUD.md#document-private-policy) governs every index and cross-document read.

`moted.service` runs the Node supervisor at `/run/moted/moted.sock`, storing cloud documents in `/var/lib/mote/documents.sqlite` and durable AI sessions in `/var/lib/mote-ai`. Each task runs Mu and Chromium as the unprivileged `mote-ai` user in a transient systemd service. Workers cannot access the document database, backups, Nginx credentials, or sibling task directories. Each receives its own explicit read-only snapshot and approved source/config resources. Workers still have outbound networking and configured provider access; this is not a hostile-user multi-tenant sandbox.

See the [service](server/moted.service.example), [Nginx deployment](deploy/mote.nginx.conf), and [manual backup command](CLOUD.md#manual-backup). Defaults are two workers, 15 minutes per run, 2 GiB memory, and 200% CPU per worker. Request bodies are capped at 128 MiB, result JSON at 8 MiB, and each widget screenshot at 10 MiB. The backend never executes candidate HTML. Task workspaces/results no longer expire on a 24-hour timer; explicit task resolution controls cleanup. Inspect failures with `journalctl -u moted.service`.

`GET /api/ai/tasks/:id/events?after=N` serves the cookie-gated SSE transcript. `Last-Event-ID`, if supplied, takes precedence over the query cursor; the frontend reconnects only on an explicit action after failure. `transcript` events contain `{ id, attempt, kind, text }`, where IDs increase within the task, attempts start at 1, and kind is `request`, `stdout`, or `stderr`. Requests are recorded when queued, even if stopped before a worker starts. `reset` indicates that the cursor is outside retained history; `warning` reports output limits or storage failure. Heartbeats run every 15 seconds. Nginx buffering stays disabled and stream responses send `no-store, no-transform`. Only selected Mu output is exposed, not raw session/provider journals or configuration. Task mutations are serialized so discard/delete cannot race a revision into an orphaned worker.

Server transcript defaults are 2 MiB / 2048 events, at most 128 KiB per event and 256 pending writes; slow SSE clients disconnect at 128 queued events or 512 KiB. Per-attempt stdout/stderr logs each retain at most 1 MiB, with old logs trimmed to a 4 MiB task-wide default after each attempt. Environment overrides are `MOTED_TRANSCRIPT_MAX_BYTES`, `MOTED_TRANSCRIPT_MAX_EVENTS`, `MOTED_TRANSCRIPT_MAX_EVENT_TEXT`, `MOTED_TRANSCRIPT_MAX_PENDING`, `MOTED_TRANSCRIPT_HEARTBEAT_MS`, `MOTED_LOG_MAX_BYTES`, and `MOTED_LOG_TOTAL_MAX_BYTES`. Frontend history is capped at roughly 512K text characters / 2000 chunks per tab. Task-local transcript replay survives supervisor restart and remains bounded; it is not unlimited chat storage. Missing backend sessions offer accept/discard rather than an endless retry. If server cleanup fails, local release remains final and a notice explains that unconfirmed execution artifacts remain retained.

Once selected, clicking or dragging inside edits/selects text instead of moving the object. Click elsewhere on the page to deselect and move it again. The **top, left, or bottom border always moves**, and the **right border resizes**; no extra movement handles or expanded border targets are used. There are no delete buttons, corner resize handles, or anchor markers. Focused objects move with arrow keys (Shift for 1px); their right borders support left/right arrows for width. Press Delete/Backspace with the outer object focused to remove it immediately; Undo restores it. Undoable actions do not ask for confirmation.
- Floating images share the same anchor, drag, resize, and delete behavior. Drop one or more local images onto the document, or use **+ → Image** to choose a PNG, JPEG, WebP, GIF, or AVIF (up to 10 MB per file); images are embedded in the local working copy and uploaded with cloud synchronization; SQLite deduplicates embedded image data internally. An explicitly requested AI task includes them in its full-document snapshot. A multi-image drop is one undo step, uses the drop position at any zoom, and rejects the whole batch if a file is invalid. Resizing preserves proportions. Select an image to edit its accessible description or replace its file in the sidebar.
- **External image paste:** pasting a single image file arms a one-shot placement tool with a translucent image preview and the shared grid. Click to place at a sensible default size, or drag in either direction to size proportionally; Alt bypasses grid snapping. Enter places the default size at the retained main-text caret or segment insertion point. Escape, blur, outside clicks, another tool, zoom/mode changes, history navigation, and document edits cancel without inserting anything. Confirmation selects the image and is one undo step. Native Mote object/segment/paragraph paste, mixed text content, source inputs, widget frames, and image drops keep their existing behavior. Clipboard image data uses the same validation and 10 MB limit as uploads; HTML-only remote image URLs are not fetched. Paste one image at a time, or use a batch file drop.
- Floating tables use the same selection-first interaction as text boxes: drag an unselected table from any cell to move the table; select it first to edit/select cell contents or resize internal column dividers. Once selected, click a cell, use Tab / Shift+Tab to navigate, and add/remove rows or columns through the sidebar. Every cell uses the global **Table** paragraph class, independent of Body but with the same preset. Table is available in the theme editor and through **Table style…**, never in the normal paragraph-class dropdown; the toolbar shows a fixed Table label inside cells. Composable **Bold**, palette colors, and **Box/Underline** remain available. Each cell contains exactly one paragraph: Enter, Shift+Enter, and Ctrl/⌘Enter insert soft newlines, not paragraph spacing. Pasted paragraphs/headings flatten to newlines while preserving text and supported inline marks. Pasted table/spreadsheet ranges still fill separate cells. Tables support cell selection, rich-text paste, and document-wide undo/redo for text and row/column changes. The last row and column cannot be removed through the sidebar; delete the floating object to remove the entire table.
- Rectangles, ellipses, lines, and labels are regular floating-object kinds, sharing anchoring, movement, selection, marquee selection, grid snapping, ordering, persistence, undo, zoom, and minimap behavior with text, images, and tables. Rectangles can be square or rounded; ellipses can be circles; both have per-object fill/stroke colors, width, and Solid/Dashed outlines. Lines can be straight or simple elbow routes, have per-object stroke settings, arrows at either end, draggable endpoints, and optional connections to floating objects. Default strokes follow the Defaults font color; shape fill defaults to None. Labels are single-paragraph rich text using the fixed Label class (Caption-equivalent presets, independently editable), never wrap automatically, and can attach to object center/top/bottom or to line center/left/right/above/below positions. Labels fit their text height and show a hover outline in editing mode. Top-outside and bottom-outside attachments use a gap of one third of the resolved Label font size (4px at the default 12px); inside and line attachment gaps remain 8px. Double-clicking an attachable object selects or creates its label; labels can be detached and remain independently movable. Like text boxes and tables, an unselected label moves by dragging its text; once selected, its text accepts ordinary caret placement and text-selection drags. Enter finishes label editing and Shift+Enter inserts a soft break. Empty/whitespace-only labels and text boxes, including zero-width-only text, disappear when editing/selection ends; blank formulas are cleaned up on deselection. Empty tables retain their editable grid. Abandoned empty content is also cleaned up when opening a draft for editing, never by reading-only views. Zero-length line gestures do not leave invisible objects.
- A **page-wide 16px dot grid**, with one origin at the document's top-left, appears only while dragging or resizing floating objects, including creation and table-column resizing. Objects snap to that same grid in both text and space areas; Alt bypasses snapping but not page bounds. Resizing or merging spaces never moves the grid origin. Selection, text editing, hover, marquee selection, reading mode, and the minimap do not show it. Dragging unoccupied document padding (all four sides), inserted space, or the surrounding gutters, outside the left segment-selection strip, starts rectangular marquee selection for any floating kind; Shift adds. Transparent shape interiors are click-through, while filled shapes and images can be moved from their interiors. Marquee and group movement preserve relative positions, and attached line endpoints/labels follow their targets.
- **Table columns** resize by dragging internal dividers, adjusting only the two adjacent columns while preserving total table width. The outer right border resizes the whole table proportionally. Dividers support Left/Right arrows (Shift for 1px), a 40px minimum where space permits, and Escape cancellation; zoom/mode changes cancel an active drag. Drag previews are transient and each release is one undo step. **Left / Center / Right** in the inspector aligns the entire column containing the caret, or all columns intersecting a rectangular selection. Mixed alignment leaves all three buttons inactive. New columns start left-aligned with an equal-share weight; adding/removing columns preserves the relative widths of surviving columns. New rows follow existing column alignment.
- Configurable document width (320–2400px, initially 960px) and four margins (initially 48px each). Left/right main-text margins can be linked or edited independently and always leave at least 120px for text. Top/bottom margins are independent (0–2400px): top spacing precedes main text, and bottom spacing follows the last main-text block or lowest floating object. The page remains continuous, without a minimum page height or branding footer; explicit spaces are retained. Changes are immediate and locally saved, with no Apply/Cancel stage.
- **Notes:** each document has an initially empty plain-text scratchpad for outlines, backup content, and plans. Open Notes below the canvas; its independently scrolling pane leaves Context/Assistant visible at full height. Drag the top divider or focus it and use Up/Down (Home/End for the size limits). Escape from the text area collapses it. The browser remembers open state and preferred height, initially collapsed at 200px; short windows cap the pane to preserve canvas space. A dot marks nonempty notes. Reading and mobile hide the pane. Notes save and recover with the document, survive duplication and native `.mote` export/import, and are omitted from public shares, PNG, and HTML—including HTML's embedded reimport payload. Authorized agents can read notes as tentative working context, but cannot edit them. Indexing may use notes as supporting context without treating plans as already-written page content.
- One chronological undo/redo history covers text across editors, internal Notes, paragraph/inline formatting, table structure, layout/theme changes, space insertion/resizing/removal, and floating-object creation/deletion/geometry/image changes. Numeric-field focus sessions, color adjustments, and continuous typing are grouped; each released layout drag is one step. Toolbar Undo/Redo and Ctrl/⌘Z / Ctrl/⌘Shift+Z (also Ctrl/⌘Y) work across editor focus and panel closing. Text/numeric settings inputs keep native input undo. History keeps up to 100 steps in memory and is cleared on reload or confirmed Reset to example; saved documents do not contain history.
- A live minimap on the left of the canvas shows text, semantic colors, whitespace, and floating boxes. Click a region to navigate or drag the shaded viewport to scrub vertically; horizontal position and editor selection are preserved. Wheel scrolling and keyboard arrows, Page Up/Down, Home/End work over the minimap. There is no hover popup. Native canvas scrollbars are hidden; wheel, touch, and trackpad scrolling remain available.
- The context inspector and AI assistant occupy the right sidebar; document settings and browser preferences open in dialogs. The minimap stays on the left in editing, reading, and standalone HTML. Small main-text title and heading bookmarks extend rightward toward the document, folding to 10px tabs until the minimap is hovered or a label receives keyboard focus. Expanded labels are up to 90px wide (60px on mobile when explicitly shown), with 9px text. Labels take no horizontal layout space and can overlap the centered document; the expanded label lane keeps them open while crossing gaps, and folds away on pointer exit. Title labels use semibold text and a heavier minimap-side edge, distinguishable even when folded. A single title is omitted when it is the first main-text paragraph; leading explicit space is ignored, but an empty paragraph counts. Multiple titles all receive labels. Floating notes remain visible in the miniature but do not contribute bookmarks or affect the title count. The current landmark changes at a focus line 15% down the canvas viewport, capped at 120px; clicking a label aligns its paragraph to that line without changing horizontal position or text selection. Labels follow live edits and the miniature's scroll position; nearby labels spread out to stay readable. A very dense bookmark overlay can scroll independently over its labels. Full title or heading text is available in each label's tooltip and accessible name.
- Global settings under **More → Browser preferences** offer faithful-proportion (default) and fit-whole-document minimap sizing, plus automatic/show/hide visibility. Automatic hides at viewport widths of 1050px and below, including mobile. Configure these preferences in editing mode; they also apply to in-app reading. Preferences live in browser-local storage, separately from the V0 document.
- Fixed app frame with independently scrolling document canvas and settings. In editing mode, zoom controls live in the top bar alongside the other title-bar actions; reading keeps the zoom gestures/shortcuts without a toolbar. The percentage always shows the actual scale. Its dropdown starts with **Auto** (the editing default), followed by 25%, 50%, 75%, 100%, 125%, 150%, 200%, or 300%. Auto fits the available canvas width, capped to keep at least 600 document pixels visible vertically and at 300%. It follows viewport, panel, and document-width changes. Zoom only the document using these controls, Ctrl/⌘ + wheel, pinch, or Ctrl/⌘ +/−; manual zoom leaves Auto and stays fixed across resizes. Ctrl/⌘ 0 restores Auto. Incremental zoom snaps near both 100% and the current calculated Auto scale without enabling Auto; continued zooming moves past either detent. Explicit presets stay exact. The page lays out at native document size and uses transform scaling, so zoom does not change text wrapping; a scaled outer footprint handles scrolling and centering. Zoom is view state, not saved document geometry.
- Desktop editing/reading modes; viewports under 768px are reading-only. Reading hides the top bar and all settings panels, with an **Edit** return button floating in exactly the same top-right position as **Read** in editing mode. Mobile and exported HTML have no mode button. Local/cloud save failures remain visible and retryable in private reading mode; mobile retains a Files entry point. Reading has no visible page border or shadow and no outer left/right canvas padding. The page and minimap share the authored page background; exposed canvas stays neutral gray. Document width, internal margins, wrapping, and spatial geometry stay unchanged. The minimap and heading navigation remain available; return to editing for creation, export, and settings. On loading or first entering reading mode, zoom starts at the smaller of Auto and 100%, then stays fixed until changed. Reading Auto still fits the full document, including its internal margins, without any extra outer side gutter; selecting Auto or pressing Ctrl/⌘0 uses the uncapped Auto calculation, and its snap point remains available. Zooming in progressively crops only unused document-side margins before horizontal scrolling begins: the content span is the main-text area plus floating-object bounds, including attached labels, strokes, arrowheads, and overflowing formulas, limited to the existing page edges. With a 960px document and otherwise empty 48px side margins, that span is 864px. Unequal unused margins shrink proportionally, without reflowing or moving document content. Editing keeps its original gutters. Editing and reading independently remember their session zoom settings, including Auto; switching modes restores the destination mode’s setting. PNG retains the full native page and margins; standalone HTML shares the adaptive reading viewport.
- Each tab has an independent, recoverable IndexedDB working copy. Cloud synchronization runs every 10 seconds while dirty and on Ctrl/⌘S. Atomic revision checks reject concurrent stale writes. Conflict actions are **Save as copy**, **Discard local changes**, and **Overwrite cloud version**; overwrite directly replaces the cloud content after checking the observed revision, without an additional recovery copy. There is no merging or conflict preview.

Opening Document settings, Browser preferences, or the AI assistant clears document-object and segment selections and leaves document editing focus. Selecting an object or interacting with the document restores the selection inspector, closing those panels without stopping AI tasks. Header zoom controls and interactions within settings keep the panel open. Returning to the document during a drag preserves its canvas width until release, so automatic zoom cannot interrupt the gesture.

Direct insertion uses the last main-text caret as its starting anchor, even when a floating object is selected. Repeated insertion stays available. Spaces are created/resized with Alt-dragging, not through the object menu. Spaces span the page, including its text margins. Clicking one preserves the text caret rather than selecting the space. Ordinary dragging inside text still selects text; ordinary dragging inside document padding, a space, or either side gutter selects floating objects. Object interactions take precedence over gap manipulation, and an object drag keeps its original meaning when Alt is pressed to bypass snapping. Floating text and tables share the main text’s composable inline toolbar and document palette. In editing mode, object selection gates content editing/interaction for text boxes, tables, labels, and HTML widgets. Images, shapes, lines, and formulas remain movable when selected because they have no on-canvas content editor. Reading mode remains directly selectable/interactive without object selection; AI-reserved rich text stays locked.

## Model and boundaries

### English and Simplified Chinese

Mote is English-first, with horizontal mixed English/Simplified Chinese document text. **Document → Layout → Text language** selects English (the default) or Simplified Chinese for the document content, without changing the interface. This language applies to the shared page, including floating text, tables, labels, minimap snapshots, PNG, and standalone HTML. There are no per-passage language controls or automatic language detection. Vertical writing and language-driven right alignment/RTL layout are non-goals; ordinary table-column alignment is unchanged.

The three semantic typeface choices use installed fonts, not downloaded or embedded document fonts:

- **Sans serif:** English documents prefer Inter, Segoe UI, Helvetica Neue, Arial, Noto Sans, and Liberation Sans before the Chinese fallbacks. Simplified Chinese documents prefer Microsoft YaHei first. Both retain PingFang SC, Noto Sans CJK SC / Noto Sans SC, and system sans serif fallbacks. This keeps English curly apostrophes narrow while retaining Chinese glyph coverage.
- **Serif:** Georgia for English, with Songti SC, SimSun, and Noto Serif CJK SC / Noto Serif SC for Chinese, then the system serif fallback.
- **Monospace:** system monospace, SFMono-Regular, and Consolas, with Sarasa Mono SC, Noto Sans Mono CJK SC, and Microsoft YaHei fallbacks. Chinese glyph coverage and cell-width alignment are best-effort.

Prose uses normal word breaking, strict CJK punctuation breaking, and emergency wrapping for long unbreakable strings. Labels retain their explicit no-wrap behavior. **Theme → Defaults → Mixed-script spacing** defaults on and uses CSS `text-autospace` to add visual gaps between Chinese and Latin letters/numbers where the browser supports it. It never inserts spaces into stored or copied text. Code objects retain literal source whitespace and do not apply mixed-script spacing to their source. Title and Heading presets no longer apply negative tracking; existing saved theme overrides are not rewritten. Theme samples include mixed English/Chinese text. System-font availability and browser typography support can still change wrapping across devices; no identical-layout guarantee is made.

Editor composition transactions are grouped by editor and composition identity, without the ordinary typing timeout splitting a paused conversion. Global document shortcuts yield to composing/process-key events, table paragraph-input handling yields to composition, and document-history navigation waits until composition ends. Scoped Chromium checks use browser composition injection, not a native OS candidate window; Windows/macOS input methods and Safari/Firefox still need hands-on verification.

### Floating Code, formulas, and HTML widgets

**+ → Code** arms a drawing tool: drag horizontally to choose width, or click for a default-width snippet. The new object starts empty with its caret ready. Its plain-text `source` preserves whitespace, grows to its measured content height, scrolls horizontally rather than wrapping long lines, and shows line numbers. Select JavaScript, TypeScript, Python, JSON, HTML, CSS, Shell, or SQL in the language picker; `plaintext` is the initial plain-text mode. A light or dark syntax scheme controls highlighting. Syntax colors are independent of the document palette; source is displayed, never executed. Its size, weight, line height, and letter spacing come from the document-wide Code theme style. The typeface is always monospace; the selected syntax scheme supplies its own background, foreground, and token colors. The Code theme style is under Objects, not Paragraphs.

Height follows every source line, including blank and trailing lines; there is no vertical scrollbar or line wrapping. The horizontal scrollbar appears only when needed. Line numbers and the language header stay fixed while source scrolls. Select one object to edit; Enter and Shift+Enter insert line breaks, Tab / Shift+Tab indent/outdent, and paste flattens rich paragraphs into plain line breaks. Escape returns focus to the object. Drag its header to move it, or deselect it and drag anywhere inside; grouped objects stay in positioning mode. Copy returns the complete source without the header or line numbers. Reading and standalone HTML retain selection, Copy, and horizontal scrolling. PNG captures the visible object width from the beginning of each line, without Copy controls. Blank source objects are removed on deselection, like empty text boxes. The highlighter is a lightweight bundled lexer, not a full language parser or IDE.

**+ → KaTeX** inserts a floating display-mode formula. The inspector edits its LaTeX source live, without `$$` or `\[...\]` delimiters; syntax errors retain the source and appear on the object. Width is user-controlled and height follows content. Formulas are centered, never automatically wrapped or shrunk, and can use explicit constructs such as `aligned`. Oversized content follows the existing page-edge cropping policy. **Math style…** opens a global size/color style inherited from Defaults, with px/em units and normal history/reset behavior; math typefaces remain KaTeX's. KaTeX's unsafe HTML commands are disabled (`trust: false`). The renderer and WOFF2 math fonts are bundled for offline HTML and PNG. This is not a full LaTeX document engine, and inline mathematics is not included.

**+ → HTML widget** first asks for a screenshot, using the same embedded-image formats and 10MB limit as image objects. The new widget starts with an editable button-counter demo. **Edit code…** opens one HTML/CSS/JavaScript source field; drop a single `.html` or `.htm` file into that field to replace the source in one document-undo step. Source edits save immediately, while **Run / Restart** recreates the iframe and executes the current source. Dropping a file does not run it or replace the screenshot. Each widget has its own DOM, CSS, globals, and libraries. Moving, resizing, selecting, changing mode, and front/back ordering retain its running state. Runtime interaction state is not saved or included in document undo; reopening starts from saved source.

HTML widgets have independent width/height controls and corner resizing. Their iframe viewport follows the saved dimensions, while page zoom scales the entire widget. In editing mode, click/drag an unselected widget’s noninteractive interior to select/move it. Selection directly enables its contents for subsequent clicks and drags, without a separate interaction mode or button. Clicking elsewhere on the page deselects it and makes its interior draggable again. Selection and movement never restart the iframe; only Run / Restart or an explicitly restored source revision replaces its execution. Reading/mobile interiors are directly interactive. Each iframe uses `sandbox="allow-scripts"`, without access to Mote's DOM/storage or top-level navigation. This prevents namespace collisions and limits access, but is not a CPU/memory quota or a promise that arbitrary code cannot affect responsiveness.

Resource references, including CDN scripts and external data, are used as written. Mote does not inspect widget source, bundle or rewrite external resources, or guarantee offline operation for network-dependent demos. Normal browser resource restrictions still apply. There is no separate ECharts object or bundled chart library: authors can embed ECharts with their own script reference.

The example formula exercises aligned equations, fractions/roots, scripts, Greek letters, sums/binomial coefficients, integrals/derivatives, matrices, underbraces, cases, and vector notation. The two example widgets load pinned ECharts 6.0.0 from jsDelivr: **A week of attention** uses an `<attention-chart>` custom element with shadow DOM, a measure selector, legend filtering, tooltips, and bar-click details (also emitting `attention-select`); **Ideas in motion** animates a repeating six-pass bar ranking with value interpolation, Pause/Play, and Next pass. Reduced-motion preferences disable transitions and start the ranking paused. Their HTML sources and manually captured PNG previews live in `src/document/examples/`; no chart dependency is bundled. To refresh a preview, open its HTML at 690 × 400 and capture that viewport (the ranking preview shows paused pass 4).

The author-supplied screenshot is required and used for the minimap and PNG export, stretched to the object's saved rectangle. **Replace screenshot** updates it explicitly; authors should supply a matching aspect ratio and refresh it when needed. Mote does not capture widget HTML or verify that a screenshot matches the source/current state. Minimap snapshots remove live iframe content before insertion; PNG mounts a screenshot-only reader and never starts widget code. HTML exports keep live widgets, not screenshot substitutes. Both kinds share ordinary floating selection, anchoring, movement, grid, overlap/repel, labels, line connections, ordering, duplication/deletion, and document history.

### V0 representation

Optional `language` is `en` or `zh-Hans` (omission means English). Optional `theme.autospace` is a boolean (omission means enabled). Both persist with the document, participate in history, and are validated on draft initialization and native import. They require no text rewriting or schema migration.

KaTeX objects store `kind: 'katex'` and `latex` alongside shared floating geometry. HTML widgets store `kind: 'html'`, `html`, embedded `screenshot`, accessible `alt`, and explicit `height`. Math overrides live in `theme.blocks.math`; omission means inherited size/color, without rewriting the draft. Native import checks these fields and screenshot safety, but intentionally does not sanitize executable widget source. The `.mote` file contains source and screenshots, never live iframe state or run counters.

`MoteDocument` contains a `version: 'V0'`, optional plain-text `notes` (absent means empty), width, left/right margins, theme defaults, paragraph-class overrides and the document palette, main-text editor JSON, and floating objects. Required `theme.hue` is a finite OKLCH hue in degrees, from 0 inclusive to 360 exclusive (default 145). Primary is derived at render time from that value, never duplicated as raw colors in `theme.palette`; `primary` and `primary:soft` are valid native references. Clipboard/AI segment palettes omit Primary, so pasted content adopts the destination hue. Its ID and generated CSS-variable names are reserved. Older V0 drafts missing hue or retaining the former Subtle neutral entry use the existing confirmed-reset flow; unsupported native imports leave the current document untouched. Subtle is no longer a built-in color reference. There is no migration of older palettes. Each main-text block has a stable UUID. Main-text paragraph semantics are `title`, `heading`, `body`, `caption`, or `list`; List has a zero-based `listLevel`. Code is not a paragraph class: legacy V0 documents with `semantic: 'code'` paragraphs are rejected, not migrated. The Code entry remains in `theme.blocks` for Floating Code typography. Each floating object stores an anchor UUID (or a document-top null anchor), absolute document-space x, nonnegative anchor-relative y, width, and Overlap/Repel text-flow behavior where applicable. Text/table objects store constrained rich-text content; text boxes also store optional `background` and `borderColor` colors (null or omitted means transparent); Floating Code stores plain `source`, a safe language identifier, and `scheme: 'light' | 'dark'`; images store an embedded source and accessible description; rectangles and ellipses store height, fill, stroke, stroke width, dash style, and rectangle corner style; lines store two anchor-relative endpoints, optional object connections, route, bend, arrowhead settings, and stroke settings; labels store constrained rich-text content and an optional attachment. Code has no saved height; its rendered height follows source content. A label is a single paragraph with fixed `label` semantics. Attached geometry is derived from current target layout, not saved as an absolute page position. An omitted kind denotes a text box. Tables have their own constrained schema: one table, exactly one paragraph per cell, no editable paragraph semantic attribute, and the shared composable inline marks. The table node stores a `columns` array of `{ width, align }`, with normalized proportional widths and left/center/right alignment. An absent array means equal-width, left-aligned columns. Column commands update structure and metadata in one transaction; rectangular paste extends metadata when it grows the table. Rendering uses a colgroup and column-wide cell decorations, with noneditable divider controls excluded from the minimap. Images use their intrinsic aspect ratio; tables grow vertically with their cell content.

List retains the flat `paragraph` node and stable block UUIDs; each list paragraph stores `semantic: 'list'` and a zero-based `listLevel`. There are no list containers, ownership relationships, or nested item nodes. Floating Code objects share the ordinary anchor, repulsion, space-flow, minimap, persistence, and undo systems; they are not parsed as rich-text paragraphs.

Each spacer stores a stable block UUID and a `height` in document pixels. Consecutive spacer nodes normalize to one, summing heights and transferring objects and line endpoints to the retained anchor with their offsets preserved. Text has no saved height or capacity reservation. The 12px removal threshold applies at gesture completion, not as a side effect of changing typography. Old V0 text-height reservations are no longer interpreted; V0 makes no layout-migration promise.

Gap previews use transient editor decorations; creation previews do not insert saved document nodes. Resizing an existing gap adds or removes room at the drag's starting position: floating objects and free line endpoints at or below that position move by the height change, while those above stay put. Later main-text anchors move normally, and attached labels/connected endpoints follow their targets without moving twice. Upward dragging can produce overlap, but anchor-relative offsets remain nonnegative. Mouse release commits once, even if Alt has already been released. Escape, pointer cancellation/capture loss, window blur, zoom/mode changes, and document replacement cancel a drag. Each completed gesture and any resulting merge form one document undo step. Normal paragraph margins are preserved rather than added twice when a gap separates them. Closing a space never resizes or deletes its floating objects; overlap with the following text remains possible.

When an anchor is deleted, its floating objects move to the closest surviving preceding block, or the document-top origin. Their content is retained. The shared history restores document snapshots and editor selections without stealing focus or undoing view preferences. Reset to example remains confirmed and clears history. Only the current V0 is supported: loading checks its identity and initializes content through the editor schemas, without historical upgrades or a general-purpose document validator. An editor parsing failure offers a confirmed reset to example for authenticated workspace documents; this revision-checked reset also replaces the cloud save. Declining leaves stored data untouched. Public readers can never reset content.

Desktop tabs edit independent working copies rather than taking an exclusive document lock. A per-tab identity lock prevents duplicated tabs from sharing one local recovery record; without Web Locks, new page sessions always fork. Dirty local copies are never replaced automatically by remote content. Clean private editors check for newer cloud versions. Public shared readers fetch once and make no document update checks.

Storage-access failures show Retry, never a reset prompt. Local save failures retain the in-memory document and warn before leaving. **Synced** means a backend acknowledgment; **Saved locally · changes pending** is not a cloud backup. Authentication failures preserve edits and offer sign-in in a separate tab.

IndexedDB (`mote-cloud` → `copies`) holds per-session recovery, not the authoritative workspace. Clearing browser data can remove unsynced work. **Files → Local recovery** exposes pending copies, including those belonging to closed tabs. The former `mote-local` draft remains untouched and can be explicitly imported as a new cloud document. SQLite holds cloud content; backups are manual only, and native `.mote` export remains available.

The floating layer deliberately permits overlap. Pointer and keyboard movement, duplication, and resizing stop at the document's horizontal edges; group movement preserves relative positions and accounts for attached labels. Content editing and widget interaction activate only when exactly one floating object is selected. Multi-selected text boxes, labels, tables, and widgets remain in positioning mode: dragging an interior moves the group, table dividers stay hidden, and widget frames remain inert. Reading-mode interaction is unchanged. Changing document width does not rewrite saved offsets, and shrinking the page or growing unwrapped label text can still leave existing content outside its bounds. Direct inserts measure their rendered size and stagger when either the new or existing object would completely cover the other; partial overlap remains allowed. Duplicates also stagger while preserving group relationships. Explicit drag placement and attached labels retain their intended geometry. This is insertion-only placement, not ongoing collision avoidance or a full spatial layout inspector.

- **Floating clipboard:** focus one object or marquee/Shift-select a group, then use Ctrl/⌘C, X, and V to copy, cut, and paste. All floating kinds are supported. Attached labels accompany their targets; internal line connections remain within the copied group, while connections to objects outside it detach at their displayed positions. Cutting also detaches surviving connections to the removed objects. Paste adds a newly selected group with fresh object and rich-text IDs, preserving relative placement and stacking. It retains the copied page position, or uses the main-text caret's height when pasting in the main editor, and staggers to avoid fully covering existing objects. Placement uses destination measurements and page bounds; oversized groups retain their dimensions rather than being scaled. Repeated paste adds independent groups. Native V0 data has an HTML carrier and readable text fallback; referenced palette families follow the same import/remapping rules as segment paste. Cut and paste, including palette changes, each undo in one step. While editing floating text, labels, table cells, source fields, or widget contents, the content editor keeps its clipboard behavior. AI-reserved objects cannot be copied or cut. Floating paste never replaces a main-text or segment selection.

## Document files

In editing mode, **More → Export** opens a modal with three formats. Export processing remains local and takes the current in-memory content, including unsynced changes. **Files → Import .mote / HTML…** creates a new cloud document rather than replacing the open one. Ctrl/⌘S synchronizes the active working copy.

Internal Notes are preserved only in native `.mote` exports. PNG and HTML publish the page without notes; importing an exported HTML file therefore starts with empty notes.

The **Filename** field supplies the export name, with the selected extension added automatically (an existing PNG/HTML/Mote extension is replaced, not duplicated). Where `showSaveFilePicker()` is available, export opens the browser's native Save As dialog with that suggested name and format filter. The picker is invoked directly from the click before export preparation; canceling does not generate or download a file. Bytes are written only after generation succeeds, and success is reported after the writable stream closes. Elsewhere, Mote uses an ordinary download with the chosen filename; browser preferences determine whether it prompts for a location. The filename is session-local UI state, not part of the document.

- **PNG:** one full-length image at one bitmap pixel per document CSS pixel, independent of display density, scroll position, and view zoom. It captures the shared reader at native size after images/fonts/layout settle, including the theme background, spaces, tables, labels, shapes, lines, and floating text. The page's horizontal edges crop overflowing content; the width never grows to accommodate objects. Fractional pixel extents round upward. No app chrome, page shadow, selection controls, or added bottom padding. Animated images become a still frame. The initial implementation caps height at 32,767px and area at 32 million pixels; smaller browser limits can also prevent export. It checks rasterization support and reports failures rather than silently shrinking/truncating the document. HTML and `.mote` remain alternatives. Scoped raster checks use Chromium; other engines' HTML-in-SVG raster support varies.
- **HTML:** a single file that opens directly from disk, with inline CSS/JavaScript and embedded document/images/math fonts. Mote content and self-contained widgets work offline; widgets referencing online resources still require them. It mounts the same `DocumentCanvas` through `ReadDocument`, sharing text schemas, theme styles, anchor/repulsion measurement, floating-object layout, fit/zoom, minimap, and heading navigation. The shell has no top bar, Edit button, File/View menus, or zoom buttons. Auto zoom, zoom gestures/shortcuts, and automatic minimap/heading navigation remain; the minimap hides on small screens. The page keeps its authored background without a border or shadow; the minimap shares that background and the exposed canvas uses the same neutral gray surround as the app. The Mote reader itself does not access IndexedDB, localStorage, Web Locks, or a server; widget code runs separately in sandboxed iframes. The page and minimap crop horizontal overflow just like app reading mode; zoom still permits horizontal navigation within the page. Text stays selectable and searchable. JavaScript is required; ordinary system fonts remain system fonts, so typography can vary across devices and the shared layout recalculates accordingly. The V0 document JSON, with internal Notes omitted, is embedded in a non-executable `#mote-document` script element, so Mote-exported HTML can be imported back as an editable document.
- **Mote document (`.mote`):** binary gzip of UTF-8 JSON containing the existing `MoteDocument`, including `version: "V0"`, IDs, theme, geometry, rich text, and embedded assets. There is no archive manifest, custom binary header, encryption, or base64 wrapper around the file. Session history, selection, zoom, and browser preferences are excluded. Both compressed and decompressed data are capped at 128 MiB. Only the current V0 schema is supported; V0 does not promise compatibility with older builds. Ordinary gzip tools can inspect the JSON.

Import accepts `.mote` and Mote-exported `.html`/`.htm` files (case-insensitive extensions). Native files are decompressed; HTML is parsed in an inert template and must contain exactly one `script#mote-document` with type `application/json`. Extraction never runs the outer HTML reader/scripts or loads its resources. After opening the imported document, its authored widgets run in the usual sandboxed frames. Both paths validate the embedded JSON, including the current V0 schema, geometry, safe image/style values, and rich-text schema. HTML files and extracted JSON are capped at 128 MiB. This is not a general HTML-to-document converter; older exports must still match the current V0 schema. Unsupported or corrupt files do not alter the current document. There is no migration or repair layer. Successful import creates a new cloud document with a fresh document ID; existing files are untouched.

PDF export is deferred. PNG and arbitrary HTML cannot be imported back.

## Structure

```text
src/app/        application shell, controls, responsive styles
src/document/   V0 model, examples, IndexedDB, history, validation, file codecs/PNG export, clipboard, Code language IDs/highlighting
src/editor/     constrained Tiptap schemas, inline formatting, editor interactions
src/canvas/     anchor measurement, all floating kinds including the source Code view, spatial interactions, shared reader, zoom, minimap
src/theme/      semantic styling, shared palette, theme-derived UI colors and controls
src/reader/     offline reader entry and single-file HTML export
src/ai/         reservations, task state, service client, review UI
server/        moted, worker isolation, task guide, preview/delivery helpers, fake runner
```

The Vite configuration builds the offline reader as a production IIFE and stylesheet behind `virtual:mote-reader-bundle`. The HTML exporter embeds those build outputs; it has no handwritten alternate document renderer. Export codecs and the reader bundle load lazily from the main application. No export dependencies were added.

The minimap shares the rendered page through an inert, noneditable DOM snapshot, with editing controls and accessibility duplicates removed. Both sizing modes share this renderer and navigation geometry. Proportional mode keeps the page's aspect ratio and scrolls the miniature for long notes; fit mode compresses only the vertical axis as needed. Main-document zoom changes the viewport indicator, not miniature content scale. Scroll-only updates translate the existing snapshot and indicator; layout/content changes refresh the snapshot once per animation frame.

## Deployment

The current app is live at **https://mote.ylxdzsw.com**. Nginx serves `/var/www/mote` using `/etc/nginx/conf.d/mote.conf`, with the existing wildcard origin certificate and workspace cookie gate. Documents/AI require login; explicit shared reader URLs bypass it. Deployment includes the durable `moted` service, with no scheduled backups. See [CLOUD.md](CLOUD.md) for manual backup and restore instructions.

The deployment sets `Cache-Control: no-store` and disables Nginx ETags/expiration for HTML, JavaScript, CSS, and fallback responses. Cloudflare receives the origin directive and currently reports `DYNAMIC`/`BYPASS`, so the pre-release build is not cached at the edge. There is no service worker. Intentional IndexedDB document persistence is separate from HTTP caching. Future updates require `npm run build`, copying `dist/` to `/var/www/mote`, then `nginx -t && systemctl reload nginx`.

Vite development and preview responses also send `Cache-Control: no-store`. `public/_headers` carries the same rule for static hosts that support that format. Other hosts must explicitly set `Cache-Control: no-store` on **all** responses, including HTML and built assets.

Review the early-development decisions in `.mu/AGENTS.md` before a release.
